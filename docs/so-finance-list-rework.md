## มติเจ้าของ (09/11/2026 · ถามทีละข้อ)

**แถวเดียวกันสองฝ่าย** — ทุกแถวตอบได้ว่า SO อะไร มาจาก QT ไหน ลูกค้าคือใคร ยอดเท่าไร เก็บแล้วเท่าไร กี่งวด จ่ายแล้วกี่งวด แต่ละงวดสถานะอะไร
บัญชีถามคำถามเดียวกัน ⇒ หน้ารายการ SO กับหน้างานบัญชีใช้แถวทรงเดียวกัน

| เรื่อง | มติ |
|---|---|
| หน้ารายการ SO | รื้อหน้าตาทั้งหน้า (ไม่ใช่แค่ปรับคอลัมน์) |

| ข้อ 3 · ลิ้นชักฝ่ายขาย | รอบแรกดูอย่างเดียว + ลิงก์หน้าใบ · **ทีหลัง** เพิ่ม "ชุดเงินเข้า" 3 ปุ่มพร้อมกัน (แจ้งชำระ + สลิป · แนบสลิปเพิ่ม · ดึงการแจ้งกลับ) · งานวางแผนงวด (ช่วงบริการ · วันกำหนด · ผูกคำร้อง · ธงก่อนติดตั้ง · ยื่นนับ Actual) อยู่หน้าใบถาวร |
| ข้อ 4 · หน้าภาพรวมบัญชี | ถอด `/finance` ภาพรวม — เมนูบัญชีเปิดเข้างานบัญชีเลย · การ์ดยอดไปอยู่บนหัว · ใบรอปิดเป็นแท็บ |
| เงินค้างจากใบยกเลิก | แถบเตือนบนหน้างานบัญชี **โผล่เฉพาะตอนมี** (ไม่ใช่แท็บถาวร) — ย้ายคิวที่สามของทะเบียนการชำระมา · ยก/ถอน/คืนเงินทำในลิ้นชัก |

**ทำไมยังต้องมีแถบเงินค้าง** — ด่านตอนยกเลิกใบที่มีเงิน (`salesOrderCancelNeedsReviewer`) คุมแค่ว่าใครยกเลิกได้และขึ้นคำเตือน ไม่บังคับให้จัดการเงิน
และบัญชีรับรองงวดหลังใบยกเลิกได้ · ตรวจ 09/11 เจอ 3 ใบ (แก้แล้ว 1 · อีก 2 เป็นสลิปเดียวกับใบใหม่ทุกไบต์ = รับรองซ้ำ 64,200.00 · บัญชีกำลังแก้ด้วยถอนคำรับรอง + ตีกลับ)

**การใช้งานจริงที่ใช้ตัดสินข้อ 3** (audit 12/08–09/11): ฝ่ายขาย — ช่วงบริการ 109 · วันกำหนด 90 · แจ้งชำระ 41 · ผูกคำร้อง 5 · ดึงกลับ 1 · แนบเพิ่ม 1 · บัญชีรับรอง 194

## ตัดสินใจทางเทคนิค

- **หน้างานบัญชีอยู่ path เดิม `/finance/payments`** — เมนู · ป้ายตัวเลข (`?status=reported`) · กระดิ่งวางบิล (`?billing=` `?due=`) · daily digest และลิงก์ในแจ้งเตือนเก่าในฐานชี้มาที่นี่ · `/finance` และ `/finance/requests` redirect มา
- "ยกไปใบใหม่" ในลิ้นชักบัญชี = ลิงก์ไปหน้าใบปลายทาง (ปุ่มยกเงินอยู่ที่ใบใหม่อยู่แล้ว · ยังไม่เคยมีใครใช้) — ไม่แยกโมดัลยกเงินรอบนี้
- ทุกปุ่มในลิ้นชักเรียก API ตัวเดิม (`PATCH …/installments` · `PATCH …/[id] {finance_approve}`) — ด่านชุดเดิม ไม่เพิ่มสิทธิ์
- ยอดจ่ายก่อน VAT = `totalAmount − vatAmount` ของใบ (ไม่หาร 1.07 เดา) — คนละตัวกับ `actualAmount`
