## ตัดสินใจทางเทคนิค

- **หน้างานบัญชีอยู่ path เดิม `/finance/payments`** — เมนู · ป้ายตัวเลข (`?status=reported`) · กระดิ่งวางบิล (`?billing=` `?due=`) · daily digest และลิงก์ในแจ้งเตือนเก่าในฐานชี้มาที่นี่ · `/finance` และ `/finance/requests` redirect มา
- "ยกไปใบใหม่" ในลิ้นชักบัญชี = ลิงก์ไปหน้าใบปลายทาง (ปุ่มยกเงินอยู่ที่ใบใหม่อยู่แล้ว · ยังไม่เคยมีใครใช้) — ไม่แยกโมดัลยกเงินรอบนี้
- ทุกปุ่มในลิ้นชักเรียก API ตัวเดิม (`PATCH …/installments` · `PATCH …/[id] {finance_approve}`) — ด่านชุดเดิม ไม่เพิ่มสิทธิ์
- ยอดจ่ายก่อน VAT = `totalAmount − vatAmount` ของใบ (ไม่หาร 1.07 เดา) — คนละตัวกับ `actualAmount`

## PR-2 — หน้ารายการใบสั่งขาย (10/11)

- คอลัมน์: เอกสาร · ลูกค้า · **ยอดก่อน VAT · เป้า** (เปลือกงานขายเท่านั้น) · **ยอดจ่าย รวม · ก่อน VAT** (ช่องเดียว) · **เก็บแล้ว** (แถบ + ค้าง + รอบัญชีตรวจ) · **งวด** (จ่ายแล้ว x/y + ชิปรายงวด + บรรทัดถัดไป/เลยกำหนด n วัน) · ใบกำกับ · มุมมองบริการเพิ่ม "สัญญา · จ่ายถึง" (ช่องเดียว) + รอบที่เดิน
- หัวคอลัมน์ยอดยังไม่เรียกว่า "Actual" ตามมติ 2026-09-11 (คอลัมน์โชว์ยอดทุกสถานะ) — ต่อท้าย "· เป้า" ให้แยกจากยอดจ่ายก่อน VAT · ใบย้อนหลัง/ใบค่าสรรพสามิตขึ้นขีด + เหตุ
- เปลือกบัญชี (ฝ่ายบัญชีเปิดหน้านี้จากเมนูเอกสารร่วม) ไม่มีคอลัมน์ยอดก่อน VAT · เป้า
- กดแถว = ไปหน้าใบเหมือนเดิม · **กดชิปงวด = ลิ้นชักรายงวด** (ดูอย่างเดียว · ปุ่มท้ายไปแท็บการชำระ) — ไม่เปลี่ยนทางเข้าหน้าใบที่คนคุ้น
- จอ ≤ 680px = การ์ดรายใบ (ชิ้นเดียวกับแถว) แทนตารางที่เลื่อนข้าง
- บรรทัดวันกำหนดอ่าน `payment.nextDue` ตัวเดียวกับการเรียง "กำหนดชำระ"
- วัด 10/11 (devBypass อ่านอย่างเดียว · บล็อก non-GET): ล้นแนวนอน 0px ที่ 1440 · 1024 · มุมมองบริการ 1440 · มือถือ 390 = การ์ด ไม่ล้น · ลิ้นชักเปิดได้ · ไม่มี error บนจอ
- การ์ดสรุปบนหัว (4 ใบ) คงเดิม — ยังไม่ได้รับมติให้เปลี่ยน
