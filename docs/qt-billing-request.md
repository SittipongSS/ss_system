# ขอเอกสารบัญชีจากหน้า QT + ผูกงวดชำระ (หลายคำร้องต่องวด)

สถานะ: **กำลังดำเนินการ** — PR-1 (โมเดล + ผู้อ่านเดิม) เขียนเสร็จ 28/10/2026 · **mig 0413 เจ้าของรันบน prod แล้ว 28/10** (คอลัมน์ 2 · ย้ายลิงก์เดิม 4 คำร้อง · unmoved 0) · PR-2 (จอหน้า QT + ช่องเลือกงวด) ยังไม่เริ่ม · ตรวจกับ origin/main `250648bc`

## โจทย์ (เจ้าของ 28/10)
"การขอเอกสารบัญชีตอนนี้เหมือนจะออกได้ที่ SO อยากให้ออกที่ QT ได้เลย โดยเลือกหรือผูกอะไรเกี่ยวงวดจ่ายได้"

## ของที่มีอยู่แล้ว
- คำร้อง `billing_doc` ยึด QT อยู่แล้ว (`needs:['quotation']`, SO เป็นแค่อ้างอิงเสริม) · POST ไม่บังคับ SO · QT ต้องอนุมัติแล้ว + ยอด > 0
- ทางเข้าวันนี้: แผงงวด SO (เติม QT+SO+งวด) · กระดิ่ง "ขอใบวางบิลงวดนี้" · ปุ่ม "เปิดคำร้อง" หน้าดีล/โครงการ (เติม QT อย่างเดียว) · `/requests`
- **หน้า QT ไม่มีปุ่มเลย** · ฟอร์มไม่มีช่องเลือกงวด (มีแค่ % / ยอด จากยอดทั้งใบ)
- ผูกงวด = `sales_order_installments.billingRequestId` (0260) — ต้องมี SO ก่อน · คำร้อง 1 ใบ ↔ งวด 1 งวด ทั้งสองทาง
- 1 QT : 1 SO (`sales_orders.quotationId` UNIQUE + RPC `sales_order_already_exists`)

## มติ (28/10 ถามทีละข้อ)
1. **เลือกงวด หรือ "ไม่ระบุงวด" ก็ได้** — ไม่ระบุแล้วพิมพ์ % / ยอดเองแบบวันนี้
2. **ยอด: เลือกงวดแล้วเติมยอดงวดให้ แก้ได้อิสระ** (เพดาน = ยอดทั้งใบตามกติกาเดิม)
3. **งวดเดียวมีได้หลายคำร้อง** (เช่น ใบวางบิลก่อน · ใบเสร็จทีหลัง) — รื้อกติกา "งวดละคำร้อง"
4. **ปุ่มบนหน้า QT สองที่**: รายแถวในการ์ดงวดชำระ "ขอเอกสารงวดนี้" (เติมงวดให้) + ปุ่ม "ขอเอกสารบัญชี" ที่การ์ดจัดการใบ (เลือกงวดในฟอร์ม/ไม่ระบุ) · ใต้แถวงวดโชว์คำร้องที่ขอไปแล้ว

## โมเดลข้อมูล (แก้ 28/10 หลังตรวจโค้ด — รุ่นแรก "จับคู่ด้วยเลขงวด" ใช้ไม่ได้)

🔴 **ทำไมรุ่นแรกใช้ไม่ได้**: แถวงวด **ย้ายข้ามใบ** ได้โดย id เดิม — ออก Rev. SO (0376 · ใบ Rev. มาจาก QT คนละใบ)
· ยกเงินจากใบที่ยกเลิก (0378 · ใบใหม่ QT คนละใบ) · และ **เลขงวดเปลี่ยนได้** ตอนปรับแผน (0377 เลื่อน seq)
⇒ (quotationId, seq) หลุดทันทีที่มี Rev./ยกเงิน/ปรับแผน · แต่ **id แถวงวดรอดทุกเส้น**

- 🆕 `dept_requests."installmentId"` → FK `sales_order_installments(id) ON DELETE SET NULL` — ความจริงของ "คำร้องนี้เป็นของงวดไหน"
  · หลายคำร้องชี้งวดเดียวได้ (มติ 3) · แถวถูกลบ (ลบใบ/ตั้งงวดใหม่) = ลิงก์หลุดเอง ไม่ชี้ของที่ไม่มี
- 🆕 `dept_requests."installmentSeq"` smallint 1–12 — งวดที่เลือกจากแผน QT **ตอนยังไม่มีแถวงวด** (ไม่มี SO)
  · `ensureInstallments` (ที่เดียวที่สร้างแถวงวดจากแผน QT) **ผูกคำร้องที่รออยู่ตามเลข** ทันทีหลัง insert
    — ณ วินาทีนั้นเลขงวด = เลขในแผน QT เป๊ะ จึงจับคู่ได้ไม่เดา
  · มีแถวงวดแล้ว ⇒ ต้องเลือกงวดจริง (`installmentId`) ส่งแค่เลขมา = 400 บอกตรง ๆ
- `sales_order_installments."billingRequestId"` **คงไว้เป็นตัวชี้** = คำร้องแรกที่ผูกงวดนี้ (ทุกสถานะ) — SQL ของ 0376/0377/0378
  ใช้ตัดสิน "งวดล็อกจากปรับแผน" อยู่ ⇒ ไม่แตะ SQL เดิม · เขียนตัวชี้ที่ฟังก์ชันเดียว `syncBillingPointers` หลังทุกการผูก/ถอด/ลบ
- ผู้อ่านทุกตัว (แผงงวด SO · ทะเบียน FN · กระดิ่ง/digest · ใบกำกับจากคำร้อง · หน้าคำร้อง) อ่าน **รายการคำร้องของงวด**
  = คำร้องที่ `installmentId` = งวด ∪ คำร้องที่ตัวชี้ชี้อยู่ (กันลิงก์ที่โค้ดรุ่นเก่าเขียนระหว่างรัน mig กับ deploy) ·
  "งวดนี้ขอแล้ว" = มีคำร้อง live อย่างน้อยหนึ่งใบ (`billingRequestLive` เดิม)
- ก่อนรัน mig: ผู้อ่านถอยไปใช้ตัวชี้อย่างเดียว (จอไม่พัง) · ทางเขียนที่ต้องใช้คอลัมน์ใหม่ตอบ 503 "ฐานยังไม่ได้รัน 0413"
- backfill ใน mig: คำร้องที่ตัวชี้ชี้อยู่ → `installmentId` + `installmentSeq` (รันซ้ำได้)
- ตั้งงวดใหม่ตอนอนุมัติ (freeze reseed — เส้นที่แทบไปไม่ถึง) คงกติกาเดิม "ไม่อุ้มคำร้อง": ล้างทั้ง id และเลขก่อนลบแถว
