# วันกำหนด / เลยกำหนด ทั้งระบบ — ผลสำรวจ + มติ + งวดแก้

> สถานะ: **กำลังดำเนินการ** · ตรวจกับโค้ดเมื่อ 2026-11-23 · งวด 1 (#2097 #2098 #2100 #2101 #2103) ขึ้น prod 23/11 `a02d1114` รอ UAT · งวด 2 ตัวกลาง `lib/dueState` อยู่ในคอมมิตนี้ · งวด 2 ขึ้น prod (#2107 #2109 `4ec9f74e`) · งวด 3 กระดิ่ง "เลยกำหนด" อยู่ในคอมมิตนี้ (มติ 24/11)

## 1. ภาพรวม

- พบจุดที่คิด/แสดงเรื่องวันกำหนด **~70 จุด ใน ~180 ไฟล์** · ไม่มีตัวกลางร่วมทั้งระบบ — มีตัวกลางเฉพาะโมดูลคำร้อง (`liveDueDate`) กับเงิน (`billingRuleV4.dueState` ซึ่ง **ไม่มีจอไหนอ่าน**)
- ตัวช่วยนับวันต่างกันราว 10 ชุด (บางชุดนับแบบ UTC บางชุดเที่ยงคืนเครื่อง บางชุดนับเป็นชั่วโมง/24)
- ข่าวดี: เกือบทุกจุดเทียบแบบ `วันกำหนด < วันนี้` (วันครบกำหนดยังไม่แดง) และส่วนใหญ่อ่านวันไทย · ไม่เจอรูป `new Date(due) < new Date()`
- ปัญหาจริงมีสี่กลุ่ม: **(ก) แดงผิด/เงียบผิด** (ข) คำไม่ตรงกัน (ค) เกณฑ์/สีไม่ตรงกัน (ง) แจ้งเตือนขาด

## 3. ความไม่สอดคล้อง

**คำ** — แนวคิดเดียวกันพูดหลายแบบ
- เลยกำหนด: "เลยกำหนด" · "เลย N วัน" · "เลยกำหนด N วัน" · "เลยกำหนดมา N วัน" · "เลยมา N วัน" · "เลยมาแล้ว N วัน(ทำการ)" · **"เกินกำหนด"** (หน้าลูกค้า · สหมิตร · PM) · "ช้า N วัน" · "เลยนัด N วัน" · "เลยวันนัดมา N วันแล้วยังไม่ปิดงาน"
- ครบวันนี้: "ครบกำหนดวันนี้" · "วันนี้" · "ถึงกำหนดวันนี้" · **"ใกล้ครบกำหนด"** (ครอบพรุ่งนี้ด้วย) · "อีก 0 วัน" (เติมน้ำหอม · สิ้นเดือน)
- ค้าง: "ค้าง N วัน" · "ค้างมา N วัน" · "ค้าง วันนี้" · "อยู่สถานะนี้มา N วัน" · "รอมาแล้ว N วัน"
- หน้าลูกค้าเขียน "ครบกำหนด DD" บนแถวที่เลยกำหนดไปแล้ว

**สี** — เลยกำหนดเป็นแดงเกือบทุกที่ แต่: แถบไทม์ไลน์งวด "เลยกำหนดชำระ" เหลือง (แถวข้าง ๆ แดง) · "เลยรอบวางบิล N วัน" เหลืองเสมอ · เดือน FC เลยกำหนดเหลือง · ใกล้ครบ = เหลืองทุกที่

**หน้าต่าง "ใกล้"** — พรุ่งนี้ (การ์ดคำร้อง) · 3 วัน (กระดิ่งงวด · ป้ายวางบิล · งาน PM) · 7 วัน (การ์ดวางบิล · คิวของฉัน "ภายในสัปดาห์นี้" ที่จริงคือ 7 วันข้างหน้า · ติดตั้ง 0..7 = 8 วัน vs บริการ 0..6) · 14 วัน (เติมน้ำหอม) · 30/90 วัน (ต่อรอบบริการ)

**เกณฑ์ "ค้าง" ขึ้นแดง** — 7 วัน (แถวคำร้อง) · 8 วัน (/tax) · 14 วัน (สัญญารอลงนาม) · 30 วัน (SO รอเปิดคำร้อง · เติมคืนบริการ) · 1/2/5 วันทำการ (ลีด SLA · ติดตาม · ส่งกลับอัตโนมัติ) · ตีกลับแดงทันที · ลีดติดตาม: จอแดงทันทีที่เลยวัน แต่กระดิ่งมาเมื่อเกิน 2 วันทำการ

**"วันนี้"** — ราว 30 จุดอ่านนาฬิกาตอนเรนเดอร์ (เวลาไทยถูกแต่ค้างข้ามเที่ยงคืน + เสี่ยง hydration) · 4 จุดใช้นาฬิกาเครื่อง (/pm/tasks · mgmt/calendar · คาดปิดดีล · หัวใบคำร้อง) · แบบอย่างที่ถูกมีแล้วที่ `app/service/page.js:88/126` (เก็บใน state + อ่านใหม่ตอนกลับมาที่แท็บ)
- 🪤 ด่าน `check:thaitime` จับ `fooAt.slice(0,10)` แต่ **ไม่จับ `String(x.fooAt).slice(0,10)`** (มี `)` คั่น) ⇒ จุด UTC ใน §2 #7 หลุดด่านทั้งหมด

## 4. โซนบริการ / PM / RD / อื่น ๆ (สรุป)
- บริการ: นัดค้าง (`date < today` ไม่มีขอบล่างยกเว้นหน้าช่าง 14 วัน) · เติมน้ำหอม "น่าจะหมดแล้ว/ใกล้หมด 14 วัน" · ประเมินพื้นที่ เลยวันนัด/เลยวันส่งผล · ติดตั้ง "เลยวันที่ต้องการแล้ว" · คำว่าเลยวันนัดมีสี่แบบสี่ที่
- PM: "เลยกำหนด N วัน / เหลือ N วัน" (≤3 วันเหลือง) · คิด "งานเลยกำหนด" หกแบบ (นาฬิกาเครื่อง/ไทย/UTC ปนกัน) · โค้ดตาย `derived.js:12-48`
- RD: /rd/perfumers "เลยกำหนด N กลิ่น" ใช้ liveDueDate ✓ · ราคา "หมดอายุ" ไม่มีเตือนล่วงหน้า
- เอกสารลูกค้า (หนังสือรับรอง 6 เดือน): "หมดอายุแล้ว" ไม่มีเตือนล่วงหน้า ไม่มีกระดิ่ง
- สหมิตร "เกินกำหนด (PO/lead)" นับบรรทัดที่ส่งแล้วด้วย (โมดูลพักไว้)
- วันยืนราคา QT: **ไม่มีที่ไหนเช็กหมดอายุ** · ภาษีสรรพสามิต: ไม่มีแนวคิดวันกำหนดยื่น

## 6. ข้อเสนอรวมตัวกลาง

1. **`lib/dueState.js` ตัวเดียว** — `dueState({ due, today, settled, turn, window })` คืน `{ key: 'late'|'today'|'soon'|'later'|'waiting'|'none', days }` · `ageState({ since, today, lateAfter })` คืน `{ days, late }` · `thaiDayOf(timestamp)` (= businessDayKey) · `calendarDays(a, b)` — ทุกจอเรียกตัวนี้ ห้ามนับวันเอง
   - กติกากลาง: เลย = `due < today` · ของจบ/ยกเลิก/ไม่ใช่ตาเรา ⇒ ไม่แดง · วันที่ไม่มีใครรับปาก ⇒ ไม่แดง
2. **คำชุดเดียว** (เสนอ): `เลยกำหนด N วัน` (แดง) · `ครบกำหนดวันนี้` (เหลือง) · `อีก N วัน` (เหลืองเมื่ออยู่ในหน้าต่าง "ใกล้") · `ค้าง N วัน` (แดงเมื่อเกินเกณฑ์ของโมดูล) · เลิกใช้ "เกินกำหนด" / "เลยกำหนดมา" / "เลยมาแล้ว" / "ใกล้ครบกำหนด"
3. **`<DueBadge>` ใน components/ui** วาดคำ+สีจาก `dueState` — จอไม่ประกอบคำเอง
4. **`useThaiToday()`** ยกแพตเทิร์นของ `app/service/page.js` (state + effect + อ่านใหม่ตอนโฟกัส/ข้ามเที่ยงคืน) แทนการเรียก `businessDate()` ตอนเรนเดอร์
5. **ยาม CI**: ขยาย `check:thaitime` ให้จับ `String(x.fooAt).slice(0,10)` + เทสต์คำต้องห้าม (แบบ `labelVocabulary.test.mjs`) กัน "เกินกำหนด" ไหลกลับ + ratchet "ห้ามนับวันเอง" แบบ `dueReaders.test`
6. **กระดิ่ง**: ย้ายกวาดต่อรอบบริการเข้า cron + แยกกุญแจตามสถานะ · เพิ่ม "เลยกำหนด" ของงวดชำระ/คำร้อง/งาน PM ต่อเมื่อเจ้าของเคาะผู้รับ (การ์ดงาน PM เคยถูกถอดโดยมติ)
