# ผูกดีลกับลีดต้นทางย้อนหลัง (สองทาง)

สถานะ: รอตรวจ · มติผู้ใช้ 2026-09-22 · mig 0371 รันบนฐานจริงแล้ว 2026-09-22 (ยืนยัน CHECK มี link_deal/unlink_deal)

## โจทย์

SA ลืมกด "เปิดดีลจากลีดนี้" ที่หน้าลีด แล้วไปเปิดดีลตรงจากหน้าดีล ผลคือ

- ลีดค้างสถานะติดต่อแล้ว/นัดแล้ว ระบบยังทวงวันติดตามและตีกลับอัตโนมัติต่อ
- KPI ของ MKT นับลีดใบนั้นว่า "ไม่แปลง" ทั้งที่ลูกค้าเปิดดีลไปแล้ว

ข้อมูลจริงบน prod วันที่ 22/09: ลีดประมาณ 11 ใบ มีดีลรวม 20+ ใบที่เปิดนอกเส้นลีด เทียบกับลีด 22 ใบที่เปิดถูกทาง
ในจำนวนนี้ 3 ลีดยังเปิดค้างอยู่ และ 6 ลีดผูกแค่ดีลใบแรก ส่วนดีลหมวดอื่นของลูกค้ารายเดียวกันไม่ได้ผูก

## ทางเข้า 3 ทาง (ใช้กติกาชุดเดียว)

| ที่ | ปุ่ม | ยิง |
|---|---|---|
| หน้ารวมดีล → เพิ่มดีล | ช่อง "ลีดต้นทาง (ถ้ามี)" ผูกทุกใบในรอบนั้น | `POST /api/sales-planning/deals` (kind `create_deal`) |
| หน้าดีล → แผงจัดการ | "ผูกลีดต้นทาง" / "ถอดลีดต้นทาง" + การ์ด "ลีดต้นทาง" | `POST` / `DELETE /api/sales-planning/deals/[id]/link-lead` |
| หน้าลีด → การ์ด "ดีลจากลีดนี้" | "ผูกดีลที่มีอยู่" | endpoint เดียวกับหน้าดีล (ส่ง dealId ใน path) |

การลบดีลก็ใช้กติกาเดียวกับการถอด

## มติ 2026-09-22

1. **ลีดทุกสถานะผูกได้ รวม "ไม่ไปต่อ"**
   - ลีดจะเปลี่ยนเป็น "เปิดลูกค้าแล้ว" เพราะความจริงคือเปิดดีลไปแล้ว
   - เหตุผลไม่ไปต่อยังอยู่ในคอลัมน์และในประวัติ
   - ข้อยกเว้น: ลีดที่ยังไม่ถูกกระจาย (รอคัดกรอง/รอกระจาย) รวมถึงลีดที่ถูกตีกลับจนไม่มีทีม ผูกได้เฉพาะ Admin กับ AE Supervisor
2. **ถอดได้**
   - ถ้าลีดไม่เหลือดีลแล้ว ลีดจะกลับไปสถานะก่อนเปิดดีล โดยไม่มีวันติดตาม ทำให้ AE ต้องบันทึกการติดต่อใหม่
   - การลบดีลใช้กติกาเดียวกัน
3. **คนที่ผูก/ถอดได้**
   - บทบาทที่เปิดดีลจากลีดได้อยู่แล้ว (Admin/AE/Senior AE) และ AE Supervisor
   - ต้องแก้ดีลใบนั้นได้ และทำงานลีดใบนั้นได้ทั้งคู่ (AE = ผู้รับมอบ · Senior = ทีมเดียวกัน)
   - AC และ marketing ผูกไม่ได้

## กติกาที่โค้ดใช้

อยู่ที่ `webapp/src/lib/sales/dealLeadLink.js` ที่เดียว ส่วนที่เขียนลงฐานอยู่ที่ `dealLeadLinkRepo.js`

- **ดีลที่ผูกไม่ได้**
  - ดีลของใบสั่งขายย้อนหลัง เพราะ CHECK ของ mig 0360 บังคับให้ `leadId` ว่าง
  - ดีลสหมิตร (`metadata.source` ขึ้นต้นด้วย `sahamit`)
  - ดีลที่ผูกลีดอื่นอยู่แล้ว ต้องถอดก่อน ไม่มีทางย้ายตรง
- **สิ่งที่เขียนลงดีล**
  - คอลัมน์ `leadId` กับกระจก `metadata.leadId` เขียนในคำสั่งเดียว พร้อม `leadChannel`
  - `source` เขียน `'lead'` เฉพาะเมื่อยังว่าง
- **การเปลี่ยนสถานะลีด**
  - อัปเดตแบบมีเงื่อนไขสถานะเดิมเสมอ (`.eq('status', …)`) เพื่อไม่ทับการตีกลับที่แทรกเข้ามา
  - ถ้าพลาดหลังดีลขยับแล้ว จะตอบเป็น `leadWarning` ไม่ใช่ 500
- **ประวัติลีด**
  - `link_deal` = ผูกย้อนหลัง · `unlink_deal` = ถอด/ลบดีล
  - `create_deal` = เปิดดีลใหม่ (รวมถึงการเลือกลีดในฟอร์มเพิ่มดีล)
  - `reason` เก็บ `รหัสดีล · ชื่อดีล` เพราะ `lead_events` ไม่มีคอลัมน์ dealId
- **ลีดที่ยังไม่มีผู้รับผิดชอบ** (หัวหน้าผูกใบรอคัดกรอง/รอกระจาย) จะได้ผู้ดูแลดีลเป็นผู้รับผิดชอบ
  ได้ทีมของดีลถ้ายังไม่มีทีม และได้เวลามอบหมาย (`assignedAt`/`firstAssignedAt`) ไปด้วย
  ถ้าไม่ทำ ลีดที่แปลงสำเร็จจะหลุดตาราง AE ของ KPI หรือหลุดแถว "มอบหมายแล้ว" ของผัง Funnel ทำให้ยอดสองตารางไม่เท่ากัน
  ถอดกลับคิวคัดกรอง/รอกระจายเมื่อไร ช่องเหล่านี้จะถูกล้างออก และรอกระจายจะเริ่มนาฬิกา `screenedAt` ใหม่
- **สถานะที่ลีดจะกลับไปตอนถอด**
  - ใช้ `fromStatus` ของเหตุการณ์ `create_deal`/`link_deal` ล่าสุดที่พาลีดเข้า qualified
  - เหตุการณ์เก็บทีม/ผู้รับ **ก่อนผูก** ไว้ ใช้คืนค่าตอนกลับเป็นไม่ไปต่อ · กลับคิวคัดกรอง = ล้างทีม+ผู้รับ ·
    กลับรอกระจาย = ล้างผู้รับ
  - กลับ "รอติดต่อกลับ" = เริ่มนาฬิกา `assignedAt` ใหม่ ไม่งั้นระบบจะตีกลับอัตโนมัติเช้าวันทำการถัดไป
  - ถ้าไม่เจอเหตุการณ์ (ดีลก่อน mig 0199 · บันทึกประวัติล้มตอนผูก) ให้อ่านร่องรอยบนแถวตามลำดับ:
    มีเหตุผลไม่ไปต่อ = ไม่ไปต่อ · ไม่มีทีม = รอคัดกรอง · ไม่มีผู้รับ = รอกระจาย · เคยนัด = นัดแล้ว ·
    เคยติดต่อ = ติดต่อแล้ว · นอกนั้น = รอติดต่อกลับ
    ⚠️ ลีดรอคัดกรอง/รอกระจายที่หัวหน้าผูกแล้วประวัติหาย จะถอยได้แค่ "รอติดต่อกลับ" เพราะตอนผูกประทับผู้รับไปแล้ว
    **จึงต้องรัน mig 0371 ก่อน deploy** (ถ้ายังไม่รัน การบันทึก `link_deal` จะล้มทุกครั้ง)
  - ถ้ามีคนผูกดีลใหม่เข้าลีดใบเดียวกันระหว่างย้อนสถานะ ระบบจะนับซ้ำหลังย้อน และคืนเป็น "เปิดลูกค้าแล้ว"
    ส่วนฝั่งผูก จะอ่านสถานะลีดใหม่หลังเขียนดีลเสร็จ
- **รายการลีดในโมดัลผูก** มาจาก `GET /leads?linkable=1` ซึ่งกรองด้วยด่านเดียวกันที่ server
- **รายการดีลในโมดัลผูก** กรองที่จอด้วย `isDealLinkableToLead`: ต้องแก้ได้ ยังไม่มีลีด และไม่ใช่ดีลที่ผูกไม่ได้
- **PATCH `/deals/[id]` เขียน `leadId`/`source`/`leadChannel` ใน metadata ไม่ได้แล้ว** (ก่อนหน้านี้เขียนได้ ทำให้กระจกชี้คนละลีดกับคอลัมน์)

## ผลต่อตัวเลข

- ผูก = ลีดเข้าตัวเศษของอัตราแปลง (`won`) ในเดือนที่รับลีดเข้า ทำให้ตัวเลขเดือนเก่าขยับได้ ซึ่งเป็นความจริงที่ตกหล่นไป
- D14 ของ MKT ไม่ขยับ เพราะอ่านเฉพาะเหตุการณ์ `meeting`
- ลีดที่เป็น "เปิดลูกค้าแล้ว" หลุดจากการตีกลับอัตโนมัติและการทวงวันติดตามเอง

## ยังไม่ทำ (ตั้งใจ)

- **ไม่ backfill คู่ที่ลืมผูก** — จับคู่จากชื่อ/เบอร์ผิดได้ ต้องให้คนผูกจากหน้าจอ
  รายการคู่ที่น่าจะใช่อยู่ในผลตรวจวันที่ 22/09 (เก็บในบันทึกของเซสชัน ไม่ได้เก็บในรีโป)
- ไม่มีปุ่มถอดบนหน้าลีด เพราะการ์ดดีลเป็นลิงก์ทั้งใบ ให้ถอดที่หน้าดีล
- ไม่มีแจ้งเตือนกระดิ่งตอนผูก/ถอด
