# Decision 0016 — หน้าแรกเป็นเมนูทุกระบบในเปลือกแอป

วันที่: 15 กันยายน 2026 (มติหัวเว็บ 16 กันยายน 2026)
สถานะ: รอตรวจ — โค้ดขึ้น main ครบแล้ว รอ UAT ด้วยบัญชีจริง (PR5) · แทนที่บางข้อของ [Decision 0005](./0005-home-remains-navigation-hub.md) และ [Phase 4C](../phase-04c-home-navigation-hub.md)

> เลขบรรทัดที่อ้างถึงทั้งหมดอ่านจาก `main` ที่ `77833eea` (16 กันยายน 2026)

## บริบท

`/home` คือจุดที่ทุกคนลงหลังล็อกอิน (`app/page.js:35, 53, 77`) และเป็นปลายทางเมื่อ proxy ปฏิเสธการเข้าหน้า (`proxy.js:121, 146`) ตอนนี้หน้านี้วาดเองนอกเปลือก `AppLayout` (`LayoutWrapper.js:18`) ตามที่ Phase 4C ตรึงไว้ (`phase-04c-home-navigation-hub.md:9`) หน้าจอประกอบด้วยคำทักทาย ชิปบทบาทและทีม การ์ด "ทำงานต่อ" และการ์ดระบบใบใหญ่ที่มีป้าย "รอคุณ N" (`home/page.js:202-316`)

ผู้ใช้ยืนยันปัญหาสี่ข้อเมื่อ 15 กันยายน 2026:

1. การ์ดใหญ่เปลืองที่
2. กดสองต่อกว่าจะถึงงาน (การ์ด → หน้าแรกของระบบ → เมนู)
3. ป้ายบอกแค่ "รอคุณ N" ไม่บอกว่ารออะไร
4. หน้าตาไม่เข้ากับเปลือกระบบ

ข้อเท็จจริงที่ตรวจกับโค้ดแล้ว:

- **หัวเว็บบนจอ >1200px มีแถวระบบ ยอดรวม และดรอปดาวน์เมนูของทุกระบบอยู่แล้ว** (`AppLayout.js:987-1063`) การ์ดระบบบน `/home` จึงซ้ำกับหัวเว็บ
- **หน้าแรกกับเปลือกทำงานเดียวกันซ้ำสองชุด** ได้แก่ อ่าน session, devBypass, โมดัลบังคับเปลี่ยนรหัสผ่าน, ออกจากระบบ และตัวดึงตัวเลข (`home/page.js:68, 70-120, 148-154, 325-329` เทียบกับ `AppLayout.js:93, 130-195, 319-329, 1175-1180`) ทั้งสองชุดเริ่มเพี้ยนกันแล้ว:
  - หน้าแรกไม่ล้าง `userId`/`userName` ตอนออกจากระบบ (ดู `AppLayout.js:327`)
  - `userContext` ของหน้าแรกทิ้ง `teams` และ `department` (`home/page.js:131-135`) ⇒ คนที่อยู่ทีม KA เป็นทีมรองไม่เห็นการ์ดงานสหมิตร (`permissions.js:1132-1136`)
- **`/api/nav/counts` แยก "นับไม่สำเร็จ" ออกจาก "ศูนย์" ไม่ได้**
  - ตัวนับที่พังจะถูกข้ามคีย์ไป (`route.js:88-93`) และค่าศูนย์ก็ถูกตัดทิ้งด้วย (`navCounts.js:61-63`) ปลายทางจึงเห็นเหมือนกันทั้งสองกรณี
  - ตัวนับแบบ head-count 8 จุด (`route.js:136, 346, 354, 367, 463, 489, 502, 515`) ตัวนับงานส่วนตัว (`route.js:73-77`) และการอ่านอีกหลายจุดไม่ตรวจ `error` เลย ของที่พังจึงกลายเป็น 0
  - การอ่านที่ตั้ง `.limit(5000)` ถูก PostgREST ตัดที่ 1,000 แถวอยู่ดี (`check-row-cap.mjs:52-53`) และตัวนับ forecastReview ส่งลิสต์ id ทั้งก้อนใน `.in()` (`route.js:206, 209`) ซึ่งชนเพดาน URL ได้เมื่อข้อมูลโต

รอบม็อก 15 กันยายน 2026:

- **รอบ 1** มีห้าแนว คะแนนตรงโจทย์ออกมาเท่ากันทุกแนว ผู้ใช้จึงให้ทิศทางใหม่ว่า *"อยากได้ที่โชว์ menu ทั้งหมด แล้วโชว์แค่ตัวเลขที่ต้องทำ แต่งานต่อค่อยเข้าในเมนูดีกว่า"*
- **รอบ 2** มีห้าทรง ผู้ใช้เลือกทรงที่ 2 "คอลัมน์ระบบ" (`mockups/home-redesign/r2-2-columns.html`) และตอบคำถามเสริมครบทุกข้อ
- **รอบ 3** (`mockups/home-redesign/r3-columns.html` · ฉบับสุดท้าย) ต่อจากทรงที่ 2 ตามมติเสริม และปิดปัญหาค้างของรอบ 2: ดรอปดาวน์บนหัวยังซ้ำตัวเลข · ท้ายคอลัมน์ไม่เสมอ · บทบาท 2–3 ระบบได้ก้อนแคบชิดซ้าย · ระบบที่ปิดกินทั้งแผง · เลขตัวอย่าง "12" ในคำอธิบาย · เศษแถวโผล่หลังหัวแผงที่เกาะ · multi-column ต่างกันระหว่างเบราว์เซอร์

## การตัดสินใจ

1. **`/home` = เมนูทุกเมนูของทุกระบบที่ผู้ใช้เข้าได้**
   - แต่ละระบบเป็นแผงที่หน้าตาเหมือนลิ้นชักเมนูจริง ใช้แถว `.topnav-item` ประกอบด้วยไอคอน · ชื่อเมนู · ตัวเลขเต็มหลักชิดขวา (ไม่ตัดเป็น 99+)
   - ไม่มีรายการใบงาน ไม่มีบรรทัดคำกริยาใต้เมนู ไม่มีปุ่ม "ทำงานต่อ" ไม่มีคำทักทาย และไม่มีช่องค้นหา
   - งานจริงทำในเมนูปลายทาง
   - **การจัดวาง:** CSS grid ที่ตำแหน่งแผงคำนวณจากจำนวนแถวเมนู (ไม่ใช่การวัด และไม่ใช้ multi-column)
     - ระบบที่เปิดใช้วางได้ในแถวเดียว ⇒ หนึ่งระบบหนึ่งคอลัมน์
     - ไม่พอ ⇒ แบ่งคอลัมน์ตามลำดับ `SYSTEM_CATALOG` ให้สูงใกล้กัน แล้วยืดแผงที่สูงสุดของคอลัมน์ให้ท้ายคอลัมน์เสมอกัน
     - แถวเมนูของทุกคอลัมน์ตรงแนวกันเสมอ · สูงสุด 4 คอลัมน์ · จอ ≤640px คอลัมน์เดียว
2. **`/home` อยู่ในเปลือก `AppLayout`**
   - `LayoutWrapper` ครอบทุกหน้ายกเว้น `/`
   - `systemForPathname('/home')` คืน `null` ซึ่งเป็นกติกาเดียวกับ `/notifications`, `/account` และ `/go`
   - `ss:last-system` ต้องไม่ถูกเขียนทับ
   - ตัดโค้ดที่ซ้ำกับเปลือกออกจากหน้าแรกทั้งหมด (session, devBypass, โมดัลรหัสผ่าน, ออกจากระบบ, `useNavCounts`) เหลือตัวดึงตัวเลข**หนึ่งตัวต่อหน้า**ที่เปลือก
3. **หัวเว็บบน `/home` เหลือแถวบนแถวเดียว แล้วต่อด้วยแถบต้อนรับกรมท่าในหน้า** (ม็อก `r4-band.html` — ผู้ใช้เลือกแบบ ง เมื่อ 15 กันยายน 2026 และยืนยันอีกครั้งเมื่อ 16 กันยายน 2026 ว่าเอาแบบ ง ตามที่ม็อกไว้ ไม่ย้ายโลโก้)
   - **แถวบน 52px เหมือนทุกหน้า** ตำแหน่งของทุกชิ้นเท่าหน้าอื่น: โลโก้ชิดซ้าย · กระดิ่ง · เมนูบัญชี (จอ ≤768 = กระดิ่ง + ปุ่ม "…")
     - โลโก้บน `/home` ได้ `aria-current="page"`
     - เส้นคั่นหลังโลโก้ซ่อน (เส้นนั้นมีไว้คั่นป้าย "ระบบ › เมนู" ซึ่งหน้าแรกไม่มี) แต่ระยะห่างคงเดิม ⇒ โลโก้อยู่ตำแหน่งเดียวกับหน้าอื่น
   - **สิ่งที่ไม่วาดบน `/home` ทุกชั้นจอ:** แถวระบบ >1200px (`.topnav-systems`) · ตัวสลับระบบ ≤1200px (`.topnav-sys`) · แฮมเบอร์เกอร์และลิ้นชัก · แถบเมนูล่างมือถือ (`MobileBottomNav`) · แถวเมนูของระบบ (`.topnav-menu`)
     - เหตุผล: แผงในหน้ากางเมนูของทุกระบบอยู่แล้ว ทุกชิ้นข้างบนจึงเป็นสำเนาที่สองของสิ่งเดียวกันบนจอเดียว
   - **ปุ่ม "…" บนมือถือยังอยู่** เพราะเป็นทางเดียวไปบัญชีและออกจากระบบ · แผ่นที่เปิดออกมาบน `/home` เหลือหมวดบัญชีอย่างเดียว หัวแผ่นเขียน "หน้าแรก · บัญชีและการตั้งค่า"
     - หมวด "เครื่องมือ" ถูกซ่อนบน `/home` เพราะมีการ์ดเดียวคือ "หน้าหลัก" ซึ่งชี้หน้าที่ยืนอยู่
     - ชื่อระบบบนแผ่นต้องเป็น "หน้าแรก" ไม่ใช่ระบบล่าสุดจาก `localStorage`
   - **แถบต้อนรับกรมท่าอยู่ในหน้า ไม่ใช่ในหัว** — ต่อจากแถวบนโดยไม่มีรอยต่อ (พื้นไล่สีชุดเดียวกัน) ถือชื่อหน้า · วันที่ · คำอธิบายป้าย แล้วแผงเมนูลอยขึ้นมาทับขอบล่างของแถบ
     - ไถลงแล้วแถบเลื่อนหายไปกับหน้า เหลือแถวบน 52px ที่ติดขอบจอ · เงาใต้แถวบนโผล่เมื่อพ้นแถบเท่านั้น
     - ชื่อหน้า วันที่ และคำอธิบายป้ายชิดซ้ายตามแนวเนื้อหา (ไม่จัดกึ่งกลาง)
   - **ลิงก์ "ข้ามไปที่เมนูทุกระบบ"** เป็นชิ้นแรกของหัว โผล่เมื่อโฟกัสด้วยคีย์บอร์ด
   - หน้าอื่นทุกหน้ายังใช้หัวเว็บแบบวันนี้ครบ — มตินี้ใช้กับ `/home` เท่านั้น
4. **หัวเว็บบน `/home` ไม่มีตัวเลขเลย**
   - ชิ้นที่เคยถือตัวเลข (แถวระบบ ดรอปดาวน์ เมนูย่อยแบบกางต่อ ตัวสลับระบบ แถบล่างมือถือ) ไม่ถูกวาดบน `/home` อยู่แล้วตามข้อ 3 ⇒ ตัวเลขหายไปพร้อมกัน
   - ของที่ยังวาดอยู่ (โลโก้ เมนูบัญชี แผ่น "…") ห้ามมีป้ายตัวเลขและห้ามพูดตัวเลขใน aria-label
   - กระดิ่งแจ้งเตือนยังแสดงป้ายยังไม่อ่านของตัวเองตามเดิม
   - หน้าอื่นทุกหน้ายังมีตัวเลขบนหัวเว็บตามเดิม
5. **ไม่มีเครื่องหมาย "ระบบล่าสุด"**
   - บน `/home` ไม่มีชิ้นไหนไฮไลต์ว่ากำลังใช้ระบบใด (แถวระบบและตัวสลับระบบไม่ถูกวาดอยู่แล้ว)
   - ลำดับแผงตายตัวตาม `SYSTEM_CATALOG`
6. **ป้ายตัวเลขบอกขอบเขตของงาน**
   - งาน "ของฉัน" = ป้ายทึบ
   - งาน "ทั้งฝ่าย / ทั้งบริษัท" = ป้ายโปร่งมีขอบ
   - นับไม่สำเร็จ = ป้ายขอบประใส่ขีด `—` **ห้ามแสดงเป็น 0**
   - ศูนย์ = ไม่มีป้าย
   - ขอบเขตของแต่ละคีย์ตัดสินต่อคนดู จากตัวตัดสินกลางเพียงตัวเดียว · เป็น "ของฉัน" ได้ต่อเมื่อทุกเลนที่ตัวนับรวมให้คนนั้นเป็นงานส่วนตัว
   - มีคำอธิบายบรรทัดเดียวที่แถวชื่อหน้า นำด้วยคำ "ตัวเลขงานค้าง" · ป้ายตัวอย่างใส่ตัวอักษร "N" ไม่ใช่ตัวเลข · บอกเฉพาะแบบป้ายที่อยู่บนจอ
   - จำนวน "นับไม่สำเร็จ" และข้อความ "ไม่มีตัวเลขงานค้าง" คิดจากแถวที่วาดบนจอเท่านั้น ไม่ใช่จากทุกคีย์ที่ server นับ
7. **จอมือถือของคนที่มีหลายระบบ**
   - มีสารบัญระบบบนสุดของหน้าเมื่อมีตั้งแต่ 4 ระบบ: ชิปชื่อระบบพร้อมยอดรวมของตัวเลขที่เห็นในแผงนั้น กดแล้วเลื่อนไปที่แผงของระบบนั้น
   - การกดชิปไม่เพิ่มประวัติของเบราว์เซอร์ (ปุ่มย้อนกลับครั้งเดียวต้องออกจากหน้าแรกได้)
   - หัวแผงเกาะอยู่ใต้แถบบนระหว่างเลื่อน
   - ไม่พับเมนูเก็บ
8. **ระบบที่ยังไม่เปิดใช้** (`disabled` ใน `SYSTEM_CATALOG`) ยังแสดงอยู่ตามลำดับ แต่เป็น**บรรทัดเดียว**สูงเท่าหัวแผง จางพร้อมข้อความ "ยังไม่เปิดใช้" ไม่มีแถวเมนู และกดไม่ได้ · วางต่อท้ายคอลัมน์ของระบบก่อนหน้า · ในสารบัญมือถือเป็นชิปจางที่กดไม่ได้
9. **เมนูบนหน้าแรกกับเมนูในเปลือกมาจากทะเบียนเดียว**
   - ยกนิยาม `allGroups` / `SHARED_DOC_ITEMS` และตัวกรองสิทธิ์ (`AppLayout.js:55-69, 335-661, 678-705`) ออกไปเป็นโมดูลกลาง
   - ทั้ง `/home` และ `AppLayout` เรียกใช้ตัวเดียวกัน จึงไม่มีทางที่รายการเมนู การมองเห็น หรือ `countHref` จะเพี้ยนหากัน
10. **`/api/nav/counts` ต้องบอกสถานะรายคีย์** ว่านับแล้ว (รวมศูนย์) หรือนับไม่สำเร็จ โดยไม่เพิ่มรายการแถว ไม่เขียนฐาน และไม่ทำให้ป้ายบนหัวเว็บของหน้าอื่นเปลี่ยนพฤติกรรม · ตัวนับทุกตัวต้องโยน error และต้องไม่ถูกตัดที่ 1,000 แถวหรือเพดาน URL เงียบ ๆ

  - แถบอยู่**ในหน้า** ไม่ใช่ในหัว ⇒ ไถแล้วหาย เหลือแถวบนเตี้ยเท่าหน้าอื่น · หัวไม่หนาขึ้นเลยแม้แต่พิกเซลเดียว
  - พื้นแถบต่อจากแถวบนแบบไม่มีรอย ⇒ หน้าแรกดูเป็นหน้าแรก โดยที่ตำแหน่งโลโก้ กระดิ่ง และปุ่มบัญชีไม่ขยับจากหน้าอื่นเลย

## ตรวจรับ

- **หน้าต้องเปิดได้เสมอ** ในทุกกรณีต่อไปนี้:
  - บัญชีไม่มีระบบเลย (แสดง EmptyState)
  - ตัวนับพังทุกคีย์ (ทุกแถวที่มีตัวนับเป็นขีด หน้าไม่ล้ม)
  - อ่าน session ไม่สำเร็จเพราะเครือข่าย (แสดง error พร้อมปุ่มลองใหม่และปุ่มกลับหน้าเข้าสู่ระบบ ไม่เด้งเอง)
- **ความสูงแถวคงที่** ทั้งตอนกำลังนับ ศูนย์ มีตัวเลข และนับไม่สำเร็จ · ชื่อเมนูไม่ถูกตัดใหม่เมื่อตัวเลขมา
- **ตรวจครบทุกบทบาท:**
  - ทุก role ใน `ROLES` (25 ตัว) + role ว่าง (`user`) + สิทธิ์เสริม + หลายทีม ผ่าน fixture ของทะเบียนเมนู
  - ใต้ devBypass อย่างน้อย admin · ae_supervisor · senior_ae · ae · marketing · rd · finance · ts / ts_manager / ts_planner · pc / wh · secretary · executive · viewer · ra
  - **บัญชีจริงที่ไม่ใช่ admin ผ่าน proxy บน production** อย่างน้อย FN · RD · TS · AE Supervisor — devBypass ปิด proxy ทั้งตัว และ admin ผ่าน `lockedOut` ตั้งแต่บรรทัดแรก (`proxy.js:297`)
- **หัวเว็บ:**
  - `/home` ทุกความกว้าง: ไม่มีแถวระบบ ตัวสลับระบบ แฮมเบอร์เกอร์ แถวเมนู แถบล่าง และไม่มีตัวเลขบนหัวนอกจากป้ายกระดิ่ง
