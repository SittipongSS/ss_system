เจ้าของถาม "รื้อหน้า modal สินค้าใหม่ดีมั้ย" — ตอบว่า **จัดลำดับใหม่ ไม่เขียนใหม่** ฟอร์มยังเป็นโมดัลตัวเดียวที่ใช้ทั้งเพิ่มและแก้
(`components/database/ProductForm.js` · กฎ "ปุ่มแก้ไขต้องเปิดฟอร์มตัวเดียวกับตอนสร้าง" ใน webapp/AGENTS.md)

ปัญหาของโครงเดิม (3 หัวข้อ: ข้อมูลหลัก · สูตรและบรรจุภัณฑ์ · ราคาขายปลีก):
1. เรื่องราคาอยู่สองหัวข้อ — ปุ่ม "รวมชุด / รายชิ้น" อยู่หัวข้อสูตร แต่ช่องราคาทั้งชุดอยู่หัวข้อ 3 (ผิด [form-design-rules.md](form-design-rules.md) §1 ข้อ 3: ช่องที่โผล่ตามเงื่อนไขต้องอยู่ใต้ตัวที่ทำให้มันโผล่)
2. บอกสรรพสามิตสองที่ไม่ตรงกัน — กล่องหมวดด้านบนดูแค่ธงของหมวด ชุดของขวัญจึงไม่ขึ้นว่าเสียภาษี แต่ป้ายใต้รายการสูตรบอกว่าเสีย
3. ป้ายราคาไม่เปลี่ยนตามสินค้า — ชุดของขวัญยังเขียน "ราคาขายปลีก" ทั้งที่หมายถึงราคาทั้งชุด
4. ไม่เห็นภาษีที่จะคิดได้จนกว่าจะบันทึก

## โครงที่จะทำ

- **หัวข้อ ④ เป็นที่เดียวที่พูดเรื่องสรรพสามิต:** กล่องสถานะ "เสีย / ไม่เสีย" + เหตุ (ธงของหมวด · สูตรในชุดหมวดไหน · RA ตั้งรายตัว)
  · กล่องหมวดด้านบนเหลือชื่อหมวด + ชิป "หมวดเสียสรรพสามิต" / "จดแจ้ง อย." (เลิกกล่องเตือนยาว)
- **ชุดของขวัญ:** ปุ่ม "รวมชุด / รายชิ้น" (G5 · ไม่มีค่าเลือกไว้ก่อน) อยู่ใน ④ และช่องราคาโผล่ใต้ปุ่ม
  · รวมชุด = "ราคาขายปลีกทั้งชุด (รวม VAT)" · รายชิ้น = ตารางชิ้นที่เสียภาษี (ราคา/ชิ้น × จำนวนจาก ②) + ฐานภาษีรวม + ช่องราคาทั้งชุดไว้อ้างอิง
  · ② เหลือแถว หมวด · สูตร · จำนวนชิ้น (+ ชิป "สรรพสามิต" บนแถวหมวดเสียภาษี) — ช่องราคาต่อชิ้นย้ายออกจาก `GiftSetFormulaRows`
- **ป้ายช่องราคา** ตามชนิดสินค้า: สินค้าทั่วไป "ราคาขายปลีก (รวม VAT)" · ชุดของขวัญ "ราคาขายปลีกทั้งชุด (รวม VAT)"
- **ตัวคิด/ข้อความใช้ของเดิม:** `lib/excise/giftSetExcise.js` (แบบของชุด · โหมด · ฐาน · ข้อความสรุป) · `productTaxRates` — ไม่มีสูตรใหม่ในจอ
- **ไม่เปลี่ยน:** ช่องทุกช่อง · payload ที่ส่ง API · ด่านฝั่ง server · ข้อมูลในฐาน · ฟอร์มยังเป็นโมดัลตัวเดียวของเพิ่มและแก้
