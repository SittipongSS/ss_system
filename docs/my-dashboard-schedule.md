# กำหนดการของฉัน — ปฏิทินในแดชบอร์ดของฉัน

> สถานะ: **รอตรวจ** · ตรวจกับโค้ดเมื่อ 2026-08-21 · build ครบตามมติ รอ UAT บนบัญชีที่มีนัดจริง

## ปัญหาที่แก้

แดชบอร์ดของฉัน (`/sa/dashboard` แท็บ "ของฉัน") ตอบว่า **ต้องทำอะไรก่อน** ได้ตั้งแต่ #1150
(คิวรวมทุกชนิด) แต่ไม่เคยตอบว่า **กี่โมง** — นัดลูกค้าที่บันทึกจากคิวลีดไม่โผล่ในหน้านี้เลย
ทั้งที่เป็นของชิ้นเดียวของคนขายที่มีเวลาตายตัวและเลื่อนไม่ได้ · คนขายจึงต้องเปิด `/sa/calendar`
อีกหน้าเพื่อรู้ว่าบ่ายนี้ว่างไหม แล้วกลับมาหน้านี้เพื่อรู้ว่าต้องทำอะไร

## มติ (ผู้ใช้ 2026-08-21 · เลือกจากม็อกสองแบบ)

**แบบ ก** — ซ้ายเป็นรายการ ขวาเป็นปฏิทิน (แบบ ข "ตารางเวลา 7 วัน × ชั่วโมง" ตกไป เพราะมีแต่
นัดที่ลงช่องเวลาได้ ส่วนงาน/คำร้องเป็นวันล้วน ตารางจึงว่างเปล่าสำหรับคนที่ไม่มีนัด และกินความสูง
~480px ดันคิวของฉันตกใต้พับหน้าจอ)

1. **ซ้ายเป็นสองการ์ด** — บน "นัด" (เรียงตามนาฬิกา) · ล่าง "ถึงกำหนด" (งาน + คำร้อง)
   สองกองนี้อ่านคนละแบบ การ์ดละใบจึงไม่ต้องมีคำว่า "ทั้งวัน" มาคั่นกลางรายการ
2. **ขวาสลับได้ วัน / สัปดาห์ / เดือน** — ตั้งต้นที่สัปดาห์ · **จำมุมมองล่าสุดไว้ข้ามการเข้าใช้**
   (`localStorage` คีย์ `ss:my-dashboard:schedule-view`)
3. **การ์ดซ้ายผูกกับ "วันที่เลือก" ไม่ใช่กับมุมมอง** — ตั้งต้นเป็นวันนี้ · กดวันบนปฏิทินแล้ว
   หัวการ์ดเปลี่ยนตามวันนั้น · ปุ่ม "วันนี้" คืนทั้งวันที่เลือกและช่วงที่กาง
4. **ตำแหน่งบนหน้า** — เหนือ "คิวของฉัน" (ของที่มีเวลานัดเลื่อนไม่ได้ ต้องเห็นก่อนไปเลือกงานอื่นทำ)

## รอบสอง — รื้อลำดับของทั้งแท็บ (มติผู้ใช้ 2026-08-21)

- **การ์ด "เริ่มที่นี่" ถูกถอดออก** — มันชี้แถวบนสุดของคิวซึ่งอยู่ห่างไปสองบรรทัด และตอนนี้
  "ของที่ต้องทำวันนี้" มีบ้านของตัวเองแล้วในการ์ด "ถึงกำหนด"
- **แถบตัวเลขด้านบนเปลี่ยนเป็นยอดเงิน** (เป้า % · ยอดปิดได้ · ดีลที่เปิดอยู่ · Pipeline ·
  ยอดถ่วง FC) แทนจำนวนของค้าง — ของค้างมีที่อยู่สองที่อยู่แล้ว (ชิปกรองบนคิว · การ์ดถึงกำหนด)
  ⇒ บล็อก "ตัวเลขของฉัน" ที่เคยอยู่ใต้คิวถูกยุบขึ้นมาเป็นแถบนี้ ปุ่ม "ตั้งเป้า"/"ดูผลงานเต็ม"
  ย้ายขึ้นมาอยู่เหนือแถบ
- **คิวของฉัน (ซ้าย) กับ รายการอัปเดตล่าสุด (ขวา) อยู่บรรทัดเดียวกัน** — ยุบเป็นคอลัมน์เดียว
  ที่ ≤1000px
- **แถบยอด 4 ช่อง** — เป้า (ยอดเงิน) · ยอดปิดได้ · **% ที่ปิดได้** (ยอดปิดได้ ÷ เป้า) ·
  **ดีลที่เปิด** (มูลค่า + จำนวนใบ) · ⚠️ ตอนเพิ่มช่อง % ต้องย้ายช่อง "เป้า" กลับไปโชว์
  **ยอดเป้า** ไม่ใช่ % ไม่งั้นเลขเดียวกันโผล่สองช่อง · ไม่มีเป้า = ทั้งสองช่องเป็นขีด
  (ไม่มีตัวหาร ห้ามคิด % จากเป้า 0) ·
  "ดีลที่เปิดอยู่" กับ "Pipeline" เดิมพูดถึงกองเดียวกัน ยุบเป็นใบเดียว · **"ยอดถ่วง FC" ถูกตัดออก**
  (มติผู้ใช้ — ค่าคาดหวังของท่ออ่านที่แท็บ "ผลงานขาย" ที่เดียว) · ช่อง "ยอดปิดได้" บอกส่วนต่าง
  กับเป้าแทนการเขียนชื่องวดซ้ำ **ยกเว้นตอนยังไม่ตั้งเป้า** ซึ่งไม่มีอะไรให้เทียบ
  (เป้า 0 กับ "ยังไม่ตั้งเป้า" คนละเรื่อง)
- **ตัวกรองของสองแผงเป็นคอนโทรลเดียวกันและอยู่ระดับเดียวกัน** — เดิมคิวใช้ปุ่มเรียงกันในตัวการ์ด
  ส่วนฟีดใช้ชิปข้อความบนหัวส่วน ⇒ ของที่ทำงานเหมือนกันสองอันบนจอเดียวหน้าตาคนละแบบ ·
  ทั้งคู่เป็น `Segmented` พร้อมจำนวนในชิป วางในแถบเครื่องมือของ body เหมือนกัน ·
  **จำนวนในชิปฟีดนับจากก้อนก่อนกรอง** ไม่งั้นชิปที่ไม่ได้เลือกจะขึ้น 0 ทั้งแถวตอนกรองอยู่
- **ปุ่ม "ตั้งเป้า" / "ดูผลงานเต็ม" ย้ายไปอยู่ระดับเดียวกับแท็บ** (`app/sa/dashboard/page.js`)
  — ปุ่มที่ลอยเหนือแถบตัวเลขอ่านเหมือนปุ่มของแถบตัวเลข ทั้งที่มันคือทางออกไปหน้าอื่น ·
  "ดูผลงานเต็ม" สลับไปแท็บ "ผลงานขาย" ในหน้าเดียวกัน (เดิมเป็นลิงก์พร้อม `scope=person`)
- **สองแผงล่างสูงเท่ากันและเลื่อนข้างในเอง** — เพดาน `430px` ≈ **8 แถวของคิว** (แถวลิสต์ 52px)
  · ฟีดโหลดเพิ่มทีละ 8 โพสต์ **โดยการ์ดไม่สูงขึ้น** ของใหม่ต่อท้ายในกล่องที่เลื่อนเอง ·
  ปุ่ม "ดูเพิ่มเติม" อยู่นอกกล่องเลื่อน · หัวตารางคิวตรึงไว้ตอนเลื่อน
- **เมนู "ปฏิทินนัด" ย้ายไปกลุ่มขวาของแถบเมนู ข้าง "วางเป้า"** (`utility: true` ใน `AppLayout`)
  — แถบซ้ายเป็นลำดับงาน (ลีด → ดีล → ใบเสนอราคา → ใบสั่งขาย) ส่วนปฏิทิน/วางเป้าเป็นเครื่องมือ
  · ปุ่ม "ปฏิทินนัด" ที่หัวส่วนกำหนดการถูกถอดออกตาม (สองประตูไปหน้าเดียวกันบนจอเดียว)

## รอบสาม — แก้ของที่ขัดกันเอง (ตรวจทั้งหน้า 2026-08-21)

| ที่เจอ | ทำไมมันผิด | แก้ยังไง |
|---|---|---|
| แถบสัปดาห์ซ่อนชิปแล้วไม่บอก | เช็ค `นัด+ถึงกำหนด > 4` ⇒ นัด 4 ใบ ถึงกำหนด 0 หาย 2 ใบเงียบ ๆ · นัด 5 ใบขึ้น "+1" ทั้งที่ซ่อน 3 | นับที่ถูกตัด**ของแต่ละกอง** (`WEEK_CELL_LIMIT`) |
| "ดูผลงานเต็ม" ไปโผล่ยอดทั้งบริษัท | ย้ายปุ่มขึ้นแถวแท็บแล้วเปลี่ยนเป็น `setTab` ⇒ ไม่ส่ง `scope` · `PerformanceTab` ตั้งต้น `company` | กลับเป็นลิงก์ `?tab=performance&scope=person&person=<id>` (id จาก `/api/users/me`) |
| คำร้องใบเดียวสองวัน | ปฏิทินใช้ `committedDueDate \|\| requestedDueDate` แต่คิวอ่านแต่ `committedDueDate` ⇒ ปฏิทินวางวันหนึ่ง คิวบอก "ไม่มีกำหนด" | คิวถอยไปใช้ `requestedDueDate` ด้วย แต่ `basis: 'waiting'` (ยังไม่มีใครรับปาก = ไม่ใช่สาย) + เทสต์คุมสองเคส |
| หัวการ์ด "ถึงกำหนด" ขึ้นขีดทั้งที่มีแถว | นับแต่ของวันนั้น ไม่นับของค้างที่โชว์อยู่ใต้มัน | นับ `items + overdue` |
| "นัดถัดไป" เปลี่ยนคำตอบตามมุมมอง | มันกรองจากก้อนที่โหลด = ช่วงที่กางอยู่ ⇒ เลื่อนไปเดือนหน้าแล้วนัดแรกของเดือนนั้นกลายเป็น "นัดถัดไป" | โชว์เฉพาะตอนช่วงที่กางคลุมวันนี้ |
| สลับสัปดาห์→วัน แล้ววันที่เลือกหาย | `anchor` ไม่ตามวันที่เลือก แล้ว `clampSelected` ดึงกลับมาวันนี้ | ตอนสลับเป็นมุมมองวัน `anchor = selected` |
| กดลูกศรแล้วปฏิทินว่างใต้ป้ายช่วงใหม่ | โครงขึ้นเฉพาะโหลดครั้งแรก (`loading && !data`) ⇒ ช่วงใหม่ดูเหมือน "ไม่มีอะไร" | ขึ้นโครงทุกครั้งที่ `loading` |
| ป้ายจำนวนบนหัวแผงชนกับชิป | ป้ายนับหลังกรอง ชิปนับก่อนกรอง = สองเลขไม่เท่ากันบนหัวเดียว | ถอดป้ายออกทั้งสองแผง (ชิปบอกจำนวนอยู่แล้ว) |
| อื่น ๆ | `aria-label` แถบยอดอ้างว่าเป็นของงวด ทั้งที่ "ดีลที่เปิด" เป็นทุกงวด · สถานะว่างของคิวมีอิโมจิ (ผิดกฎ "ไม่มีอิโมจิบนหน้าจอ") | ตัดงวดออกจากป้าย · ลบอิโมจิ |

## แหล่งข้อมูล และความละเอียดของเวลา

| แหล่ง | ฟิลด์ | ความละเอียด | ที่อยู่บนจอ |
|---|---|---|---|
| นัดลูกค้า — `lead_events` (kind='meeting') | `eventAt` (timestamptz) | **มีเวลาจริง** | การ์ด "นัด" · บล็อกในรางของมุมมองวัน |
| งานของฉัน — `personal_tasks` | `dueDate` (วันล้วน) | วัน | การ์ด "ถึงกำหนด" · แถว "ทั้งวัน" |
| คำร้องที่ฉันเปิด — `dept_requests` | `committedDueDate` (ถอยเป็น `requestedDueDate`) | วัน | เหมือนงาน |

**ห้ามเดาเวลาให้ของที่เป็นวันล้วน** — งานกับคำร้องอยู่แถว "ทั้งวัน" เท่านั้น

## กับดักที่เจอระหว่างทำ

- **`lead_events` ไม่มีความยาวนัด** (เก็บแต่เวลาเริ่ม) ⇒ บล็อกในรางยาว 1 ชม. ตาม
  `ASSUMED_MEETING_MINUTES` และ "เวลาชนกัน" ทั้งหมดอยู่ใต้ข้อสมมตินี้ · อยากได้ของจริงต้องเพิ่ม
  คอลัมน์ `durationMin` + ช่องในฟอร์มนัดของคิวลีด (ยังไม่ทำ)
- **คำร้องมีวันสองชนิด ห้ามปนกัน** — `committedDueDate` คือฝ่าย *รับปาก* (ของจริง) ·
  `requestedDueDate` คือผู้ขอ *อยากได้* ⇒ ใบที่ยังไม่รับปาก **ไม่นับว่าเลยกำหนด** เพราะยังไม่มี
  ใครผิดสัญญา (ป้ายแดงตรงนั้นคือการโทษฝ่ายที่ยังไม่ได้รับปาก)
- **`.neq('status','Completed')` ตัดแถวที่สถานะเป็น NULL ทิ้งด้วย** (PostgREST) ⇒ กรองงานที่ยัง
  ไม่เสร็จฝั่ง JS ไม่ใช่ใน query
- **แบ่งช่องวันของนัดด้วยเวลาท้องถิ่นเสมอ** — `eventAt` เป็น UTC · server ส่ง ISO ดิบมาแล้วให้จอ
  เป็นคนตัด (`localDayKey`) กติกาเดียวกับ `lib/sales/leadCalendar.js`
- **ห้ามอ่านนาฬิกาตอนเรนเดอร์** (`Date.now()` / `new Date()`) — React Compiler ตกทันที และ
  SSR/CSR ได้คนละค่า ⇒ "นัดถัดไป" กับแถบ "ตอนนี้" อ่านเวลาใน `useEffect`
- **แถบ "ตอนนี้" ละเอียดระดับ 30 นาที ไม่ใช่เส้นตามนาที** — เส้นรายพิกเซลต้องใช้ inline style
  ซึ่งชนเพดาน `audit:ui` (metric `inlineStyle` ของโมดูลขายขึ้นไม่ได้) ⇒ ย้อมช่วงครึ่งชั่วโมงแทน
  ด้วยเหตุผลเดียวกัน ตำแหน่งบล็อกในรางมาจาก `data-slot`/`data-span` ที่ CSS module แปลเป็น `grid-row`

## ยังไม่ทำ

- ยังสร้าง/แก้/เลื่อนนัดจากหน้านี้ไม่ได้ — นัดเกิดจากคิวลีดที่เดียว กดแล้วเด้งไปใบลีด (กฎเจ้าของโมดูล)
- ยังไม่มีความยาวนัดจริง (ดูกับดักข้อแรก)
- UAT ยังไม่ได้ทำบนบัญชีที่มีนัดจริง — บัญชีที่ใช้ทดสอบไม่มีนัดในระบบ นัดในภาพทดสอบเป็นข้อมูล
  ปลอมที่ค้างไว้ฝั่งเบราว์เซอร์เท่านั้น ไม่ได้เขียนลงฐาน
