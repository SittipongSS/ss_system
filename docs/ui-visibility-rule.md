# เห็นได้ = โชว์เลย · ติดด่าน = โชว์แล้วบอกเหตุ

> สถานะ: `กำลังดำเนินการ` · มติผู้ใช้ 2026-08-30 · ตรวจกับโค้ดเมื่อ 2026-08-30

กฎเดียวที่ตอบคำถาม **"ของชิ้นนี้ควรโผล่บนจอไหม และถ้าโผล่แล้วกดไม่ได้ ต้องบอกอะไร"**
ใช้กับทุกปุ่ม ทุกเมนู ทุกช่องข้อมูล ทั้งหน้ารายละเอียด แถวตาราง โมดัล และการ์ด

## กฎ

**สองคำถามคนละคำถาม อย่ารวมเป็นคำถามเดียว**

| คำถาม | ตัวตัดสิน | ผลบนจอ |
|---|---|---|
| **1. คนนี้มีสิทธิ์รู้ไหมว่ามีของชิ้นนี้อยู่** | บทบาท/ฝ่าย/ขอบเขต (`can*`, ทีม, เจ้าของแถว) | ไม่มีสิทธิ์ = **ไม่โชว์** · มีสิทธิ์ = **โชว์เลย** ไม่ต้องกดเปิด ไม่ต้องบัง |
| **2. ใบนี้ *ตอนนี้* ทำรายการนี้ได้ไหม** | สถานะ/ข้อมูลของใบ (ยังไม่มีลูกค้า · ยังไม่อนุมัติ · ยังไม่ถึงขั้น) | **โชว์เสมอ** แล้ว**บอกเหตุ** ห้ามซ่อน ห้ามหรี่เงียบ ๆ |

สลับสองข้อนี้แล้วได้บั๊กคนละแบบ:
เอาเงื่อนไขของ*ใบ*ไปตอบข้อ 1 ⇒ ปุ่มหายเงียบ ผู้ใช้ไม่รู้ว่าต้องไปทำอะไรก่อน
เอาเงื่อนไข*สิทธิ์*ไปตอบข้อ 2 ⇒ คนไม่มีสิทธิ์เห็นปุ่มที่ตัวเองไม่มีวันแตะได้

## เขียนยังไง

**มี lifecycle อยู่แล้ว (ลีด · ดีล · โครงการ · สัญญา · เอกสาร)** — ประกาศที่ transition
ตัวเดียว แล้วการ์ด (`RecordControlCard`) กับแถวตาราง (`RecordActionMenu`) กินตัวเดียวกัน

```js
{
  id: "deal-win", kind: "advance", label: "ปิดการขาย",
  visible: (record, user) => canEditRecord(user, "deals", record),  // ข้อ 1 — สิทธิ์
  allow: (record) => record.quotationId ? true : "ต้องมีใบเสนอราคาที่อนุมัติแล้วก่อน", // ข้อ 2 — ด่าน
}
```

`allow` คืน `true` = กดได้ · คืน **สตริง** = ปุ่มยังโชว์ แต่ disabled พร้อมเหตุที่คืนมา
(มีเทสต์ล็อกไว้ใน `lib/recordLifecycle.test.mjs` — ห้ามสลับสองช่องนี้)

**ปุ่มเดี่ยวที่ไม่มี lifecycle** (ปุ่มสร้างของบนหน้าดีล/โครงการ ฯลฯ) — `components/ui/GatedAction`

```js
<GatedAction blocker={quotationBlocker} onClick={openQuoteModal}>สร้างใบเสนอราคา</GatedAction>
```

`blocker` ว่าง = ทำงานปกติ · มีข้อความ = กดแล้วขึ้น toast บอกเหตุ (ปุ่มยังอยู่ที่เดิม
ไม่ขยับ ไม่หาย) ⚠️ **`blocker` ต้องมาจากด่านตัวเดียวกับที่ server ใช้ปฏิเสธจริง** —
ห้ามคิดเงื่อนไขขึ้นเองตรงจุดที่วางปุ่ม ไม่งั้นวันหนึ่งปุ่มกับด่านจะพูดคนละเรื่อง

**ทั้งหน้าที่ไม่มีสิทธิ์** — `components/ui/AccessDenied` ตัวเดียวทั้งระบบ

```js
const state = accessState(role, canViewX);          // 'loading' | 'allowed' | 'denied'
if (state === "loading") return <Skeleton/>;        // ห้ามฟ้องก่อนรู้ว่าใครเข้ามา
if (state === "denied") return <AccessDenied icon={<Icon/>} title="ใบสั่งขาย" message="..." />;
```

🪤 `return null` ตอนไม่มีสิทธิ์ = **จอขาวสนิท ไม่มีปุ่มกลับ** ผู้ใช้แยกไม่ออกระหว่าง
"เข้าไม่ได้" กับ "ระบบค้าง" — proxy เปิด URL หลายเส้นให้ทุก role กดถึงได้อยู่แล้ว

## เด้งออกก็ต้องบอกว่าเด้งเพราะอะไร

`proxy.js` กันหน้าที่ role นั้นเปิดไม่ได้ด้วยการ **redirect** — เดิมไป `/home` หรือ
`/settings` เปล่า ๆ ผู้ใช้จึงเห็นแค่หน้าที่ตัวเองไม่ได้กด แล้วเดาเองว่าลิงก์เสียหรือสิทธิ์ไม่ถึง
(เคยกลายเป็นใบแจ้งปัญหาจริงสองรอบ: `/rd` และ `/notifications` ตกจาก `OPEN_PAGES`)

ตอนนี้ redirect ทุกตัวพก `?denied=<path>` ไปด้วย และหน้าปลายทางวาง `<DeniedNotice />`
ซึ่งขึ้นแถบบอกว่าเปิดหน้าไหนไม่ได้ (`/home` · `/settings` · `/database/products`)

⚠️ **หน้าที่มี `AccessDenied` ของตัวเองอยู่แล้ว ไม่ต้องให้ proxy เด้ง** — ปล่อยผ่านมา
ให้หน้าอธิบายเองดีกว่า เพราะ `AccessDenied` บอกได้ว่า *หน้าอะไร* และ *ใครเปิดได้*
(ทำแล้วกับ `/database/product-categories`) · ไม่ได้เปิดข้อมูลเพิ่ม เพราะหน้าคืน
`AccessDenied` ก่อนยิง API และ API ยังมีด่านของตัวเอง

⚠️ **ด่านระดับโมดูลอยู่ที่ `layout.js` ไม่ใช่ `page.js`** — `app/sahamit/layout.js` เคย
`router.replace("/home")` + `return null` ทั้งโมดูล และรอดสายตาตอนไล่หน้ารอบแรก
เพราะสแกนแค่ `page.js` (เทสต์ข้อ 8/9 นับ `layout.js` ด้วยแล้ว)

⚠️ **ปุ่มกลับต้องไม่พาไปหน้าที่ถูกปฏิเสธซ้ำ** — หน้าลูกของ `/mgmt` เคยให้ปุ่มกลับชี้
`/mgmt` ซึ่งคนคนเดียวกันก็เปิดไม่ได้ = ทางตันสองชั้น · ชี้ `/home` แทน

## `disabled` เปล่า ๆ ใช้ได้แค่ไหน

| สถานการณ์ | เขียนยังไง |
|---|---|
| กำลังบันทึก/กำลังโหลด (`busy` · `saving`) | `disabled` เฉย ๆ — สถานะชั่วคราว ไม่มีเหตุให้อธิบาย |
| ยังกรอกไม่ครบ **ในฟอร์ม/โมดัลเดียวกัน** | `disabled` ได้ — ช่องที่ขาดอยู่ตรงหน้าแล้ว |
| เงื่อนไขอยู่**นอกจอนี้** (ต้องไปแก้ที่ใบอื่น/หน้าอื่น) | ต้องบอกเหตุ — `allow` หรือ `GatedAction` |

เส้นแบ่งคือ **"ผู้ใช้มองเห็นเหตุอยู่แล้วหรือเปล่า"** ไม่ใช่ว่าเงื่อนไขซับซ้อนแค่ไหน

## ไม่ใช่ด่าน — ไม่ต้องโชว์

กฎนี้พูดถึง "ยังทำไม่ได้ **ตอนนี้** แต่ทำได้ถ้าไปจัดการอย่างอื่นก่อน" เท่านั้น
สามอย่างนี้ไม่ใช่ด่าน ซ่อนได้ตามเดิม:

- **ทำไปแล้ว** — ปุ่ม "รับแล้ว" บนแถวที่สถานะรับแล้ว · ปุ่ม "ส่ง" บนใบที่ส่งไปแล้ว
- **ไม่มีของให้ทำ** — "ขอให้ PC อัปเดตกำหนด" ตอนไม่มีรายการค้างสักรายการ
- **เครื่องมือของจอ** — ล้างตัวกรอง (ตอนไม่ได้กรอง) · ดูเพิ่ม (ตอนไม่มีของเหลือ) · หน้าถัดไป

ถามตัวเองว่า *"ถ้าผู้ใช้อยากกดปุ่มนี้ตอนนี้ เขาต้องไปทำอะไรก่อน"* — ตอบได้ = ด่าน ต้องบอก ·
ตอบไม่ได้เพราะไม่มีอะไรให้ทำ = ไม่ใช่ด่าน

## ข้อมูล ไม่ใช่แค่ปุ่ม

- **เห็นได้ตามสิทธิ์ = โชว์ค่าเลย** ห้ามซ่อนใต้ปุ่ม "แสดง" หรือใส่จุดบัง
  (`canSeeProductCost` ผ่านแล้วต้องเห็นตัวเลข ไม่ใช่เห็นปุ่มขอดู)
- **ไม่มีสิทธิ์ = ตัดตั้งแต่ server** ไม่ใช่ส่งมาแล้วซ่อนด้วย CSS
  (`redactProductMargin` เป็นตัวอย่างที่ทำถูก)
- **แก้ไม่ได้แต่ดูได้ = โชว์แบบอ่านอย่างเดียว** ไม่ใช่ตัดช่องทิ้ง — ช่องที่หายไปทำให้
  ผู้ใช้คิดว่าระบบไม่เก็บข้อมูลนั้น
- **ของที่ถูกกรองออกเพราะสิทธิ์ ให้บอกจำนวน** เช่น `ซ่อน 3 งานที่ไม่มีสิทธิ์เห็น`
  ไม่ใช่หายไปเฉย ๆ จนยอดรวมไม่ตรงกับที่เห็น

## ที่แก้ในรอบนี้ (2026-08-30)

`/mgmt` · `/mgmt/tasks` · `/mgmt/calendar` · `/mgmt/trash` · `/mgmt/meetings` · `/mgmt/rocks` ·
`/sa/calendar` · `/database/product-categories` · `/database/product-categories/import`
(หกหน้าแรกยัง `router.replace("/home")` ทิ้งไว้ด้วย ⇒ ผู้ใช้เด้งออกโดยไม่รู้ว่าเพราะอะไร — ถอดออกแล้ว)

**12 หน้าที่เขียนจอปฏิเสธของตัวเอง** (glass-panel ลอย ๆ · `empty-state dashed` + inline style · `StatusNotice`) ⇒ `AccessDenied`
`/sa/projects` · `/sales-planning/leads` · `/sales-planning/quotations` · `/sales-planning/quotations/new` ·
`/sales-planning/sales-orders` · `/sales-planning/sales-orders/new` · `/sales-planning/targets/report` ·
`/users` · `/sahamit/forecast/new` · `/sahamit/forecast/[id]/edit` · `/sahamit/po/new` · `/sahamit/po/[id]/edit`

ทุกหน้าที่แตะเปลี่ยนจาก `!can*` เป็น `accessState(role, can*)` ด้วย — ของเดิมฟ้อง
"ไม่มีสิทธิ์" แวบหนึ่งทุกครั้งที่เปิดหน้า เพราะ role ยังไม่กลับมาจาก `getUser()`

**ปุ่มที่ซ่อน/หรี่โดยไม่บอกเหตุ**

| ที่ | เดิม | ตอนนี้ |
|---|---|---|
| หน้าดีล — "สร้างโครงการใหม่" · "ผูกกับโครงการเดิม" (ตอนยังไม่มีไทม์ไลน์) | ซ่อนจนกว่าดีลจะถึงขั้น *เสนอไทม์ไลน์* | โชว์เสมอ — 🐞 ด่านจริงฝั่ง server (`create-project`) **ไม่เคยตรวจ stage** จอจึงเข้มกว่าของจริง |
| หน้าดีล — "ผูกกับโครงการเดิม" (ตอนมีไทม์ไลน์แล้ว) | `disabled` + เหตุใน tooltip | `GatedAction` — จอสัมผัสไม่มีวันเห็น tooltip |
| หน้า PO สหมิตร — เลือก/สร้างโครงการ · ยืนยันดีล | `disabled` เงียบ ๆ ตอน PO ไม่มีรายการ | `GatedAction` บอกให้ไปเพิ่มรายการที่หน้าแก้ PO |

**สายเด้งออก (`proxy.js`)**

| เดิม | ตอนนี้ |
|---|---|
| `/database/product-categories` → `/database` เงียบ ๆ | ปล่อยผ่าน ให้หน้าโชว์ `AccessDenied` ของตัวเอง |
| `/settings/company` · `/settings/workflow-templates` → `/home` เปล่า ๆ | `/home?denied=…` + แถบบอกเหตุ |
| `/settings/document-standards` · `/settings/commercial-presets` → `/settings` เปล่า ๆ | `/settings?denied=…` + แถบบอกเหตุ |
| `/database` (คนที่ไม่มี `customers:view`) → `/database/products` เงียบ ๆ | `?denied=…` + แถบบอกเหตุ |
| ด่าน default-deny (`lockedOut`) เด้งทุกหน้านอก `OPEN_PAGES` ไป `/home` เงียบ ๆ | `/home?denied=…` + แถบบอกเหตุ |

`components/ui/DeniedNotice` อ่าน `?denied=` จาก `window.location` (ไม่ใช่ `useSearchParams()`
ซึ่งบังคับให้หน้าที่เรียกต้องมี `<Suspense>`) และรับเฉพาะ path ในระบบเดียวกัน

**`app/sahamit/layout.js`** — ด่านทั้งโมดูล เคย `router.replace("/home")` + `return null`
⇒ `AccessDenied` (ไอคอน/ชื่อตรงกับ `config/systems.js`)

**ปุ่มกลับของหน้าลูก `/mgmt`** เคยชี้ `/mgmt` ซึ่งคนเดียวกันก็เปิดไม่ได้ ⇒ ชี้ `/home`

**ด่านใน CI** — `lib/systemRules.test.mjs` ข้อ 8 (ห้ามเขียนจอปฏิเสธเอง — มี
`PAGES_WITH_OWN_DENIAL_TEXT` สำหรับ 5 กรณีที่ไม่ใช่การปิดประตูทั้งหน้า) และข้อ 9
(ห้าม `return null` ตอนด่านสิทธิ์ไม่ผ่าน) · **นับทั้ง `page.js` และ `layout.js`** ·
ทั้งสองข้อลองทำให้ตกจริงแล้วก่อนส่ง

## ยังไม่ได้ทำ

- UAT รอบแรกผ่านแล้วด้วยบัญชี `ts_manager` (2026-08-30) — เหลือลองด้วย role
  ที่มี *บางส่วน* ของสิทธิ์ (rd = ดูงานขายได้แต่สร้างไม่ได้ · executive = เข้า /mgmt ได้)
- `disabled` ที่เหลืออีก ~340 จุดยังไม่ไล่ทีละตัว — ที่ไล่รอบนี้คือจุดที่เงื่อนไข
  **อยู่นอกจอ** เท่านั้น · ส่วนที่เป็น `busy`/`saving`/ช่องในฟอร์มเดียวกัน ถูกต้องตามกฎอยู่แล้ว
- lifecycle ที่ยังไม่มี (คำร้อง · งาน · ใบแจ้งปัญหา) ยังกระจายกติกาปุ่มไว้ในหน้า —
  ย้ายเข้า `defineLifecycle` เมื่อแตะหน้านั้นครั้งถัดไป
