# ส่งต่องานบริหารงานขาย

สถานะ: **รอตรวจ** · มติเจ้าของ 27/11/2026 (ถามทีละข้อ) · แบบหน้า `~/ss-team/mockups/sales-handover/index.html`

## ที่มา

27/11/2026 เจ้าของสั่งเปลี่ยนเจ้าของดีลหนึ่งใบ แล้วต้องตามย้ายมือเพิ่มอีกสองที่ (SO ร่าง · สัญญาร่าง) ถึงจะ "ส่งต่องานแบบเต็มรูปแบบ"
ปุ่ม "โอนงานพนักงาน" เดิมใน /users ย้ายได้แค่ดีลเปิดทั้งหมดให้คนเดียว + เป้า · ไม่แตะดีล Won ที่งานยังค้าง ใบร่าง และลีด

## มติ 7 ข้อ

1. ทำทั้งสองทาง ใช้หน้าต่างเลือกตัวเดียวกัน
   - ปุ่ม ⇄ "โอนงาน" ใน /users → หน้า `/users/[id]/handover` โชว์รายการ เลือกทีม + คนรับทีละรายการ โอนแล้วหายไปจนเหลือ 0
   - ปุ่ม "ส่งต่องาน" ใน **Control Panel รางขวา** ของหน้าดีล (`RecordControlCard` · secondary) และหน้าลูกค้า (การ์ด "จัดการลูกค้า")
2. ปุ่มบนหน้าดีล/ลูกค้า: AE Supervisor + Admin (`canHandoverSalesWork` = `isSalesManager` · CD/CM ที่อยู่เหนือ Sup ได้ด้วย)
   ไม่มีสิทธิ์ = ไม่โชว์ปุ่ม · ติดเงื่อนไขของใบ = โชว์แล้วบอกเหตุ · หน้า /users/[id]/handover = `users:manage`
3. ดีลในรายการ = ดีลเปิด + ดีล Won ที่งานยังไม่จบ · Won ที่จบแล้ว + Lost อยู่กับคนเดิม · ยอดขายของ SO ที่อนุมัติแล้วไม่ย้าย
   **"งานยังไม่จบ"** (เจ้าของยืนยัน 27/11) = ยังไม่ออก SO · มี SO ยังไม่อนุมัติ · สัญญายังไม่จบ (ร่าง/รอลงนาม/รอรับรอง) · SO ที่อนุมัติแล้วยังมีงวดที่บัญชียังไม่ยืนยัน
   ดีลของใบสั่งขายย้อนหลัง (ภาชนะระบบ) ไม่อยู่ในรายการ — ย้ายทีละใบที่ฟอร์มแก้ไขดีล (UNIQUE ลูกค้า × AE ของ mig 0360)
4. ลีดเปิดอยู่ในรายการ เลือกคนรับทีละใบ (ด่านคนรับตัวเดียวกับหน้าลีด `validateLeadAssignee`)
5. เป้าแบ่งได้หลายคน กรอกยอดรายเดือนต่อคน ผลรวมแต่ละแถว (เดือน × ทีม) ต้องเท่าเป้าเดิมพอดี + ปุ่มเกลี่ยเท่ากัน
6. ส่งต่อแล้ว คนเดิมหยุดได้กระดิ่งเธรดของดีลนั้น ยกเว้นถูก @ ถึง · ประวัติว่าใครทำอะไรไม่แตะ
7. AC และ AE Supervisor เลือกได้ทุกแถวทุกครั้ง (ตั้งต้น = คนเดิมของใบ · แถบส่งหลายใบตั้งต้น "คงคนเดิมของแต่ละใบ")

ค่าตั้งต้นที่ไม่ได้ถามแยก: คนรับได้กระดิ่งหนึ่งครั้งต่อคำขอ (โอน 30 ใบ = 1 กระดิ่งสรุป) · หมายเหตุไม่บังคับ · ทีมตั้งต้น = ทีมเดิมของใบ · คนรับไม่มีค่าตั้งต้น

## อะไรย้ายตาม

| ของ | ช่องที่ย้าย | หมายเหตุ |
| --- | --- | --- |
| ดีล | `ownerId` `ownerName` `team` (+ AC/Sup ถ้าเลือกใหม่) | `metadata.handedOffFrom` จดคนเดิม (ตัดกระดิ่ง) |
| SO ยังไม่อนุมัติ (ร่าง · รออนุมัติ · ตีกลับ · ยกเลิกอนุมัติ) | `createdBy` `createdByName` | ตีกลับแล้วกลับไปหาคนรับ · อนุมัติทีหลังเจ้าของยอด = คนรับ (trigger 0294) |
| SO อนุมัติแล้ว | ไม่ย้าย | `ownerId` = เจ้าของยอด แช่ไว้ |
| สัญญายังไม่จบ | `ownerId` `ownerName` `createdBy` `createdByName` `team` | กระดิ่ง/คิว "รอฉัน" ของสัญญาไปหาคนรับ |
| สัญญาลงนามแล้ว | `ownerId` `ownerName` `team` | ผู้สร้างคือประวัติ ไม่แตะ |
| ใบเสนอราคา | ไม่เขียน | ชื่อผู้เสนอราคาบนใบพิมพ์อ่านจากเจ้าของดีลสด · เบอร์ที่ตรึงไว้ไม่ตรง id ⇒ บรรทัดเบอร์หาย · ไม่ต้องออก Rev. |
| ลีดเปิด | `assigneeId` `assigneeName` `team` | ลง `lead_events` kind `reassign` · รีเซ็ตนาฬิกาเฉพาะใบที่ยังไม่ได้ติดต่อ |
| เป้าเดือนถัดไปเป็นต้นไป | แบ่งให้หลายคน | ต้นทางตั้ง 0 + โน้ต |

## โค้ด

- ตัวคิดล้วน: `webapp/src/lib/sales/handover.js` (เทสต์ `handover.test.mjs`)
- อ่านรายการ: `webapp/src/lib/sales/handoverRead.js` · เขียน: `handoverWrite.js`
- API: `GET/POST /api/sales-planning/handover` · แบ่งเป้า `POST /api/users/[id]/transfer` (body `{ split }`)
- ตัดกระดิ่งคนเดิม: `recipientsForUpdate` (lib/notifications.js) — ตัดหลังรวมชุดคนเคยโพสต์ · กระดิ่งคนรับ kind `sales_handover` (`HANDOVER_BELL_KINDS`)
- เธรดดีล: ชนิด `handover` (quiet)
- จอ: `components/salesPlanning/handover/*` · หน้า `app/users/[id]/handover/page.js`

## ยังไม่ได้นับ

- งานบริการที่ยังมีรอบเหลือ (ไซต์/แผนบริการไม่ผูกดีลตรง) — ดีล Won ที่เก็บเงินครบและสัญญาจบแล้วถือว่าจบ แม้ยังมีรอบบริการ
