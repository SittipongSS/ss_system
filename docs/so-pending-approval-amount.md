# ยอด SO "รออนุมัติ" — โชว์ได้ แต่แยกจาก Actual

> สถานะ: **กำลังดำเนินการ** · ตรวจกับโค้ดเมื่อ 2026-09-11 · mig 0353 รันบนฐานจริงแล้ว 2026-09-11 (backfill 8 ดีล รวม 993,000 · wonValue คงเป็น 0 ครบ)

## ที่มา

ผู้ใช้แจ้ง 2026-09-11: *"SO ที่รออนุมัติ มันกลายเป็น 0 อยากให้โชว์ยอดด้วย แต่แยกให้รู้ว่า
รออนุมัติ กับ Actual แล้ว ทั้งระบบ"*

ดีลกลายเป็น **Won** ตั้งแต่กดรับใบเสนอราคา (mig 0284) แต่ **Actual** นับเฉพาะใบสั่งขายที่
**อนุมัติแล้ว** (mig 0110 / 0279) ⇒ ช่วงที่ SO ยื่นแล้วรอ AE Supervisor อนุมัติ ยอดของดีล
หายไปจากทุกจอ:

- หลุดจาก **FC คงเหลือ** เพราะดีล Won แล้ว
- ยังไม่เข้า **Actual** เพราะใบยังไม่อนุมัติ
- เหลือร่องรอยแค่ใน FC Total ซึ่งไม่มีใครอธิบายได้ว่าส่วนต่างมาจากไหน

ของจริงวันที่แจ้ง: SO รออนุมัติ 8 ใบ รวม 993,000 บาท (ก่อน VAT) · ทุกใบอยู่บนดีล Won ที่ Actual = 0

## มติ

| เรื่อง | มติ |
|---|---|
| โชว์ไหม | โชว์ทุกจอที่โชว์ Actual — เป็น **ตัวเลขแยก** มีคำว่า "รออนุมัติ" กำกับเสมอ |
| นับอะไร | เฉพาะ `status = 'pending_approval'` · ร่าง / ตีกลับ / ย้อนอนุมัติ / ออก Rev. แล้ว / ยกเลิก **ไม่ใช่** รออนุมัติ |
| ยอดไหน | `actualAmount` (ก่อน VAT) ตัวเดียวกับ Actual — ห้ามใช้ `totalAmount` |
| เดือนไหน | **เดือนปัจจุบัน (เวลาไทย) เสมอ** — อนุมัติย้อนหลังไม่ได้ ถ้าอนุมัติวันนี้ Actual ก็ลงเดือนนี้ · ใบที่ค้างข้ามเดือนเลื่อนมาอยู่เดือนใหม่เอง · เดือนที่ปิดแล้ว/ปีก่อนไม่มีวันเห็นยอดนี้ |
| นับให้ใคร | ดีล Won เท่านั้น (ดีลที่ยังเปิดมี FC อยู่ใน FC คงเหลือแล้ว) · รายคน/รายทีมตามเจ้าของดีล **ปัจจุบัน** (`sales_orders.ownerId` ว่างจนกว่าจะอนุมัติ — mig 0294) |

### ⛔ ห้ามบวกเข้า Actual — ทุกกรณี

wonValue · won · actual[] · เป้า/% ปิดได้/ขาด-เกิน · variance · ยอดทบ (carry) · YoY ·
แผนที่ความร้อน · ยอดที่ตัวช่วยวางเป้า (`/api/sales-planning/history`) และปุ่ม
"เติมยอดจากระบบ" (`/sa/targets/history`) **คัดลอกไปเก็บใน `sales_history` ถาวร** —
ถ้ายอดรออนุมัติหลุดเข้าไป มันจะกลายเป็น Actual ปลอมที่ทับยอดจริงตลอดไป

ข้อยกเว้นเดียวที่ตั้งใจ: **ยอดคาดการณ์ (`windowStat.projected` ของแท็บผลงานขาย)** =
Actual + รออนุมัติ + FC คงเหลือ — ใบที่ยื่นแล้วเกือบแน่นอน ถ้าไม่นับ "คาดขาด" จะเกินจริง
ส่วน % และส่วนต่างที่อยู่ข้างกันยังคิดจาก Actual ล้วน

## ที่เก็บข้อมูล

**mig 0353** — trigger เดิมสองตัวเขียน cache เพิ่มสองคีย์ใน `sales_deals.metadata`

| คีย์ | ความหมาย |
|---|---|
| `soPendingAmount` | Σ `actualAmount` ของ SO รออนุมัติของดีล |
| `soPendingCount` | จำนวนใบ |

- ไม่มี SO รออนุมัติ = **ไม่มีคีย์** (ถอดทิ้ง ไม่เขียน 0 ค้างทุกดีล) · JS อ่านคีย์ที่ไม่มีเป็น 0
  ⇒ โค้ดขึ้น production ก่อนรัน migration ได้โดยไม่มีอะไรพัง
- `sync_sales_order_actual` กับ `enforce_sales_order_actual_on_deal` ต้องแก้ **คู่กันเสมอ**
  enforce เป็น BEFORE UPDATE ที่ไม่มีเงื่อนไข = คนเขียนคนสุดท้าย และ PATCH ดีลเอา metadata
  ทั้งก้อนของหน้าจอไป merge ทับ — enforce จึงเป็น "เจ้าของ" สองคีย์นี้ (ถอดแล้วใส่ใหม่ทุกครั้ง)
- **ไม่เก็บเดือนใน DB** — เดือนมาจากนาฬิกาตอนอ่าน cache ที่อิง `now()` เน่าเอง
- backfill วนเฉพาะดีลที่มี SO รออนุมัติ **ห้ามวนทุกดีล** (กับดัก 0110)
- 🔒 `src/lib/sales/soPendingApprovalMigration.test.mjs` อ่าน **นิยามล่าสุดในโฟลเดอร์** ของสอง
  ฟังก์ชัน — ใครคัดนิยามเก่า (0107/0108/0110 ที่ยังใช้ `orderDate`) ไปแก้ในไฟล์ใหม่ เทสต์แดง

จอที่อ่านแถว `sales_orders` ตรง ๆ (หน้ารายการ/รายละเอียด SO · ตาราง SO ในดีล/โครงการ ·
ใบเสนอราคา · รายงานเป้า) ไม่ใช้ cache — คิดจากแถวด้วยตัวช่วยชุดเดียวกัน

## ตัวช่วยกลาง — ทุกจอต้องผ่านชุดนี้

| ที่ | ตัวช่วย |
|---|---|
| `lib/sales/salesOrderWorkflow.js` | `salesOrderPendingApprovalAmount(order)` · `salesOrderAmountKind(order)` → `actual` / `pending_approval` / `excluded` · `splitSalesOrderAmounts(orders)` · `dealPendingApprovalAmount(deal)` · `dealPendingApprovalCount(deal)` · `PENDING_APPROVAL_LABEL` |
| `lib/sales/dashboardMetrics.js` | `pendingApprovalAmountOf(d)` · `pendingApprovalCountOf(d)` (นับเฉพาะดีล Won) · `pendingApprovalMonthOf(d, now)` → `currentMonth(now)` เมื่อ **ยอด > 0 หรือมีใบ** (ใบ 0 บาทถูกกฎตั้งแต่ mig 0197 — นับเป็นใบทุกจอ ให้แดชบอร์ดตรงกับรายงานเป้า/หน้า SO ที่นับจากแถวใบ) |
| `lib/sales/projectRollup.js` | `rollupDeals()` คืน `pendingApproval` · `pendingApprovalCount` แยกจาก `actual` |
| `components/salesPlanning/PendingApprovalAmount.js` | ชิ้นแสดงผลเดียวทุกจอ: **"รออนุมัติ ฿X · N ใบ"** — คำว่ารออนุมัติเป็นสีสถานะ (amber เดียวกับป้ายสถานะ SO) ตัวเลขเป็นสีข้อความรอง **ไม่ใช้เขียวของ Actual** |

ชื่อช่องใน payload ทุก API = `pendingApproval` / `pendingApprovalCount` · ห้ามใช้ `pending` เปล่า ๆ
(ชนกับ financeStatus `pending` = รอบัญชีตรวจ · สถานะงวด `pending` · statusOf `pending` = รอปิดยอด)

กราฟ: `CHART_SERIES` ล็อกไว้ 3 สี ⇒ วาดรออนุมัติด้วย **สีของ Actual ที่จางลง + ลายเฉียง**
ไม่เพิ่มสีใหม่

## จอที่ไม่แตะโดยตั้งใจ

- **ตัวช่วยวางเป้า** (`/sa/targets/plan`) และ **กรอกยอดย้อนหลัง** (`/sa/targets/history`) —
  เก็บยอดลง `sales_history` ถาวร ต้องเป็น Actual ล้วน
- **รายงาน FC รายหมวด (Excel)** — เป็นไฟล์ FC ล้วน (ยอดรวมไฟล์ = ผลรวม FC ล็อกด้วยเทสต์)
- **ทะเบียนการชำระ / งวด (`/finance`)** — งวดถูกตรึงตอนอนุมัติ (mig 0259) ยังไม่ใช่ลูกหนี้
- **ภาษีสรรพสามิต · คิวส่งต่อ ops · บริการ · สหมิตร** — อ่านเฉพาะใบอนุมัติแล้วโดยเจตนา

## ยังเปิดอยู่

ดีล Won ที่ Actual เป็น 0 ด้วยเหตุอื่น ยังดูเหมือนเดิม (ไม่อยู่ในขอบเขตคำขอนี้):
Won แต่ยังไม่ออก SO (33 ดีล FC 1,914,850) · มีแต่ SO ร่าง (2 ดีล 25,000) ·
มีแต่ SO ยกเลิก (5 ดีล 678,100) · SO ถูกย้อนอนุมัติรอออก Rev. — ตัวเลข ณ 2026-09-11
