# ยอด SO "รออนุมัติ" — โชว์ได้ แต่แยกจาก Actual

> สถานะ: **รอตรวจ** · ตรวจกับโค้ดเมื่อ 2026-09-15 · รอบแรกขึ้น production 2026-09-11 (#1703 · `099f4a3f`) · รอบสอง (คาดจบงวด + Won รอยื่น SO + ทีมตามดีล) ขึ้น production 2026-09-15 · รอบสาม (Won รอยื่น SO ไม่นับดีลเก่าที่สร้างเป็น Won · มติ 2026-09-15) โค้ดครบในแบรนช์ `claude/won-awaiting-legacy` ยังไม่ขึ้น production · mig 0353 รันบนฐานจริงแล้ว (backfill 8 ดีล รวม 993,000 · wonValue คงเป็น 0 ครบ)

## ที่มา

ผู้ใช้แจ้ง 2026-09-11: *"SO ที่รออนุมัติ มันกลายเป็น 0 อยากให้โชว์ยอดด้วย แต่แยกให้รู้ว่า
รออนุมัติ กับ Actual แล้ว ทั้งระบบ"*

ดีลกลายเป็น **Won** ตั้งแต่กดรับใบเสนอราคา (mig 0284) แต่ **Actual** นับเฉพาะใบสั่งขายที่
**อนุมัติแล้ว** (mig 0110 / 0279) ⇒ ช่วงที่ SO ยื่นแล้วรอ AE Supervisor อนุมัติ ยอดของดีล
หายไปจากทุกจอ:

- หลุดจาก **FC คงเหลือ** เพราะดีล Won แล้ว
- ยังไม่เข้า **Actual** เพราะใบยังไม่อนุมัติ
- เหลือร่องรอยแค่ใน FC Total ซึ่งไม่มีใครอธิบายได้ว่าส่วนต่างมาจากไหน

ของจริงวันที่แจ้ง: SO รออนุมัติ 8 ใบ รวม 993,000 บาท (ก่อน VAT) · ทุกใบอยู่บนดีล Won ที่ Actual = 0

## มติ

| เรื่อง | มติ |
|---|---|
| โชว์ไหม | โชว์ทุกจอที่โชว์ Actual — เป็น **ตัวเลขแยก** มีคำว่า "รออนุมัติ" กำกับเสมอ |
| นับอะไร | เฉพาะ `status = 'pending_approval'` · ร่าง / ตีกลับ / ย้อนอนุมัติ / ออก Rev. แล้ว / ยกเลิก **ไม่ใช่** รออนุมัติ |
| ยอดไหน | `actualAmount` (ก่อน VAT) ตัวเดียวกับ Actual — ห้ามใช้ `totalAmount` |
| เดือนไหน | **เดือนปัจจุบัน (เวลาไทย) เสมอ** — อนุมัติย้อนหลังไม่ได้ ถ้าอนุมัติวันนี้ Actual ก็ลงเดือนนี้ · ใบที่ค้างข้ามเดือนเลื่อนมาอยู่เดือนใหม่เอง · เดือนที่ปิดแล้ว/ปีก่อนไม่มีวันเห็นยอดนี้ |
| นับให้ใคร | ดีล Won เท่านั้น (ดีลที่ยังเปิดมี FC อยู่ใน FC คงเหลือแล้ว) · รายคนตามเจ้าของดีล **ปัจจุบัน** (`sales_orders.ownerId` ว่างจนกว่าจะอนุมัติ — mig 0294) · ทีม = **ทีมของดีล** (`sales_deals.team` — มติ 2026-09-14 "ทีมตามดีล" ไม่ใช่ทีมในบัญชีเจ้าของ ⇒ แถวคน = (คน, ทีมของดีล) คนหลายทีมได้แถวละทีม) |

### ⛔ ห้ามบวกเข้า Actual — ทุกกรณี

wonValue · won · actual[] · เป้า/% ปิดได้/ขาด-เกิน · variance · ยอดทบ (carry) · YoY ·
แผนที่ความร้อน · ยอดที่ตัวช่วยวางเป้า (`/api/sales-planning/history`) และปุ่ม
"เติมยอดจากระบบ" (`/sa/targets/history`) **คัดลอกไปเก็บใน `sales_history` ถาวร** —
ถ้ายอดรออนุมัติหลุดเข้าไป มันจะกลายเป็น Actual ปลอมที่ทับยอดจริงตลอดไป

ข้อยกเว้นเดียวที่ตั้งใจ: **ยอดคาดการณ์ "คาดจบงวด" (`windowStat.projected` ของแท็บผลงานขาย)** —
ดูหัวข้อถัดไป · % · ขาด/เกิน · ทบยอด · ต้องทำเฉลี่ย/เดือน ที่อยู่ข้างกันยังคิดจาก Actual ล้วน

## ยอดคาดการณ์ "คาดจบงวด" + "Won รอยื่น SO" (มติผู้ใช้ 2026-09-14)

> 🐞 คำอธิบายรอบ 11/09 ผิดสามจุด — ตรวจซ้ำกับจอจริง 14/09 แล้วผู้ใช้เลือกใหม่ (ข้อ ก)

**คาดจบงวด = Actual + รออนุมัติ + Won รอยื่น SO + FC คงเหลือ** · คาดขาด = ต้องปิด − คาดจบงวด

| กอง | นับอะไร | เดือน |
|---|---|---|
| Actual | SO อนุมัติแล้ว | เดือนที่อนุมัติ |
| รออนุมัติ | SO `pending_approval` | เดือนปัจจุบันเวลาไทย |
| **Won รอยื่น SO** | ดีล Won ที่ **ยังไม่มี SO อนุมัติ และไม่มี SO รออนุมัติ** (ยังไม่ออก · ร่าง · ตีกลับ/ดึงกลับ · มีแต่ใบยกเลิก) · มูลค่าดีลเต็ม · **ไม่นับดีลเก่าที่สร้างเป็น Won** (`isLegacyWonAtCreate` · มติ 2026-09-15 หัวข้อถัดไป) | เดือนที่ปิด Won (`wonMonthOf` ถังเดียวกับ FC Total) |
| FC คงเหลือ | ดีลที่ยังเปิด · **มูลค่าดีลเต็ม ไม่ถ่วงโอกาสปิด** (ช่องชื่อ `weighted` ในโค้ดหลอก) | เดือน FC |

- **ทำไมต้องมี Won รอยื่น SO**: รับใบเสนอราคา = ดีล Won ทันที (mig 0284) ⇒ หลุดจาก FC คงเหลือ
  แต่ SO เกิดเป็นร่าง (0285) ⇒ ไม่อยู่ในรออนุมัติ/Actual ⇒ คาดขาดพุ่งเต็มมูลค่าดีลจนกว่าจะยื่น SO
  (ของจริง 14/09: 42 ดีล FC 2,659,950 — ไม่มี SO 35 · มีแต่ร่าง 2 · มีแต่ใบยกเลิก 5)
  🐞 ตรวจ 15/09: 35 ดีล "ไม่มี SO" คือดีลเก่าที่สร้างเป็น Won ผ่านสวิตช์ทุกดีล — ยื่น SO ไม่ได้ จึงตัดออก
  (หัวข้อถัดไป) · กองวันนี้ 42 ดีล / 2,348,450 → **7 ดีล / 703,100** (2,659,950 เดิมลดเหลือ 2,348,450 เพราะ mig 0359 ล้างบล็อก A 311,500)
- "มี SO อนุมัติแล้ว" ดูจาก `metadata.wonMonth` ไม่ใช่ยอด Actual > 0 — ใบอนุมัติ 0 บาทมีจริง 28 ดีล
- เดือนที่บริษัทกรอก Actual มือ (`sales_history`) `overlayHistory` ล้างเส้น Won รอยื่น SO ในช่องที่ทับ —
  ยอดของดีลพวกนั้นอยู่ในตัวเลขที่กรอกแล้ว
- ข้อความ "คาดจบงวด … — คาดขาด / คาดถึงเป้า" ขึ้นใต้แถบบริษัทเสมอในงวดที่ยังไม่จบ พร้อมบรรทัดบอกฐาน ·
  แถบเล็กในตารางติดตามบอกค่าเดียวกันผ่าน title/aria (งวดที่จบแล้วไม่พูดคาดการณ์)
- ข้อจำกัดที่รู้: ดีลที่มี SO อนุมัติบางส่วน + ส่วนที่เหลือยังร่าง ไม่นับส่วนที่เหลือ · ดีลเดินข้ามเดือน
  ได้ (Won เดือนหนึ่ง → ยื่น SO อีกเดือน) หน้าต่างรายเดือนจึงเห็นยอดย้ายเดือน ส่วนรายปีคงที่
- ตัวช่วย: `dashboardMetrics` (`isWonAwaitingSo` · `isLegacyWonAtCreate` · `wonAwaitingSoAmountOf` · `wonAwaitingSoMonthOf` ·
  `WON_AWAITING_SO_LABEL`) · API ช่อง `wonAwaitingSo` / `wonAwaitingSoCount` · ลิ้นชัก metric `wonAwaitingSo`

## Won รอยื่น SO ไม่นับดีลเก่าที่สร้างเป็น Won (มติผู้ใช้ 2026-09-15 "เอาที่แนะนำ")

ที่มา: ตรวจฐานจริง 15/09 — กอง Won รอยื่น SO 42 ดีล 2,348,450 เป็นดีลที่สร้างเป็น Won ผ่านสวิตช์
"ดีลเก่าจากระบบเดิม" 35 ดีล 1,645,350 (83% ของจำนวน · 70% ของยอด) · ดีลเหล่านี้ยื่น SO ไม่ได้เลย
(ออกใบเสนอราคาให้ดีล Won ไม่ได้ · SO ต้องมีใบเสนอราคาที่รับแล้ว · PATCH เปลี่ยนขั้นของดีล Won ไม่ได้)

| เรื่อง | มติ |

## ที่เก็บข้อมูล

**mig 0353** — trigger เดิมสองตัวเขียน cache เพิ่มสองคีย์ใน `sales_deals.metadata`

| คีย์ | ความหมาย |
|---|---|
| `soPendingAmount` | Σ `actualAmount` ของ SO รออนุมัติของดีล |
| `soPendingCount` | จำนวนใบ |

- ไม่มี SO รออนุมัติ = **ไม่มีคีย์** (ถอดทิ้ง ไม่เขียน 0 ค้างทุกดีล) · JS อ่านคีย์ที่ไม่มีเป็น 0
  ⇒ โค้ดขึ้น production ก่อนรัน migration ได้โดยไม่มีอะไรพัง
- `sync_sales_order_actual` กับ `enforce_sales_order_actual_on_deal` ต้องแก้ **คู่กันเสมอ**
  enforce เป็น BEFORE UPDATE ที่ไม่มีเงื่อนไข = คนเขียนคนสุดท้าย และ PATCH ดีลเอา metadata
  ทั้งก้อนของหน้าจอไป merge ทับ — enforce จึงเป็น "เจ้าของ" สองคีย์นี้ (ถอดแล้วใส่ใหม่ทุกครั้ง)
- **ไม่เก็บเดือนใน DB** — เดือนมาจากนาฬิกาตอนอ่าน cache ที่อิง `now()` เน่าเอง
- backfill วนเฉพาะดีลที่มี SO รออนุมัติ **ห้ามวนทุกดีล** (กับดัก 0110)
- 🔒 `src/lib/sales/soPendingApprovalMigration.test.mjs` อ่าน **นิยามล่าสุดในโฟลเดอร์** ของสอง
  ฟังก์ชัน — ใครคัดนิยามเก่า (0107/0108/0110 ที่ยังใช้ `orderDate`) ไปแก้ในไฟล์ใหม่ เทสต์แดง
- **mig 0360 (ใบสั่งขายย้อนหลัง · ยังไม่รัน ณ 2026-09-15)** นิยามสองฟังก์ชันนี้ใหม่ โดยเติม `origin = 'pipeline'`
  ในผลรวมทั้งสี่จุด (Actual + รออนุมัติ ของทั้งคู่) — นอกนั้นตรงกับ 0353 ทุกตัวอักษร (`historicalSalesOrderMigration.test.mjs`
  ตัดตัวกรองออกแล้วเทียบ) · ใบย้อนหลังเกิดเป็น "อนุมัติแล้ว" แต่ **ไม่เข้า** ทั้ง Actual และกองรออนุมัติ ·
  ใครคัดนิยามจาก 0353 ไปแก้ในไฟล์ใหม่ = ตัวกรองหาย ⇒ เทสต์แดง · รายละเอียด [historical-sales-orders.md](historical-sales-orders.md)

จอที่อ่านแถว `sales_orders` ตรง ๆ (หน้ารายการ/รายละเอียด SO · ตาราง SO ในดีล/โครงการ ·
