ขอเอกสาร — ทั้งระบบของผู้ขอและฝ่ายที่ถือของ

หัวข้อนี้ต่างจากสองหัวข้อพัฒนาตรงที่ ไม่ผูกกับฝ่ายใดฝ่ายหนึ่ง — ผู้ขอเลือกเองว่า จะถามฝ่ายไหน · ฝ่ายขายทำงานที่ บริหารงานขาย · ฝ่ายที่ถือของทำงานที่โมดูลของตัวเอง · ไฟล์ที่ได้ไปโผล่ที่ เอกสารของดีล

SA ผู้ขอ (บริหารงานขาย) ฝ่าย ฝ่ายที่ถือของ — RD · จัดซื้อ · บัญชี DB ไฟล์แนบ + เอกสารของดีล เสนอใหม่ ยังไม่มีในโค้ดวันนี้
อ่านข้อนี้ก่อน — §07 คือใจความของใบนี้ · ไล่โค้ดวันที่ 2026-08-08 แล้วพบว่า สายของหัวข้อนี้เดินไม่ครบ: แถวเอกสาร ไม่มีทางไปถึง "ได้รับแล้ว" เลยสักทาง ⇒ แถบ "มาแล้ว X · ให้ไม่ได้ Z" ที่หน้าใบโชว์อยู่ นับได้ 0 เสมอ · ส่วนที่เหลือของ ใบนี้วาดตามของที่มีจริง แล้ว §07 กับ §08 เสนอทางปิด

07🔴 สายของหัวข้อนี้เดินไม่ครบ — สามข้อที่ต้องตัดสิน

ไล่โค้ดวันที่ 2026-08-08 · ทั้งสามข้อยืนยันจากไฟล์จริง ไม่ใช่ข้อสังเกตจากการอ่านจอ

ก · แถวเอกสารไม่มีทางไปถึง "ได้รับแล้ว" เลยสักทาง

documentBoard นิยาม received = stage === 'done' ซึ่งต้องการ answerStatus === 'done' · ไล่ทั้งรีโปแล้ว มีที่เดียวที่เขียนค่านี้: …/items/[itemId]/price/route.js ซึ่งเป็นขั้นราคาของสายพัฒนา
เช่นเดียวกัน refused = stage === 'declined' เขียนได้ทางเดียวคือ outcome: 'rejected' = "ลูกค้าไม่เอา" ซึ่งไม่ใช่ความหมายของ "ฝ่ายให้ไม่ได้"
⇒ แถบ "มาแล้ว X · ให้ไม่ได้ Z" นับได้ 0 เสมอ · ตัวเลขเดียวที่ขยับคือ "รอเอกสาร" ซึ่งเท่ากับจำนวนแถวทั้งหมดตลอดไป

ข · แถบก้าวถัดไปเสนอก้าวของสายพัฒนาให้แถวเอกสาร

HOP_AT_STAGE แปลงขั้น→ก้าว โดยไม่ดู lineKind ⇒ แถวเอกสาร ได้ปุ่มชุดเดียวกับกลิ่น/สูตร:
รับเรื่อง → ส่งของ → รับของ → ส่งให้ลูกค้า → บันทึกคำตอบลูกค้า → ใส่ราคา
สี่ก้าวท้ายไม่มีความหมายกับเอกสาร (ไม่มีลูกค้าในสาย ไม่มีราคา) และก้าวสุดท้ายจะ ตอบ 400 — "รายการนี้ยังไม่ผูกกลิ่นหรือสูตรในทะเบียน"
⇒ ใครเดินตามปุ่มไปจนสุด แถวจะค้างที่ "รอใส่ราคา" ถาวร ปิดใบไม่ได้ — บั๊กรูปแบบเดียวกับที่พัฒนาสูตรเคยเจอ ก่อนแก้ที่ ม-54

ค · สองที่นิยาม "มาแล้ว" คนละแบบ

ในใบคำร้องใช้ answerStatus · บนหน้าดีลใช้ readyAt (ดู §04) ⇒ จอเดียวกันเรื่องเดียวกัน ตอบคนละคำตอบ
ทางที่แบบนี้เสนอ — ตัด 4 ก้าวท้ายออกสำหรับแถวเอกสาร แล้วให้สายจบที่ 3 ก้าว
1 รอรับเรื่อง
2 กำลังทำ
3 ส่งเอกสารแล้ว
จบ · ได้รับแล้ว
จบ · ให้ไม่ได้
  • ฝ่าย แนบไฟล์ที่แถว → กด ส่งของ (มีอยู่แล้ว)
  • ผู้ขอ กด ได้รับแล้ว ⇒ เขียน answerStatus = 'done' — ปุ่มนี้แทน "รับของ" ที่มีอยู่แล้ว ไม่ใช่ก้าวใหม่ แค่เปลี่ยนว่ามันเขียนช่องไหน
  • ฝ่าย กด ให้ไม่ได้ + เหตุผล ⇒ answerStatus = 'declined' + declineReason (constraint answer_evidence บังคับคู่นี้อยู่แล้ว)
  • หน้าดีลเปลี่ยนไปอ่าน เกณฑ์เดียวกับใบคำร้อง ⇒ ข้อ ค หายไปเอง
⚠️ ไม่เพิ่มตารางหรือ endpoint ใหม่ — ใช้ hopPatch เดิม เพิ่มสาขา ตาม lineKind ที่เดียว ซึ่งเป็นที่ที่กติกาของก้าวอยู่แล้ว

08ช่องว่างที่แบบนี้เสนอให้ปิด

#ช่องว่างอาการที่ผู้ใช้เจอเสนอ
1 ไม่มีปุ่ม "ได้รับแล้ว" / "ให้ไม่ได้" แถบตัวเลขบนสุดของใบ — ซึ่งเป็นเหตุผลทั้งหมดที่หัวข้อนี้มีบรรทัด — โชว์ มาแล้ว 0 ตลอดไป สองก้าวจบตาม §07 · เขียน answerStatus ผ่าน hopPatch เดิม
2 ก้าวของสายพัฒนาโผล่ในแถวเอกสาร เดินตามปุ่มไปจนสุดแล้ว ค้างที่ "รอใส่ราคา" ถาวร ปิดใบไม่ได้ · ก้าวสุดท้ายตอบ 400 HOP_AT_STAGE แยกตาม lineKind — เอกสารจบที่ 3 ก้าว
3 "มาแล้ว" นิยามคนละแบบสองที่ หน้าดีลบอกว่ามาแล้ว ในใบคำร้องยังบอกว่ารอ — ทั้งคู่ "ถูก" ในตัวเอง ให้ documents/all อ่านเกณฑ์เดียวกับ documentBoard
4 ไม่บังคับวันกำหนดส่ง ใบขอเอกสารที่ดองไว้ ไม่มีวันขึ้นเป็น "เลยกำหนด" บนภาพรวมของฝ่าย ไม่ว่าจะนานแค่ไหน ตัดสินว่าจะบังคับเหมือนพัฒนากลิ่น/สูตร (ม-55) หรือยอมรับว่าหัวข้อนี้ไม่เข้าตัวเลขงานช้า
5 ยังอ้างใบเสนอราคา / ล็อตการผลิตไม่ได้ ของจริง IFRA/COA ผูกกับ ล็อต — ตอนนี้พิมพ์ลงช่องรายละเอียดเป็นข้อความเปล่า ยังไม่ทำ โดยตั้งใจ — ไม่มีที่เก็บทั้งสองอย่าง · ห้ามเดาโครงสร้างล่วงหน้า
ข้อ 5 เป็นมติเดิมที่ยังไม่เปลี่ยน — ผู้ใช้บอกไว้ว่า "เก็บไว้ทีหลังก็ได้" · เพิ่มชนิดเอกสารที่ผู้ใช้ไม่ได้พูดถึงเองตอนนี้ = เดาแทนเขา
