# ยืนยันคำสั่งซื้อย้ายจาก "ปิด Won" มาที่ "ใบสั่งขาย"

สถานะ: **รอตรวจ** — โค้ดครบ เทสต์ผ่าน · **ยังไม่รัน migration 0284/0285 บนฐานจริง** · ยังไม่ UAT
เจ้าของงาน: บริหารงานขาย (SA/AE)

> **คำสั่งตั้งต้นจากผู้ใช้ 2026-08-24:** *"การ won QT ขอเปลี่ยนเป็นแค่ modal แจ้งเพื่อยืนยันได้มั้ย
> ส่วนขั้นการใส่คอนเฟิร์ม เอาไปอยู่ตอนสร้าง SO เป็นฟอร์มหน้าสร้าง คล้าย ๆ QT ซึ่งจะมีการแสดง
> ข้อมูลที่เกี่ยวข้อง และแก้ไขในส่วนที่แก้ไขได้ และเพิ่มเติม (การชำระ ที่มีอยู่แล้ว) ก็เอาการยืนยัน
> รวมเป็นที่เดียว เพราะการคอนเฟิร์มมันแทบที่คืองวดแรกอยู่แล้ว"*

## ปัญหาของเดิม

ปิด Won บังคับกรอก 5 อย่าง (ประเภทเอกสาร · วันที่ · เลขที่ PO · ไฟล์แนบ ≥1 · กำหนดชำระ)
ทั้งที่การตัดสินใจ ณ จังหวะนั้นมีอย่างเดียวคือ **"ดีลนี้ปิดได้แล้ว"**

หลักฐานชุดนั้นถูกใช้จริงที่ **ใบสั่งขาย** ทั้งหมด:

| ค่าที่กรอกตอนปิด Won | ไหลไปไหน |
|---|---|
| `wonDocNo` | เอกสารอ้างอิงของใบสั่งขาย (mig 0246) |
| `wonAttachments` + `wonDocType = payment_slip` | หลักฐานงวดแรกตอน freeze (mig 0245/0259) |
| `wonPaymentDueDate` | `paymentDueDate` บนหัวใบ — ซึ่งมติ 2026-08-18 ย้ายไปอยู่ที่งวดแล้ว |
| `wonDocDate` | วันที่บนหัวใบสั่งขาย |

⇒ เป็นการกรอกก่อนถึงเวลาที่ต้องใช้หนึ่งขั้นเสมอ และผู้ใช้พูดถูกว่า "คอนเฟิร์มแทบที่คืองวดแรก"

## กติกาใหม่

**ปิด Won = โมดัลยืนยัน** — บอกผลลัพธ์ให้ครบ (กติกาเดียวกับ `approvalPrompt`) แล้วจบในปุ่มเดียว
คำถามเดียวที่ยังถามคือ **โครงการ** เพราะ #1385 ย้ายด่าน "ต้องมีโครงการ" มาไว้ที่นี่ที่เดียว
⇒ ดีลลอยเลือกโครงการได้ในโมดัลเลย ไม่ต้องออกไปหน้าดีลก่อนแล้วเดินกลับมา

**สร้างใบสั่งขาย = ฟอร์มเต็มหน้า** `/sa/sales-orders/new?quotationId=…`

- ข้อมูลจาก QT อ่านอย่างเดียว (ลูกค้า · ที่อยู่ · รายการ · ยอด)
- แก้ได้: เอกสารอ้างอิง · หมายเหตุ
- การ์ด **ยืนยันคำสั่งซื้อ**: ชนิดเอกสาร (สลิป / PO / เอกสารยืนยัน) · เลขที่ · วันที่ · ไฟล์แนบ
- การ์ด **การชำระ**: กำหนดชำระรายงวด + สวิตช์ "ลูกค้าจ่ายงวดที่ 1 มาแล้ว" (วันที่ + สลิป)
- ปุ่มระดับใบอยู่ใน **การ์ดจัดการเอกสาร** บนรางขวา เหมือนทุกเอกสารในระบบ

**ด่านเอกสารยืนยันอยู่ที่ "ยื่นอนุมัติ" ไม่ใช่ตอนสร้างใบ** — AE ที่ยังรอ PO จากลูกค้าต้องตั้ง
ใบร่างไว้ก่อนได้ แต่จะส่งให้คนอื่นอนุมัติโดยไม่มีหลักฐานจากลูกค้าไม่ได้

## กับดักที่เสียเวลาไปแล้ว — อย่าเดินซ้ำ

1. **เลขที่ใบสั่งขายใช้ซ้ำไม่ได้** (mig 0241) ⇒ ห้ามสร้างใบเปล่ารอไว้แล้วค่อยเติมข้อมูล
   ฟอร์มจึงถือทุกอย่างไว้ในเครื่องแล้วยิงคำขอเดียว · ไฟล์ที่แนบต้องอัปได้ตั้งแต่ยังไม่มี `orderId`
   ⇒ พักไว้ใต้โฟลเดอร์ของ **ใบเสนอราคาต้นทาง** (`sales_order_confirmation` ใน `privateEvidence`)
2. **งวดร่างต้องเป็น `pending` เสมอ** (CHECK `sales_order_installments_draft_pending` · 0259)
   ⇒ เงินงวดแรกจากฟอร์มลงเป็น `paidOn` + `evidence` บนแถว pending (= `installmentPrepaid`)
   แล้ว `freezeInstallments` เลื่อนเป็น `reported` ตอนใบอนุมัติ · **ห้ามเขียน `status` จากฟอร์ม**
3. **ใบเก่าอ่านสองบ้าน** — ใบที่ออกก่อน 0285 ไม่มี `confirm*` หลักฐานอยู่ที่ `quotations.won*`
   ทุกที่ที่โชว์เอกสารยืนยันต้องผ่าน `orderConfirmationOf(order, quotation)` ไม่งั้นใบเก่าทั้งกอง
   ขึ้นว่า "ไม่มีเอกสาร" ทั้งที่แนบไว้ครบ (และจะยื่นอนุมัติไม่ได้ทั้งที่เคยยื่นได้)
4. **ผูกโครงการ + ปิด Won ต้องอยู่ในคำขอเดียว** — ยิงสองครั้งแล้วอันที่สองล้ม = ดีลผูกโครงการ
   ไปแล้วโดยยังไม่ Won ซึ่งไม่มีใครสั่งให้เกิด (นี่คือเหตุผลที่ยกเนื้อใน `link-project` ออกเป็น lib)
5. **`accept_quotation_atomic` ยังรับ `p_evidence` อยู่** — ลายเซ็นไม่เปลี่ยนเพื่อให้ deploy สลับ
   ลำดับกันได้ · route ส่ง `{}` เสมอ
