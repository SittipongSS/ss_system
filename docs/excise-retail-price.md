# ภาษีสรรพสามิต — ราคาขายปลีกคือฐานของทุกอย่าง

> สถานะ: **รอตรวจ** · ตรวจกับโค้ดเมื่อ 2026-10-26 (ทางใบยื่นจาก SO + ตัวตัดสิน "ยกเว้น") · ยืนยันสูตรกับผู้ใช้ 2026-08-16

## สูตร (ยืนยันแล้ว)

```
ราคาขายปลีก (รวม VAT)      107
  ถอด VAT ÷ 1.07           100      ← ฐานภาษี
  สรรพสามิต 8%               8.00
  ท้องถิ่น 10% ของสรรพสามิต   0.80
  ─────────────────────────────
  ยอดที่ยื่นสรรพสามิต         8.80    = 8.8% ของฐาน
  เก็บจากลูกค้า × 1.07        9.42    (บวก VAT 7%)
```

⚠️ **เลข 8.8% ไม่ปรากฏในโค้ด** — มันเป็นผลของ `0.08` กับ `× 0.1` ที่เขียนคนละบรรทัด
ใครได้รับแจ้งว่า "อัตราเปลี่ยนเป็น 9%" แล้วแก้ `0.08` → `0.09` จะได้ **9.9% ไม่ใช่ 9%**

ที่เขียนสูตรไว้: `app/api/products/route.js` · `app/api/products/[id]/route.js`
ตัวคิดยอดบนใบยื่น: [`lib/tax/exciseBilling.js`](../webapp/src/lib/tax/exciseBilling.js)

## ไม่มีราคาขายปลีก = ภาษี 0

🐞 **พบตอนตรวจระบบ 2026-08-16:** สินค้าในหมวดที่ต้องเสียภาษี **17 จาก 94 ตัว** ไม่มี
`retailPriceIncVat` ⇒ `exciseTax` = 0 · ทั้งหมดอนุมัติแล้วและใช้งานอยู่ ⇒ ขายเมื่อไร
**ยื่นภาษีขาดโดยไม่มีอะไรฟ้อง**

### ด่านอยู่ที่ "ยื่นขึ้นทะเบียน" ไม่ใช่ตอนสร้างสินค้า

**ราคาขายปลีกกรอกตั้งแต่ตอนเปิดสินค้าไม่ได้ — มันมาทีหลัง** (มติผู้ใช้ 2026-08-16)
บังคับตอนสร้าง/อนุมัติสินค้า = บล็อกงานด้วยข้อมูลที่ยังไม่มีอยู่จริง

จุดที่ถูกคือ **ตอนยื่นขึ้นทะเบียน** (`draft → pending_legal`) เพราะทะเบียนคือใบที่
ประกาศราคาขายปลีกต่อสรรพสามิต — ไม่มีราคา = ยื่นไม่ได้อยู่แล้วโดยธรรมชาติของเอกสาร
และเมื่อทะเบียนผ่าน ราคาก็มีครบก่อนถึงขั้นขาย/ยื่นชำระเสมอ

ด่านอยู่ใน [`lib/tax/requirements.js`](../webapp/src/lib/tax/requirements.js) ซึ่งเป็น
ตัวเดียวกับที่ checklist บนจอและ submit-gate ฝั่ง server ใช้ ⇒ ปุ่มขึ้นเหตุผลตรงกับที่ถูกบล็อกจริง

⚠️ ทะเบียนที่ฝ่ายกฎหมายยกเว้นภาษีไว้ (`isExciseTaxable === false`) ไม่ต้องมีราคา —
ภาษี 0 เพราะได้รับยกเว้นจริง ไม่ใช่เพราะข้อมูลขาด

### 🐞 ทางใบยื่นจาก SO ข้ามด่านนี้ (ตรวจระบบ 2026-10-26)

ประโยค "เมื่อทะเบียนผ่าน ราคาก็มีครบก่อนถึงขั้นยื่นชำระเสมอ" **ไม่จริงกับใบยื่นที่สร้างจาก SO** — ทางนั้น
ไม่บังคับทะเบียน (รายการที่ยังไม่มีทะเบียนเป็นแค่คำเตือน) ⇒ สินค้าไม่มีราคาก็ได้บรรทัดภาษี ฿0 ลงใบเงียบ ๆ
ของจริงวันตรวจ: SO อนุมัติแล้ว 49 ใบมีสินค้าสรรพสามิต · 22 ใบมีบรรทัดแบบนี้ · **21 ใบเป็น ฿0 ทั้งใบ**

ซ้ำชั้นที่สอง: ทุกจอถือว่า `totalTax === 0` = **ใบยกเว้นภาษี** ⇒ ใบที่ยื่นขาดทั้งใบเดินทางลัดของใบยกเว้น —
ไม่ต้องกรอกเลขใบเสร็จของ S&S · ข้ามขั้น "กำลังยื่น" · ปิดงาน "ชำระแล้ว" โดยไม่มีใบเสร็จสรรพสามิต · ป้ายเขียนว่า "ยกเว้นภาษี"

สิ่งที่แก้ (ยังเป็นการ **เตือน** ไม่บล็อก — จะบล็อกการสร้างใบต้องได้มติก่อน):

| จุด | ทำอะไร |
|---|---|
| `resolveSoFiling` ([`lib/excise/soFiling.js`](../webapp/src/lib/excise/soFiling.js)) | บรรทัดที่อัตราปัดแล้วเป็น 0 ได้ `taxBaseMissing` + คำเตือน `missing_tax_base` (บอกเหตุ: ไม่มีราคา / มีราคาแต่อัตราค้าง 0) |
| โมดัล "สร้างใบยื่นจาก Sale Order" | ป้ายรายบรรทัด + คำเตือนแยกตามชนิด (เดิมนับคำเตือนทั้งก้อนเป็น "ยังไม่มีทะเบียน") |
| เส้นเดินงานบนหน้า SO | ช่วง "ยื่นชำระสรรพสามิต" ขึ้นกลุ่ม "ไม่มีราคาขายปลีก ภาษี ฿0" พร้อมรหัส FG ก่อนกดสร้าง |
| ตัวตัดสิน "ยกเว้น" | `isExemptFiling` ([`lib/tax/exciseBilling.js`](../webapp/src/lib/tax/exciseBilling.js)) — ยกเว้นเมื่อ **ทุกรายการผูกทะเบียนที่ RA ยกเว้นไว้** และยอดเป็น 0 เท่านั้น · server ประทับ `taxExempt` ให้แถว slim (`stampExemptFlags`) และใบที่ผ่าน `attachRegistrations` |
| ใบยื่นที่มีรายการ ฿0 อยู่แล้ว | หน้ารายละเอียด · โมดัลรับเงิน · โมดัลบันทึกชำระ เตือนจำนวนรายการ (`untaxedFilingItems`) |

🔒 ยาม: `src/lib/tax/exemptFiling.test.mjs` สแกนทั้ง `src/` — โค้ดที่ตัดสินจาก `totalTax === 0` / `(x.totalTax || 0) === 0` ทำเทสต์แดง

### ที่รวมให้เห็น 2 ที่

| ที่ | เห็นอะไร |
|---|---|
| **หน้าภาษี → รายงาน → "ขาดราคาขายปลีก"** | ทั้งกอง พร้อมลูกค้า/ผู้รับผิดชอบ · ส่งออก Excel ไปให้คนเติมได้ |
| **หน้าสินค้า (ฐานข้อมูล)** | แถบเตือนบนใบสินค้าตัวนั้น ว่าภาษีจะคิดออกมา 0 |

### ถ้าเติมราคาทีหลังแล้วใบยื่นเก่ายังเป็น 0?

`PATCH /api/orders/[id]` **คำนวณภาษีใหม่จากสินค้าปัจจุบัน** ทุกครั้งที่แก้รายการ ⇒
เปิดใบยื่นมาบันทึกซ้ำ ตัวเลขอัปเดตเอง ไม่ต้องสร้างใบใหม่

**ใบยื่นจากใบสั่งขาย** (`orders.salesOrderId`) ไม่แก้รายการทีละทะเบียน — ฟอร์มแก้ (`OrderFormModal` โหมดใบจาก SO)
โชว์รายการอ่านอย่างเดียว + ปุ่ม **"คิดภาษีใหม่จากใบสั่งขาย"** ⇒ PATCH `recalcFromSalesOrder` คิดผ่าน resolver ตัวเดียวกับ
ตอนสร้าง ([`lib/excise/soFilingItems.js`](../webapp/src/lib/excise/soFilingItems.js)) — อัตราล่าสุดของสินค้า · จำนวนจากบรรทัด SO ·
บรรทัดที่ยังไม่มีทะเบียนอยู่ครบ (มติ 2026-07-22 ข้อ 4) · ลิงก์ `salesOrderLineId` ติดไป · ยอดเรียกเก็บคิดใหม่
แก้ได้ในสถานะ `FILING_EDITABLE_STATUSES` (ร่าง · รอรับเงิน · ตีกลับ — ชุดเดียวของปุ่มบนจอและด่านใน route)

🐞 ก่อน 2026-10-26 (ข้อ 3 ของผลตรวจ): ฟอร์มกับ route ทิ้งรายการที่ `registrationId` ว่างเงียบ ๆ ⇒ แก้ใบจาก SO แล้วรายการหาย
ยอดหด · ทุกรายการไม่มีทะเบียน = ส่งกลับไม่ได้ · แถวใหม่ทิ้ง `salesOrderLineId` · ลบรายการเดิมก่อนใส่ชุดใหม่ (ใส่พัง = ใบว่าง) ·
ยอดเรียกเก็บไม่คิดใหม่ ⇒ ตอนนี้ route ปฏิเสธ `items` ของใบจาก SO · ใส่ชุดใหม่ก่อนแล้วค่อยลบชุดเดิม ·
ใบยื่นมือ (ไม่มี `salesOrderId`) ยังแก้ด้วยการเลือกทะเบียนตามเดิม
