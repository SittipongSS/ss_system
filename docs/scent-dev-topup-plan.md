# ลูกค้าซื้อพัฒนากลิ่นเพิ่ม — ผูก SO ใบใหม่กับคำร้องเดิม (ทาง C)

> สถานะ: **กำลังดำเนินการ** — PR-1 (ฐาน + ตัวตัดสิน + การนับ) แบรนช์ `claude/scent-topup-p1` (#2051) · **mig 0436 รันบน prod แล้ว 13/11** · PR-2–5 รอดำเนินการ

**บันทึกมติ:** ม-163 ใน `docs/requests-rd-decision-log.md` §34

## ที่มา

คำร้องพัฒนากลิ่น (`scent_dev`) ผูกกับ SO หนึ่งใบ (ม-37) และนับจำนวนกลิ่นจากบรรทัดออกแบบกลิ่นของใบนั้น (ม-38)
ถ้าลูกค้าอยากได้เพิ่มต้องจ่ายเพิ่ม ซึ่งเดินลูป DL > QT > SO ใหม่ตามปกติ แต่ SO ใบใหม่ไม่มีทางผูกกลับไปหาคำร้องเดิมเลย
ทั้งใบที่ยังเปิดและใบที่ปิดไปแล้ว

ของที่ลูกค้าซื้อเพิ่มมีสองชนิด:
1. **กลิ่นใหม่** ต้องมีบรีฟใหม่
2. **งานต่อจากของที่อยู่ในใบแล้ว** คือแก้กลิ่นที่ส่งไปแล้ว หรือเก็บ direction ที่เคยบอกว่าไม่เอา

ทาง C ใช้คำถามเดียวตัดสิน: **งานนี้ต้องมีบรีฟใหม่ไหม**
- ไม่ต้อง และใบเดิมยังไม่ปิด: **แนบ** SO เข้าใบเดิม
- ต้อง หรือใบเดิมปิดแล้ว: **เปิดใบใหม่** ที่ชี้กลับไปใบเดิม

## กติกา

### 1. เจ้าของ SO และสาย Rev.

- SO ใบหนึ่งมีเจ้าของได้คำร้องเดียว: เป็น SO หลักของคำร้องพัฒนากลิ่นที่ไม่ถูกยกเลิก หรือเป็น SO แนบ อย่างใดอย่างหนึ่ง
- **เจ้าของเดินตามสาย Rev.** — SO ที่ `revisedFromId` ย้อนไปถึงใบที่มีเจ้าของ ถือว่าเจ้าของเดียวกัน
  (ไม่ขึ้นคิว เปิดคำร้องซ้ำไม่ได้ แนบที่อื่นไม่ได้)
- **การนับอ่านจากใบ Rev. ล่าสุดที่อนุมัติ** — เดินตาม `supersededById` ไปข้างหน้า ทั้ง SO หลักและ SO แนบ
  (ปิดช่องเดิมที่คำร้องอ่านบรรทัดจากใบที่ถูก Rev. ไปแล้ว)
- ใบที่ยกเลิก (`cancelled`) หรือถูกเพิกถอนอนุมัติ ไม่นับจำนวน

### 2. แนบ SO เข้าคำร้องเดิม

**ทางเข้า:** ปุ่ม "แนบ SO ที่ซื้อเพิ่ม" ในหน้าคำร้อง และปุ่ม "แนบเข้าคำร้องเดิม" ในคิว/หน้า SO

**แนบได้เมื่อครบทุกข้อ** (ตรวจที่ server · ไม่ผ่านคืนข้อความไทยบอกทางออก):
1. คำร้องเป็นพัฒนากลิ่น และยังไม่ปิด/ไม่ยกเลิก
2. SO อนุมัติแล้ว มีบรรทัดออกแบบหรือแก้กลิ่น และอ่านจำนวนได้ (จำนวนเต็มบวก)
3. ลูกค้าของ SO กับของคำร้องมีเลขผู้เสียภาษีเดียวกัน (`customerTaxSiblings`)
4. SO ยังไม่มีเจ้าของ (รวมสาย Rev.)
5. คนกดเป็นผู้ขอของคำร้อง · เจ้าของดีลของ SO · หัวหน้าฝ่ายขายในขอบเขต · หรือแอดมิน

**โมดัลยืนยันบอกผลก่อนกด** (กติกา #1223): "จำนวนกลิ่น 2 เป็น 3 · รอบแก้ที่ซื้อ 0 เป็น 1"

**หลังแนบ:** ลงเธรดคำร้อง + แจ้งกระดิ่ง RD ที่ถือใบ · SO ที่ถูกปัดออกไว้ถูกล้างการปัดออกให้เอง (การแนบชนะการปัด)

**ถอดออก:** คนกลุ่มเดียวกัน เฉพาะใบที่ยังไม่ปิด · บล็อกเมื่อถอดแล้วคอนเฟิร์มเกินจำนวนกลิ่นโดยไม่มีแถมรองรับ
("ถอดแล้วคอนเฟิร์มเกินที่จ่าย — ระบุแถมหรือแนบใบอื่นก่อน") · ลงเธรดเหมือนตอนแนบ

### 3. เปิดใบใหม่ต่อจากใบเดิม

- ฟอร์มเปิดคำร้องพัฒนากลิ่นมีช่องไม่บังคับ **"ต่อจากคำร้อง"** เลือกได้จากคำร้องพัฒนากลิ่นของลูกค้าเดียวกัน (ทุกสถานะยกเว้นยกเลิก ใหม่สุดอยู่บน)
- บรีฟแต่ละก้อนมีช่อง **"แก้จากกลิ่น"** (ไม่บังคับ) · กลิ่นที่ถูกคอนเฟิร์มในใบที่ต่อจากขึ้นก่อน ตามด้วยกลิ่นอื่นของลูกค้า
  · **บังคับเมื่อ SO หลักขายแค่ 03-010** (แก้กลิ่นล้วนต้องรู้ว่าแก้ตัวไหน)
- RD ส่งกลิ่นจากบรีฟนั้น ช่อง "แก้มาจากกลิ่น" เติมค่าจากบรีฟให้ (RD เปลี่ยนได้เหมือนเดิม)
- หัวคำร้องใบใหม่ขึ้น "ต่อจาก RQ-…" · ใบเดิมขึ้น "มีคำร้องต่อ: RQ-…"
- ใบที่ปิดแล้ว **ไม่เปิดกลับ** · PDR ที่ออกไปแล้วไม่แตะ

### 4. คอนเฟิร์มเกินจำนวนที่จ่าย (มติ 2)

- ตอนบันทึก "ลูกค้าคอนเฟิร์ม" แถวพัฒนากลิ่น server นับ **จำนวนคอนเฟิร์มหลังบันทึก** เทียบ **จำนวนกลิ่น**
  (ถ้าอ่านจำนวนกลิ่นไม่ได้ ไม่มีด่าน เหมือนวันนี้)
- เกินและไม่ได้ส่งเหตุผลแถมมา ⇒ ตอบ `409 { code: 'over_paid' }` ข้อความ
  "เกินจำนวนที่ลูกค้าจ่าย (คอนเฟิร์ม 3 จาก 2) — แนบ SO ที่ซื้อเพิ่ม หรือบันทึกเป็นของแถมพร้อมเหตุผล"
- จอเปิดโมดัลสองทาง: **แนบ SO ที่ซื้อเพิ่ม** (เปิดตัวเลือกแนบ แล้วกลับมาคอนเฟิร์มต่อ) หรือ **ของแถม** (กรอกเหตุผล แล้วคอนเฟิร์ม)
- เหตุผลแถมเก็บบนแถว · ถอดคอนเฟิร์มแถวนั้น (ถ้ามีทางถอด) = ล้างแถมด้วย
- **แถวที่เกินอยู่ก่อนแล้ว** (3 ใบบน prod) การ์ดกระทบยอดขึ้น "เกิน n ยังไม่ระบุ" พร้อมปุ่ม "ระบุว่าแถม" รายแถว (หรือแนบ SO)
- **ด่านปิดใบเพิ่มหนึ่งข้อ:** เกินที่ยังไม่ระบุ ปิดไม่ได้ ("คอนเฟิร์มเกินที่จ่าย n ยังไม่ระบุ — แนบ SO หรือระบุว่าแถมก่อนปิด")
  · ใบที่ปิดไปแล้ว (SB-26080013) ไม่แตะ
- ข้อความกระทบยอดใหม่: "ลูกค้าคอนเฟิร์ม 3 จาก 2 — แถม 1" (ครบ) · "… — เกิน 1 ยังไม่ระบุ" (เตือน)

### 5. เปลี่ยน "ไม่เอา" เป็นคอนเฟิร์ม

ของชนิดที่ 2 ที่พบจริง (ทิพย์นที AFTER YOU LEAVE) ต้องการก้าวนี้ และวันนี้ไม่มี

- ก้าวใหม่ `reconfirm` เฉพาะแถวพัฒนากลิ่นที่ `outcome = 'rejected'` ในใบที่ยังไม่ปิด · ฝั่งผู้ขอ (เจ้าของก้าวเดียวกับ `outcome`)
- เขียน `outcome = 'confirmed'` · `confirmedQty = 1` · ล้าง `answerStatus = 'declined'` และ `declineReason` ให้แถวกลับไปรอใส่ราคา
  · ผลข้างเคียงทะเบียนเหมือนคอนเฟิร์มปกติ (กลิ่น/สูตร `developing` เป็น `active`)
- ผ่านด่านคอนเฟิร์มเกินข้อ 4 ตัวเดียวกัน · ลงเธรด "เปลี่ยนจากไม่เอาเป็นคอนเฟิร์ม" พร้อมเหตุผล (บังคับ)
- ⚠️ ถ้ากลิ่นถูกเก็บเข้ากรุไปแล้ว ไม่ปลุกเอง (กติกาเดียวกับคอนเฟิร์มปกติ) · บอกในข้อความผล

### 6. คิว SO รอคำร้อง (มติ 5–6)

- **ที่อยู่:** การ์ด "SO ออกแบบกลิ่นรอเปิดคำร้อง" ส่วนบนของ `/requests` (คู่กับการ์ด "เริ่มที่นี่")
  · ป้ายตัวเลขเมนู "คำร้อง" บวกจำนวน **ของตัวเอง** (เจ้าของดีล) ด้วยตัวกรองตัวเดียวกับการ์ด
  · หัวหน้าฝ่ายขายมีสวิตช์ "ของฉัน / ทั้งหมด" (ทั้งหมด = ในขอบเขต `inSalesDocScope`) · ป้ายเมนูของหัวหน้านับเฉพาะดีลของตัวเอง
- **แถว:** รหัส SO บน ชื่อลูกค้าล่าง · สิ่งที่ขาย (เช่น "03-002 ×1 · 03-010 ×1") · วันอนุมัติ · ค้างกี่วัน · เจ้าของดีล
- **สามปุ่ม** (กดไม่ได้ = ยังโชว์ บอกเหตุตอนกด):
  - **เปิดคำร้องใหม่** ไป `/requests/new?kind=scent_dev&salesOrderId=…` · ถ้าลูกค้ามีคำร้องเดิม เติม "ต่อจากคำร้อง" เป็นใบล่าสุดให้ (แก้ได้)
  - **แนบเข้าคำร้องเดิม** เลือกจากคำร้องที่ยังไม่ปิดของลูกค้าเดียวกัน · ไม่มีใบให้แนบ = บอกเหตุ "ลูกค้านี้ไม่มีคำร้องที่ยังไม่ปิด — เปิดคำร้องใหม่"
  - **ไม่ต้องมีคำร้อง** โมดัลกรอกเหตุผล (บังคับ) · บันทึกคนปัด/เวลา
- แท็บ "ปัดออกแล้ว" โชว์เหตุผล คน เวลา · **คืนเข้าคิว** ได้โดยคนที่ปัดเอง หัวหน้าฝ่ายขาย หรือแอดมิน
- หน้า SO รายใบ: ที่เดิมที่มีปุ่ม "เปิดคำร้อง" กลายเป็นสามปุ่มชุดเดียวกัน · SO ที่มีเจ้าของแล้วขึ้นลิงก์คำร้อง พร้อมป้าย "SO หลัก" หรือ "แนบ"

### 7. ยกเลิก/ปิดคำร้อง

- **ยกเลิกคำร้อง** ปลด SO แนบทุกใบกลับเข้าคิว (ลบแถวลิงก์ · ลงเธรด) · SO หลักว่างอยู่แล้วตามดัชนีเดิม
- **ปิดคำร้อง** SO แนบอยู่ต่อเป็นประวัติ · แนบเพิ่มไม่ได้แล้ว (ต้องเปิดใบใหม่ต่อจาก)

### 8. สิ่งที่ไม่เปลี่ยน

- ลูป DL > QT > SO เดิม · ม-37 (SO หลักคือใบที่เปิดคำร้อง) · ม-38 วิธีนับของ SO หลัก · ม-39 สายพันธุ์กลิ่น
- PDR ที่ออกไปแล้ว · **PDR 1.12 ยังอ่านจาก SO หลักอย่างเดียว** (เอกสารบรีฟตั้งต้น) — จำนวนรวมหลังแนบอยู่ที่การ์ดกระทบยอดบนจอ
- ใบที่ปิดแล้วไม่เปิดกลับ · รอบแก้ในใบยังไม่จำกัด (มติ 3)

## นอกขอบเขต

- จำกัดรอบแก้ฟรี (มติ 3 ยังไม่จำกัด)
- ปุ่ม "ลูกค้าขอเพิ่ม" ในคำร้องที่สร้างดีลพร้อมลิงก์ตั้งแต่ต้นลูป (งวดถัดไปถ้าเจ้าของต้องการ)
- แจ้งเตือนอัตโนมัติตอน SO อนุมัติแล้วไม่มีคำร้อง (ป้ายเมนูพอไปก่อน)
- ใช้ `sales_deals."parentDealId"` (mig 0072 ของดีลลูก FC) ทำลิงก์ — ไม่ใช้ ความหมายคนละเรื่อง
- PDR พิมพ์ "ต่อจากคำร้อง" หรือรายการ SO แนบ

## ความเสี่ยง

- **ด่านปิดใบใหม่กระทบใบที่เปิดอยู่** — 2 ใบที่เกิน ปิดไม่ได้จนกว่าจะระบุ · แจ้งผู้ขอก่อนขึ้น
- **สาย Rev. เพิ่มคิวรี** findRequest และลิสต์ SO อ่านเพิ่ม · ใช้ `fetchInChunks` (PostgREST 16 KB) และนับ `check:rowcap` ให้ตารางใหม่
- **trigger สองทิศ** ต้องเทสต์ใน SQL Editor ด้วยข้อมูลจริงก่อน merge (เปิดคำร้องปกติต้องยังผ่าน)
- **ก้าว `reconfirm` ยุ่งกับทะเบียน** — กลิ่นที่ถูกเก็บเข้ากรุไม่ปลุก · สูตรที่เกิดพร้อมกลิ่นเดินคู่ · ต้องมีเทสต์ทั้งสองสาย
