## ปัญหาที่หน้านี้มาปิด

ชีตของทีมมี **102 จุดที่ลูกค้าจ่ายเงินแล้วแต่ไม่มีคิวบริการ** งานพวกนั้นไม่ได้หายไป —
มันไม่เคยเดินมาถึงฝ่าย TS เลย เพราะไม่มีหน้าไหนพาใบสั่งขายมาให้
(`business-line-level-and-handoff.md:157`)

## สิ่งที่ตัดสินไปแล้ว

| ข้อ | มติ | ทำไม |
|---|---|---|
| หน่วยของคิว | **ใบสั่งขาย** (นับเป็นบรรทัด) | คนทำงานเปิดทีละใบ แต่ของที่ต้องผูกคือบรรทัด |
| ใบที่รับได้ | `status='approved'` และไม่ถูก Rev. ทับ | ใบที่ยังไม่อนุมัติมียอด/ของที่ขยับได้ ⇒ snapshot ที่ก๊อปไปจะเป็นของปลอม |
| สายธุรกิจ | ถาม `projects.line` ก่อน แล้วค่อย `sales_deals.line` | โครงการเป็นเจ้าของค่า · ดีลถือสำเนาไว้ตอนยังไม่มีโครงการ |
| ตอบไม่ได้ว่าสายอะไร | ขึ้น**ถังของมันเอง** เหนือคิว ไม่เดา ไม่เงียบ | เดาเมื่อไร ใบสายสินค้าไหลเข้าคิวบริการ หรือใบบริการหายเงียบ แย่พอกันทั้งคู่ |
| 1 บรรทัด = 1 รอบขาย | `salesOrderLineId` UNIQUE ที่ DB | จำนวนโซนที่ขายนับจากจำนวนบรรทัด |
| ต่อสัญญา | ใบใหม่ผูก**โซนเดิม** ไม่สร้างโซนใหม่ | ประวัติและยอดการใช้ของโซนเดินต่อไม่ขาดตอน |
| "รอบยังมีผลไหม" | คำนวณจากใบแม่ที่ `lib/service/terms.js` ที่เดียว | term ไม่มีคอลัมน์ status โดยเจตนา (mig 0297:83) · โรคเดียวกับ "live visit" ที่เคยมี 5 นิยาม |
| มาตรฐานต่อเดือน (ml) | **เสนอให้กดรับ ไม่เขียนเอง** และเสนอเฉพาะบรรทัดที่ขายเป็นแพ็ค | ไม่มีสูตรที่เป็นทางการ · หลักฐานเดียวคือชีตที่ลงตัว 10/13 แถวที่ 1 แพ็ค = 1 ลิตร/เดือน · บรรทัด "240 กิโลกรัม" ที่ขึ้นข้อเสนอ "240,000 ml" คือข้อเสนอที่ผิดกว่าถูก |
| หน้านี้สร้างงานไม่ได้ | ไม่มีปุ่ม "สร้างใหม่" เลยโดยตั้งใจ | TS ไม่ใช่ต้นทางของงาน (กติกาเดียวกับที่ถอดปุ่ม + ออกจากหน้าจัดคิวช่าง) |
| ไซต์ในตัว wizard | **เลือกได้อย่างเดียว** · สร้างใหม่เรียกฟอร์มเดิม | ที่อยู่ทางภาษีกับที่อยู่หน้างานเป็นคนละความจริง · ห้ามแก้ทะเบียนลูกค้าจากที่นี่ |

## สามถัง (แท็บ)

| แท็บ | เงื่อนไข | ปลายทาง |
|---|---|---|
| **รอตั้งไซต์/โซน** | ใบ approved สาย SERVICE ที่ยังมีบรรทัดไม่ผูกโซน | wizard 2 จังหวะ → เกิดแถว `service_zone_terms` |
| **รอตั้งรอบ** | โซนที่มีรอบขายมีผล แต่ไซต์ยังไม่มี `service_plans` ที่ active | หน้าไซต์ (ตั้งรอบ) |
| **ครบรอบยังไม่มีนัด** | รอบ active ที่ไม่มีนัด**ที่ยังมีชีวิต**ข้างหน้าเลย | หน้าไซต์ (เติมนัด) |

⚠️ ถังที่สามใช้ `isLiveVisit` ตัวเดียวกับด่านเข้าไซต์ — `visitQueue()` **โยน error ถ้าไม่ส่งมา**
เข้มกว่าด่านจริง = ซ่อนงานที่ทำได้ · หลวมกว่า = ชวนกดแล้วเด้ง

## ของที่ยังไม่ทำ

- **หน้าโซนยังไม่โชว์รอบขาย** — ม็อกออกแบบตารางไว้แล้ว (รอบทุกรอบ รวมที่จบแล้ว) แต่ยังไม่ลงจอ
- ปุ่ม "สร้างสัญญาบริการ" — 🅿 รอต้นฉบับสัญญาจ้างบริการ (`contractTemplates.service = null`)
- `startDate`/`endDate` ของรอบยังไม่มีที่กรอกบนจอ (คอลัมน์พร้อมแล้ว) — รอเฟสสัญญามา sync
- ยังไม่ UAT
