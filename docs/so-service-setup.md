## ทำไม

ใบสั่งขายสายบริการอนุมัติแล้ว **ไม่มีใครรู้ว่าของไปตั้งที่ไหน** — TS ต้องเปิดใบไล่จับคู่บรรทัดกับโซนเอง (วิซาร์ด "ผูกโซน")
ทั้งที่ฝ่ายขายเป็นคนเดียวที่รู้ว่าขายแพ็คเกจไหน ลงไซต์ไหน กี่แพ็คต่อรอบ กี่รอบ ช่วงไหน · บรรทัด "พิมพ์เอง" ไม่มี `fgCode`
⇒ ระบบตอบไม่ได้ว่าเป็นแพ็คเกจบริการหรือค่าขนส่ง · วิซาร์ดของ TS ไม่เคยถูกใช้จริง (term บน prod = 0)

**ของใหม่:** ฝ่ายขายตั้งที่ตารางรายการของใบสั่งขาย → ผู้อนุมัติเห็นครบก่อนกด → อนุมัติ = เปิดรอบขาย (term) ให้ TS
ในทรานแซกชันเดียวกัน · TS เริ่มที่ "รอตั้งรอบ" ตรง ๆ · ใบที่อนุมัติไปแล้ว (~59 ใบ) ฝ่ายขายตั้งย้อนหลังแล้วผู้จัดการฝ่ายขายตรวจ

### ต่างจาก r3/ม็อก — ต้องบอกเจ้าของพร้อม PR

1. **D14** ป้ายเมนู TS นับแค่ "รอตั้งรอบ" (r3 ขอ + "ครบรอบยังไม่มีนัด") — ถังนัดต้องอ่านนัดทั้งระบบทุก 2 นาที เหตุผลเดียวกับที่โค้ดเดิมไม่นับ · แท็บบนหน้ายังโชว์ตัวเลข

3. **D19** ไม่มีปุ่ม "ขอ TS เพิ่มไซต์ที่ติดตั้งแล้ว" — มอบงานข้ามฝ่ายถูกห้าม (`canAssignTask`) ปุ่มจะ 403 ทุกคนที่ไม่ใช่ admin
4. **D24/D27** สถานะ "ติดทะเบียนไซต์ — ขาด n สาขา" ไป PR-B · ตัวห่อ bulk modal ของใบย้อนหลังไป PR-D

### ต่างจากแผนที่พบระหว่างทำ (ตรวจแล้ว ยึดตามโค้ด)

- ข้อความตรวจจำนวนของบรรทัดหน่วย "เดือน" (แผน A.4) เป็น `จำนวนในใบ {qty} เดือน = ระยะเวลา ไม่ได้นับเป็นแพ็ค` — ของเดิม "…ไม่ใช่จำนวนแพ็ค" ทำให้ `check:thaiwrap` ขึ้นเกินเพดาน (ICU ตัด "จำนวนแพ็ค" กลางคำ) · จออ่าน `lineQtyCrossCheck().text` ห้ามพิมพ์ข้อความนี้เอง
- ตัวจัดการ API ตั้งค่างานบริการอยู่ที่ `lib/sales/serviceSetupRoute.js` (route เป็นตัวห่อบาง) — เทสต์เรียกได้โดยไม่ต้องดึง `next/headers`
- PATCH บันทึกสำเร็จแต่โหลดซ้ำไม่ขึ้น = 200 + `warning` (ไม่ใช่ 500 — บันทึกลงไปแล้ว กดซ้ำจะชน stale)
- `fill-coverage` แบ่งช่วงครอบจากงวด **ชุดเดียวกับที่จอเห็น** (`installmentsForScreen`) · ด่าน/การเขียนยังใช้แถวจริงในฐาน
- ส่ง `updatedAt` กลับเป็น `expectedUpdatedAt` **ตามที่ได้มา** — แปลงผ่าน `Date` ของ JS ไมโครวินาทีหาย ทุกการบันทึกจะเป็น stale

### ทะเบียนใบสั่งขาย (`/sa/sales-orders`)

- **คิวรออนุมัติ** (เปลือกงานขาย) รวมแถวที่ `_awaitingMyServiceReview` — บรรทัดหลัก "งานบริการ (ใบเดิม) · SO-…" · บรรทัดรอง
  "ลูกค้า · z โซนใน s ไซต์ · r รอบ/โซน · ไม่นับ Actual · ยื่นโดย ชื่อ dd/mm/yyyy" (ตัวเลขจาก `serviceReview` ของ server) · ปุ่ม "เปิดใบเพื่ออนุมัติ"
  · เปลือกบัญชีไม่มีแถวชนิดนี้ · ไม่ชนกับแถวใบรออนุมัติ (อันนั้น `pending_approval` · อันนี้ `approved`)
- **ชิป "ยังไม่ตั้งงานบริการ n"** — ปุ่มสลับ (`aria-pressed`) ติดท้าย Segmented มุมมองสาย · n = แถว `_serviceSetupPending` ของ **ทุกแถว** (ไม่ใช่หลังกรอง) ·
  ขึ้นเมื่อ n > 0 หรือกำลังเปิด · จำค่าด้วย `useStickyState` · อยู่ใน resetKey ของการแบ่งหน้า · ปุ่มตัวกรองล้างให้ · **ไม่นับ** ในป้ายของปุ่มตัวกรอง
- "รอฉันลงมือ" อ่าน `_waitingOnMe` ตัวเดิม — route ใส่เลนเจ้าของดีล (`serviceBackfillNeeded`) + เลนผู้จัดการให้แล้ว · ป้ายเมนู `salesOrders` นับชุดเดียวกัน (ใบไม่ซ้ำ)

## ฝั่ง TS — ถัง "รอฝ่ายขายตั้งงานบริการ (ใบเดิม)"

- `lib/service/legacySetupQueue.js` (โมดูลใหม่ เพราะต้องใช้ทั้ง `intake.js` และ `serviceSetup.js` — `intake.js`/`serviceOrders.js` ห้าม import `serviceSetup.js` · กฎวงวน import)

- แท็บ `bind` ของ `/service/intake` **ดูอย่างเดียว**: สถานะ ยังไม่เริ่ม / ฝ่ายขายกำลังตั้ง (x/n รายการ) / รอผู้จัดการตรวจ (z โซนใน s ไซต์ · p แพ็ค/รอบ) / ตีกลับ (เหตุผล)
  · ตัวกรองสถานะพร้อมตัวเลข + ค้นหา · ตารางและการ์ด · ลิงก์ "เปิดใบสั่งขาย" · ไม่มีปุ่มทำงาน (TS ไม่ใช่ต้นทางของงาน)
- `POST /api/service/intake/bind` ตอบ 409 "ปิดทางผูกโซนของ TS แล้ว — …" ก่อนอ่านอะไรทั้งสิ้น
- ป้ายเมนู `serviceIntake` = จำนวนแถวถัง "รอตั้งรอบ" (`return plan.length;`)
- ด่านเข้าไซต์: โซนไม่มี term ⇒ SA (`NOT_IN_ORDER_ZONE_REASON` · `NOT_IN_HISTORICAL_ORDER_ZONE_REASON` · `UNSET_SERVICE_ORDER_REASON`) · ไซต์ไม่มีโซน ⇒ TS (`NO_ZONE_SITE_REASON`)
- ลบโซนที่ถูกเลือกในใบ = 409 ชี้ให้ฝ่ายขายถอดโซนออกจากใบหรือปิดใช้งานแทน · บังคับลบโซน/ไซต์บล็อกเมื่อมีการเลือกในใบ · ยกเลิกคำร้องสำรวจไม่ปล่อยโซนที่ถูกเลือกในใบ
