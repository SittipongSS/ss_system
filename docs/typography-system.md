## ตัวพิมพ์คือ Sarabun ตัวเดียวทั้งระบบ

มติผู้ใช้ 2026-08-13 — เปลี่ยนจาก IBM Plex Sans Thai มาเป็น **Sarabun** ทั้งระบบ
รวมเอกสารพิมพ์ เหตุผล: หัวตัวอักษรใหญ่กว่า ช่องในตัวเปิดกว่า อ่านง่ายกว่าในเนื้อความไทย

| ที่ | โหลดอย่างไร | ไฟล์ |
|---|---|---|
| แอป | `next/font/google` → ตัวแปร `--font-app-sans` บน `<html>` | `src/app/layout.js` |
| โทเคน | `--font-sans` · `--font-mono` และ `--font-numeric` **ชี้ตัวเดียวกัน** | `src/app/globals.css` |
| เอกสาร/ใบพิมพ์ | ฝัง woff2 เป็น base64 (`DOCUMENT_FONT_FACE_CSS`) | `src/lib/sales/quotationDocumentFonts.js` |
| หน้าต่างพิมพ์อื่น (Gantt, placeholder) | `PRINT_FONT_STACK` | `src/lib/printTheme.js` |

**น้ำหนักที่โหลดมีแค่ 400 / 500 / 600 / 700** — เขียนค่าอื่น (650 · 750 · 800) เบราว์เซอร์
ปัดทิ้งเงียบ ๆ · `fontWeightScale.test.mjs` ผูก `layout.js` กับโทเคน `--fw-*` ไว้ด้วยกัน
จะเพิ่มชื่อน้ำหนักได้ต่อเมื่อเพิ่มใน `layout.js` ก่อน

### สร้างฟอนต์เอกสารใหม่

```bash
npm run gen:document-fonts
```

ดึงจาก Google Fonts → subset ไทย+ละติน → base64 → เขียนทับ `quotationDocumentFonts.js`
(8 บล็อก = 4 น้ำหนัก × 2 subset · ฟอนต์รวม ~84KB) **คอมมิตผลลัพธ์ไปกับสคริปต์เสมอ**

⚠️ **ฉบับตรึงเก่าไม่เปลี่ยนตาม** — เอกสารที่อนุมัติแล้วฝัง CSS ฟอนต์ไว้ใน snapshot
ตอนตรึง (ADR 0011) จะเป็นฟอนต์เดิมตลอดไป **ซึ่งถูกต้องแล้ว** ฉบับตรึงต้องเล่นซ้ำได้
เหมือนวันที่เซ็น ห้ามแก้ย้อนหลัง

## ความหนา — 4 ค่า มีหน้าที่ชัดเจน

| โทเคน | ค่า | ใช้กับ | **ห้าม** |
|---|---|---|---|
| `--fw-normal` | 400 | เนื้อความ ย่อหน้า คำอธิบาย ค่าปกติในตาราง | — |
| `--fw-medium` | 500 | ค่าที่ต้องเด่นกว่าป้ายของมันเล็กน้อย · เมนูที่ไม่ได้เลือก | ใช้กับย่อหน้ายาว |
| `--fw-semibold` | 600 | หัวการ์ด · เมนูที่เลือกอยู่ · ปุ่มรอง | ใช้แทน bold เพื่อ "เบาลงนิดนึง" |
| `--fw-bold` | 700 | ชื่อหน้า · ตัวเลข KPI · ป้าย · ปุ่มหลัก · หัวคอลัมน์ | ใช้เกิน 2 ระดับในกล่องเดียว |

### กฎ

1. **ในกล่องหนึ่งใช้ได้ไม่เกิน 2 น้ำหนัก** — เกินกว่านั้นสายตาหาลำดับไม่เจอ
2. **ความหนาไม่ใช่เครื่องมือสร้างลำดับหลัก** — ใช้ *ขนาด* กับ *สีข้อความ*
   (`--text` → `--text-2` → `--text-3`) ก่อน แล้วค่อยใช้ความหนาปิดท้าย
3. **ตัวเลขที่ต้องอ่านเทียบกัน = 700 เสมอ** พร้อม `font-variant-numeric: tabular-nums`
4. **ห้ามพึ่งตัวหนาสังเคราะห์** — ขอ 800 แล้วได้ 700 คือบั๊กเงียบ ตรวจด้วย `audit:ui`

## ระยะห่าง

### ความสูงบรรทัด — เลือกตาม *กล่อง* ไม่ใช่ตามขนาดตัวอักษร

| โทเคน | ค่า | ใช้กับ |
|---|---|---|
| `--lh-none` | 0 | กล่องไอคอนล้วน ไม่มีกล่องบรรทัด |
| `--lh-flat` | 1 | ตัวเลขบรรทัดเดียว · ป้ายนับบนไอคอน |
| `--lh-tight` | 1.2 | ตัวเลขใหญ่ · หัวเรื่องสั้นที่คุมความสูงเอง |
| `--lh-thai` | 1.45 | **ขั้นต่ำของกล่องที่ห่อข้อความไทยแน่น ๆ** — ป้าย ชิป แท็บ |
| `--lh-text` | 1.5 | ข้อความทั่วไป (ค่าตั้งต้นของ `body`) |
| `--lh-relaxed` | 1.6 | ย่อหน้ายาวที่ต้องอ่านต่อเนื่อง |

⚠️ **ภาษาไทยมีสระบน/ล่างและวรรณยุกต์ซ้อนสองชั้น** — ต่ำกว่า 1.45 ในกล่องที่มีขอบ
จะเห็นสระบนโดนตัด · นี่คือเหตุผลที่ `--lh-thai` มีอยู่แยกจาก `--lh-tight`

**เกณฑ์ที่แยก "ชิดขอบ" ออกจาก "ขาดหายไป" คือ 1.31em** — หมึกจริงของข้อความไทยสูง
1.31em (วัดในเบราว์เซอร์: 17px ที่ 13px · ขึ้น 12.48 / ลง 4.49) ⇒ กล่องบรรทัดที่แคบ
กว่านั้น **บวกกับ `overflow: hidden` ที่ไหนก็ได้ในสายเดียวกัน = สระถูกตัดทิ้งจริง**

🔴 **ตัวที่ตั้งค่าแคบกับตัวที่ตัด ไม่จำเป็นต้องเป็นตัวเดียวกัน** — เคสจริง 2026-08-14:
พิลผู้ใช้บนแถบระบบ (`.account-menu-identity`) ตั้ง `--lh-tight` ไว้ที่ตัวแม่ ส่วน
`overflow: hidden` อยู่ที่สองบรรทัดลูกซึ่งใส่ไว้ทำ ellipsis ⇒ บรรทัด "ผู้ดูแลระบบ"
(`--fs-2` = 10.5px ⇒ กล่อง 12.6px แต่ต้องการ 13.8px) **สระล่างขาด** ทั้งที่ไม่มีกฎไหน
ผิดเมื่อดูทีละบล็อก · ชื่อภาษาอังกฤษบรรทัดบนไม่เห็นอาการเพราะละตินไม่มีสระล่าง
`lineHeightScale.test.mjs` คุมไว้สองชั้น (บล็อกที่ตัด + ตรึงพิลผู้ใช้ไว้ตรง ๆ)

### ระยะห่างตัวอักษร — มี 3 ค่า ห้ามงอกเพิ่ม

| โทเคน | ค่า | ใช้กับ |
|---|---|---|
| `--ls-heading` | −0.02em | หัวเรื่องใหญ่ (≥ `--fs-12`) ให้ดูแน่น |
| `--ls-tabular` | −0.01em | ตัวเลขคอลัมน์ตรง |
| `--ls-label` | 0.08em | ป้ายตัวเล็กพิมพ์ใหญ่ (eyebrow) |

หน่วยต้องเป็น `em` เท่านั้น (`audit:ui` บังคับ) — `px` ทำให้ระยะเพี้ยนตามขนาดตัวอักษร

### ระยะห่างระหว่างของ — กริด 4px

| กลุ่ม | โทเคน | ใช้กับ |
|---|---|---|
| ในบรรทัดเดียวกัน | `--space-1` 4px · `--space-1-5` 6px · `--space-2` 8px | ไอคอนกับข้อความ · ชิปในแถว |
| ในกล่องเดียวกัน | `--space-2-5` 10px · `--space-3` 12px · `--space-3-5` 14px | ช่องกรอกในฟอร์ม · แถวในการ์ด |
| ขอบกล่อง | `--space-4` 16px · `--space-4-5` 18px · `--space-5` 20px | padding ของการ์ด |
| ระหว่างกล่อง | `--space-6` 24px · `--space-7` 28px | การ์ดต่อการ์ด |
| ระหว่างส่วน | `--space-8` 32px · `--space-9` 40px | ส่วนต่อส่วนในหน้ายาว |

**ครึ่งขั้น (`--space-*-5`) มีไว้แก้กรณีที่ 4px ห่างไป ไม่ใช่ค่าที่หยิบมาใช้เป็นปกติ**

### ความสูงของตัวควบคุม

`--ctl-h` 40px (เดสก์ท็อป) · `--ctl-h-touch` 44px (จอแคบ)
ปุ่ม ช่องกรอก และ select **ทุกตัว** ต้องมาจากสองค่านี้ — ไม่มีค่าที่สาม
(`controlHeight.test.mjs` มีลิสต์ `UNRESOLVED` ที่ต้องว่างเสมอ)

**36px → 40px (มติผู้ใช้ 2026-08-14)** — ผู้ใช้ส่งภาพช่อง "หัวข้อ" มาแล้วขอเพิ่ม
ความสูง "มีปัญหาทั้งระบบ" · วัดที่ 36px: พื้นในกล่อง 34px ตัวอักษรกินหมึกจริง 16.97px
⇒ ที่ว่าง **บน 10.0 / ล่าง 7.0px**
⚠️ **เพดานคือ 40** — สูงกว่านี้ไปชน `--ctl-h-touch` (44px) จนกฎจอสัมผัสไม่เหลือความหมาย

### `--ctl-text-sink` 0.23em — ตัวอักษรไทยต้องกลางที่ตาเห็น

เบราว์เซอร์จัดข้อความกลางกล่องตาม *กล่องฟอนต์* ที่ฟอนต์ประกาศ (Sarabun 13px =
ขึ้น 14px / ลง 3px) แต่ไทยเขียนสระล่างกับขีดล่างเลยเส้นฐานลงไป **4.49px**
(วัดด้วย canvas `actualBoundingBoxDescent`) ⇒ หมึกล้นกล่องฟอนต์ด้านล่าง 1.5px
⇒ **ทุกช่องทั้งระบบตัวอักษรนั่งต่ำกว่ากลาง 1.5px** เห็นชัดสุดกับ `_ ุ ู ญ ฎ ฏ ฤ`

⚠️ เพิ่มความสูงอย่างเดียว **ไม่แก้อาการนี้** — 40px ได้ บน 12 / ล่าง 9 = เบี้ยว 3px
เท่าเดิม แค่มีอากาศมากขึ้น · ต้องหั่นพื้นล่างออกเท่าส่วนที่ล้น (`padding-bottom` เพิ่ม
2× ส่วนที่ล้น ⇒ กล่องบรรทัดถูกจัดกลางใหม่ในพื้นที่ที่เตี้ยลง = ขยับขึ้นครึ่งหนึ่งพอดี)

🔴 **หน่วยเป็น `em`** เพราะส่วนที่ล้นแปรตามขนาดตัวอักษร (1.5px ที่ 13px = 0.115em)
และตัวควบคุมของระบบนี้ใช้ 11.5px – 14px · ตรึงเป็น 3px แล้ววัดจริง: `.btn.sm` กับ
`.chip` ลอยเกิน 1.1px · ช่องค้นหา (14px) ยังต่ำอยู่ 0.4px — `0.23em` แก้ให้เองทุกขนาด

**วิธีใส่ต่างกันตาม padding บนของแต่ละตัว** (มติ 2026-08-14 · วัดหลังแก้ทุกตัวอยู่ใน ±0.7px)

| กลุ่ม | ตัวอย่าง | เขียนว่า |
|---|---|---|
| padding บน = 0 | `.premium-input:not(textarea)` · `.premium-select` · `.ui-select` · `.deal-derived` · `.btn` (ยกเว้น `.btn-icon` / `.ui-pager-page`) · `.topnav-sys-btn` · `.topnav-settings-link` · `.search-glass input` · `.ui-select-search input` | กฎรวมกฎเดียว `padding-bottom: var(--ctl-text-sink)` |
| มี padding บนของตัวเอง + ความสูงตรึง | `.segmented > button` (บน 5px, `height: 26px`) | บวกที่ล่าง: `padding: 5px … var(--space-2)` |
| มี padding บนของตัวเอง + โตตามเนื้อ | `.tab-btn` · `.chip` | แบ่งครึ่ง บน −½ / ล่าง +½ (`calc(… ± var(--ctl-text-sink) / 2)`) หรือยุบบนลงหนึ่งขั้น — ความสูงรวมต้องไม่เปลี่ยน |

⚠️ กล่องครอบที่มี `<input>` เปล่าอยู่ข้างใน (`.search-glass` · `.ui-select-search`)
ต้องใส่ที่ **`input` ข้างใน** ไม่ใช่กล่องครอบ — ช่องข้างในสูงเท่ากล่องบรรทัดพอดี
หมึกของ `_` ล้นขอบล่างของตัว input เอง 0.1px ⇒ บีบที่กล่องครอบก็ยังคลิปขีดล่าง

**ห้ามใส่ให้** `.btn-icon` · กระดิ่ง (`.topnav-global-action` เปล่า) · `.ui-pager-page` ·
`.ui-switch` — สองตัวแรกเป็นไอคอนล้วน ตัวที่สามเป็นเลขล้วน ตัวที่สี่ไม่มีกล่องความสูงคงที่
🔴 ผูกกับตัวพิมพ์ปัจจุบัน — เปลี่ยนฟอนต์ต้องวัด descent ใหม่ (`controlHeight.test.mjs` คุมไว้)

## ตัวเลข

**ตัวเลขตรงคอลัมน์อยู่แล้วโดยกำเนิด** — 0–9 ของ Sarabun กว้าง **550/1000 em เท่ากันหมด**
(วัดในเบราว์เซอร์: ทุกหลัก 55px ที่ขนาด 100px) จึงไม่ต้องมีฟอนต์ mono ตัวที่สอง

- คอลัมน์ตัวเลข/วันที่ที่คนเทียบข้ามแถว ใช้ `className="num"` (ได้ `text-align: right`
  + `tabular-nums` มาให้แล้ว)

  2026-08-09) ⇒ อย่าใช้ `.mono` เพื่อหวังให้ตัวเลขตรงคอลัมน์
- จำนวนเงิน ปริมาณ เปอร์เซ็นต์ ผ่าน formatter กลางใน `lib/format.js` เสมอ

## เช็กลิสต์ก่อนส่งงานที่แตะตัวพิมพ์

- [ ] ไม่มี `font-size` / `font-weight` / `font-family` เป็นค่าดิบ (`npm run audit:ui` = 0)
- [ ] ในกล่องเดียวใช้ความหนาไม่เกิน 2 ระดับ
- [ ] กล่องที่ห่อข้อความไทยมี `line-height` ≥ `--lh-thai`
- [ ] ตัวเลขที่เทียบข้ามแถวใช้ `.num` ไม่ใช่ `.mono`
- [ ] ป้ายใหม่วัด `getBoundingClientRect()` ของคำที่ยาวที่สุดจริง ไม่ใช่เดา
