## งวดงาน — หน้าลูกค้า

ชุดแท็บ: ภาพรวม · ข้อมูลลูกค้า · การขาย · สินค้า · คำร้อง · การเงิน · สรรพสามิต · บริการ (เดิม · โผล่เมื่อมีไซต์) · เอกสาร · ความเคลื่อนไหว
รางขวา (สรุปลูกค้า + จัดการลูกค้า) คงเดิม

- **H1 — ข้อมูล + แท็บรายการ** · ขยาย `customerRelations`: ดีล (+ ลีดผ่าน `leadId`) · QT · SO (ทุก origin) · งวด ·
  คำร้อง · สัญญา · สถิติการสั่ง FG จาก `sales_order_lines` ของ SO ที่อนุมัติ · ทะเบียน + SO ค่าสรรพสามิต ·
  ถอด orders/projects · หัวหน้า 4 ตัวเลข · แท็บการขาย/สินค้า/คำร้อง/การเงิน/สรรพสามิต พร้อมแถบเครื่องมือมติ 7
- **H2 — ภาพรวม + ค้นช่องเดียว** · ต้องตามต่อ (ดีลเปิด · คำร้องค้าง · งวดค้าง) · Actual รายเดือน · ล่าสุด 6 รายการ
- **H3 — ความเคลื่อนไหวรวม** · รวม `entity_updates` ของลูกค้า + ดีล + SO + คำร้องของลูกค้ารายนั้น · keyset ทีละ 50 ·
  ชิปแหล่งที่มา · ช่องพิมพ์ = เธรดลูกค้าเดิม

กับดักที่ต้องถือตลอด:

- ยอด Actual ต้องมาจากตัวคำนวณเดียวกับรายงานยอดขาย (Actual รายงวด · mig 0412) ห้ามบวก `sales_orders.actualAmount` เอง
- `.in()` ที่ลิสต์โตตามข้อมูลต้องผ่าน `fetchAllInChunks` (PostgREST 16 KB) · อ่านหลายแถวต้อง `fetchAll` + `.order(..., 'id')` (ตัด 1,000 แถวเงียบ)
- ทุก query ต้องเช็ค `.error` — แบบที่ `customerRelations` ทำอยู่ (เคยมีแท็บว่างเงียบเพราะชื่อคอลัมน์ผิด)
- GET ห้ามเขียนข้อมูล · เทสต์ห้ามแตะฐานจริง (ส่งตัวจำลอง)
