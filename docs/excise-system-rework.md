### บั๊กต้นเหตุ: แจ้งเตือนข้ามเลนตายอยู่

`PATCH /api/excise-registrations/[id]` มีบล็อกแจ้งข้ามเลนอยู่จริง แต่ตัวส่งถูกถอด
ตอนเลิกใช้ Google Chat (mig 0236) เหลือแต่โครง `if` ที่ **ว่างเปล่าทั้งสองกิ่ง**:

```js
if (data.status === 'pending_legal') {
} else if (data.status === 'approved' || data.status === 'rejected') {
  const approvedNow = data.status === 'approved';
}
```

⇒ ฝ่ายกฎหมายไม่รู้ว่ามีทะเบียนรอตรวจ · ฝ่ายขายไม่รู้ผลจนกว่าจะเปิดหน้าเช็คเอง

### บั๊กที่พบระหว่างตรวจหน้าจอ (กระทบทั้งเว็บ ไม่ใช่แค่ภาษี)

`/api/nav/counts` ตกจากทั้ง `OPEN_READ_APIS` และ `OPEN_WRITE_APIS` ใน `proxy.js`
⇒ default-deny ตอบ **403 ให้ทุก role ที่ไม่ใช่แอดมิน** ⇒ **ป้ายตัวเลขบนเมนูหลัก
ว่างเปล่าทั้งเว็บสำหรับทุกคนที่ไม่ใช่แอดมิน** ทุกโมดูล

เงียบสนิทเพราะ `useNavCounts` กลืน error ตามกติกาของตัวเอง ("ตัวนับพังต้องไม่ทำให้
เมนูทั้งแถบพัง") และแอดมินไม่มีทางเจอเพราะผ่านตั้งแต่บรรทัดแรกของ `lockedOut`

## 2. มติและสิ่งที่ทำ

### 2.1 แจ้งเตือน — เข้ากระดิ่ง ทาง `kinds` ไม่ใช่ `entityTypes`

`lib/tax/registrationNotify.js` — ตัวตัดสินผู้รับเป็นฟังก์ชันบริสุทธิ์ เทสต์ตรงได้

| จังหวะ | kind | ผู้รับ |
|---|---|---|
| ยื่นขึ้นทะเบียน | `excise_submit` | ตำแหน่ง `legal` ทุกคน (ไม่มีเลย → ตกไปที่ `admin`) |
| อนุมัติ | `excise_approve` | เจ้าของใบ (`ownerId`) + เลขที่อนุมัติ |
| ตีกลับ | `excise_reject` | เจ้าของใบ + เหตุผล |
| ปลดอนุมัติ | `excise_revoke` | เจ้าของใบ + เหตุผล |

⚠️ **ห้ามใส่ `'excise_registration'` ลง `entityTypes`** — เธรดกลางเปิดอยู่กับทะเบียน
ทุกใบ ทุกคอมเมนต์จะไหลเข้ากระดิ่งจนคำร้องถูกดันตกขอบกล่อง 30 แถว (ปัญหาเดิมที่มติ
2026-08-20 เพิ่งแก้) · เหตุผลเดียวกับ `LEAD_BELL_KINDS`

⚠️ กติกาผู้รับของ mig 0185 ยังยึดเหมือนเดิม: **ห้าม "ทุกคนในฝ่าย"** — คิวตรวจเป็นของ
**ตำแหน่ง** ส่วนผลการตรวจส่งกลับ **เจ้าของใบ** ไม่ใช่ทั้งทีมขาย

### 2.2 อายุงาน — นับจากจุดที่สถานะปัจจุบันเริ่ม ไม่ใช่วันเปิดใบ

`lib/tax/registrationQueue.js` · เกณฑ์ `AGE_WARN_DAYS = 4` · `AGE_LATE_DAYS = 8`

⚠️ **`ageAnchor` ไม่ใช่ `createdAt` เสมอไป** — ใบที่ถูกตีกลับแล้วส่งกลับมาใหม่นับจาก
รอบล่าสุด (`updatedAt`) ไม่งั้นใบที่ฝ่ายขายเพิ่งแก้เสร็จเมื่อวานจะโชว์ว่าค้างมาสาม
สัปดาห์ แล้วตัวเลข "ค้างนาน" บนหน้าภาพรวมจะไม่มีใครเชื่อ
`approved` ใช้ `approvedAt` · `draft` ใช้ `createdAt`

⇒ ต้องเติม `updatedAt`/`approvedAt` เข้าชุดคอลัมน์ `slim` ของทั้ง registrations และ orders

### 2.3 เวลาไทย

- ตัวกรองช่วงเวลาของหน้าภาพรวมยกออกเป็น `lib/tax/period.js` — เดิมเรียก `new Date()`
  **ตอนเรนเดอร์** ⇒ ใช้นาฬิกาเครื่องผู้ใช้ และค่าขยับระหว่างเรนเดอร์
- ⚠️ เทียบด้วย **วันไทย** ไม่ใช่ตัด 10 ตัวแรกของสตริง ISO: `2026-07-31T18:00:00Z`
  คือ 1 ส.ค. ตามไทย ต้องนับเป็นเดือนสิงหาคม
- `lib/tax/reportPrint.js` (`genAt`) ใช้ `businessDayKey`/`businessTimeKey` แล้ว
  ⇒ รูดเพดาน `check:thaitime` ลง 3 → 2 (จุดที่คอมเมนต์เดิมนัดไว้ว่า "แก้พร้อมงานสายภาษีรอบหน้า")

### 2.4 Egress — ย้ายการคำนวณไป server

หน้าคิวเดิมโหลด `/api/products` (342 แถวเต็ม) + `/api/customers` (508 แถวเต็ม)
ทุกครั้งที่เปิด เพื่อใช้จริงแค่ 17 แถว

- `GET /api/excise-registrations?view=queue` — ส่ง `taxPerUnit` · `retailPriceIncVat` ·
  `docsReady` · `missingLabels` มาให้เลย
- `GET /api/excise-registrations/[id]?full=1` — ส่งสินค้า/ลูกค้า/โครงการ/ใบยื่นที่อ้างถึง
  มาในคำขอเดียว (หน้ารายละเอียดเดิมโหลดทะเบียนทั้งตารางแล้ว `find(id)`)
- ลิสต์ของ picker โหลด **ตอนเปิดโมดัลครั้งแรก** (`useApiList(null)` = ไม่ยิง)

⚠️ **ตัวคิดภาษียังเป็นตัวกลางตัวเดียว** (`exciseTaxLineForRegistration`) แค่ย้ายที่เรียก
จากจอไป route — เทสต์ `registrationRoute.test.mjs` ล็อกไว้ทั้งสองท่า

### 2.5 ความพร้อมเอกสารแบบเป็นชุด

`registrationRequirementsBatch()` ใน `lib/tax/requirements.js` — กฎเดียวกับตัวรายใบ
(`registrationMissing` เป็นส่วนตัดสินร่วม) ไม่งั้นคิวกับด่านตอนกดยื่นจะตอบคนละอย่าง
แล้วผู้ใช้เห็น "ครบ" บนคิวแต่กดยื่นไม่ผ่าน

### 2.6 สัญญาณ "กลับมามองแท็บ" ติดที่ฮุก ไม่ใช่ทีละหน้า

`lib/excise/useApiList.js` ถือสัญญาณแทนทั้งโมดูล — หน้าใหม่ที่ใช้ฮุกนี้ได้ฟรี
ลงทะเบียนใน `revalidateWiring.test.mjs` ผ่านลิสต์ใหม่ `WIRED_HOOKS`

### 2.7 ข้อมูลสกปรก: `fgCode` มีแท็บต่อท้าย

53/342 สินค้า และ 15/17 ทะเบียน เก็บรหัสเป็น `"FG-108-01-002-2009\t\t"` (ก๊อปจาก Excel)

พังจริง 3 จุด — ไม่ใช่เรื่องความสวย:
1. ด่านกันรหัสซ้ำใน `POST`/`PATCH /api/products` เทียบตรงตัว ⇒ พิมพ์รหัสสะอาดไม่ชนของเดิม
   แล้ว **เปิดสินค้ารหัสซ้ำได้**
2. เมทริกซ์สหมิตรเทียบ `row.fgCode === fgCode` ⇒ แถวไม่แมตช์
3. ZIP รายงานภาษีตั้งชื่อโฟลเดอร์จากรหัส ⇒ ได้ `FG-…-2009__ ชื่อสินค้า`

⇒ `mig 0307` ล้างสองตาราง + `CHECK` constraint กันของใหม่ที่ชั้น DB (สคริปต์นำเข้า/
แก้มือใน SQL editor ไม่ผ่านด่านฝั่งแอป ซึ่งคือทางที่ของสกปรกเข้ามาจริง) + trim ที่ `PATCH`

🪤 migration หยุดพร้อมข้อความถ้ามีรหัสที่ trim แล้วชนกันเอง (ตรวจแล้ว: 0 เคส)

## 3. สิ่งที่เพิ่มบนจอ

**ภาพรวม** — แถบ "ค้างรออนุมัติเกิน N วัน" ขึ้นบนสุดเมื่อมีของค้าง (ไม่มีก็ไม่ขึ้นเลย) ·
คิวงานมีอายุงานทุกแถวและเรียงเก่าสุดขึ้นก่อน · สายยื่นชำระที่ว่างทั้งก้อนขึ้น empty state
บอกว่าใบมาจากไหน แทน KPI ศูนย์หกใบซึ่งอ่านไม่ออกว่า "ยังไม่มี" หรือ "ตัวเลขพัง"

**คิวขึ้นทะเบียน** — 7 คอลัมน์: FG · ลูกค้า · ภาษี/ชิ้น (+ฐานราคาปลีก) · เอกสาร (ครบ/ขาด N
พร้อม tooltip บอกว่าขาดอะไร) · ผู้ยื่น+ทีม · ค้างมา (สีตามเกณฑ์) · สถานะ+เลขอนุมัติ

**รายละเอียด** — การ์ด **ฐานคิดภาษี** กางที่มา (ราคาปลีก → ถอด VAT → 8% → 10% → ภาษี/ชิ้น)
เพราะฝ่ายกฎหมายเคยกดอนุมัติโดยเห็นแต่ตัวเลขลอย ๆ · เพิ่มรหัสสาขา · ทีม · โครงการ ·
วันที่สร้าง/อนุมัติ · ผู้อนุมัติ · อายุงาน · แสดง **เหตุผลปลดอนุมัติ** (เดิมเก็บใน
`metadata.revokeApproval` แล้ว**ไม่มีจอไหนแสดงเลย** ทั้งที่คนที่ต้องยื่นใหม่คือคนที่ต้อง
อ่านมันที่สุด) · การ์ด "ใบยื่นชำระภาษีที่อ้างทะเบียนนี้" = คำตอบของ "ลบได้ไหม"
