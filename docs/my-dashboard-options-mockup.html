1 · แถวตัวเลข 4 ช่อง (เป้า · Actual · ดีลเปิด · งานเลยกำหนด)
2 · ฟีดกิจกรรม กินคอลัมน์กลางทั้งหน้า — ตอบ "อะไรเพิ่งเกิด" ไม่ใช่ "ฉันต้องทำอะไร"
3 · คอลัมน์ขวา 5 การ์ด — ลีดต้องติดต่อ / Won รอ SO / SO รอใบยื่นภาษี / ภาพรวมงาน / Pipeline FC
แต่ละใบมีลิงก์ "ดูทั้งหมด" ของตัวเอง — ไม่มีที่ไหนบอกว่ารวมแล้วค้างกี่ชิ้น และอันไหนก่อน
ห้าอย่างที่ตรวจเจอ
  • ไม่มีที่ไหนตอบว่า "เริ่มที่ไหน" — ปัญหาเดียวกับภาพรวม RD ก่อนรื้อ (ม-93) ซึ่งแก้ไปแล้วด้วยการ์ด "เริ่มที่นี่" + คิวถัดไป
  • คำร้องไม่อยู่ในแดชบอร์ดเลย — API ไม่แตะ dept_requests สักบรรทัด ⇒ ใบที่ถูกตีกลับ (ม-102) มองไม่เห็นจากหน้านี้ ทั้งที่เป็นของค้างที่ไม่มีใครกำลังทำอยู่
  • ตัวเลขซ้ำสองที่ในหน้าเดียว — เป้า/Actual อยู่ทั้งแถวบนและการ์ดขวา · งานเลยกำหนดอยู่ทั้งแถวบนและการ์ด "ภาพรวมงาน"
  • ดีไซน์ระบบส่วนตัว — DashboardShell.module.css 69 คลาส (card/queueCard/quickFacts/...) ทั้งที่ระบบมี Workspace · WorkspaceSection · MetricStrip · StartHereCard อยู่แล้ว ⇒ ปรับสี/ระยะทีต้องตามแก้ที่นี่ด้วยมือ
  • ของตกแต่งที่ระบบเลิกใช้แล้ว — ป้าย "LIVE FEED" และปุ่ม "อัปเดต" (คิวคำร้องถอดปุ่มรีเฟรชทิ้งไปแล้ว: หน้าที่ต้องกดเองแปลว่าข้อมูลไม่สดโดยปริยาย)
ของดีที่ต้องเก็บไว้
  • คิว รอยต่อเอกสาร (Won → SO → ใบยื่นภาษี) — สองจุดที่ระบบส่งไม้ต่อแล้วไม่มีอะไรคอยทวง
  • ลีดที่ต้องติดต่อ + นัดหมายที่จะถึง
  • เป้า/Actual/Gap ของเดือน · Pipeline แยกตาม FC%
  • ทุกตัวเลขนับ เฉพาะของฉัน (มติ 2026-07-28) — ไม่ใช่ของทั้งทีม

ฟีดกิจกรรมถูกตัดทิ้งทั้งก้อน — ความเคลื่อนไหวรายดีลอ่านได้ที่เธรดในหน้าดีลอยู่แล้ว

ได้อะไรหน้าสั้นที่สุด อ่านจบในจอเดียว · แยกชัดว่า "ต้องทำ" กับ "ตัวเลข" คนละฝั่ง · ไม่มีอะไรซ้ำกันเลย
เสี่ยงตัดฟีดคือการตัดของที่มีคนใช้อยู่โดยไม่ได้ถาม — และ ฟีดคือที่เดียวที่เห็นความเคลื่อนไหวข้ามดีลโดยไม่ต้องเปิดทีละใบ

ผมแนะนำ: ก

เหตุผลเดียวกับที่เลือก ก ตอนรื้อภาพรวม RD — และรอบนั้นได้ผล: แดชบอร์ดที่ตอบว่า "มีอะไรบ้าง" แต่ไม่ตอบว่า "เริ่มที่ไหน" คนจะเลิกเปิดภายในสองสัปดาห์

  • ของกลางพร้อมแล้วทั้งชุด — StartHereCard · QueueCountStrip · RequestQueuePanel (toolbar กรอง/จัดกลุ่ม/เรียง เพิ่งทำเสร็จ)
  • งานจริงอยู่ที่ นิยาม "ก้าวถัดไป" ของห้าชนิด ให้อยู่ที่ lib ที่เดียว แล้วเทสต์ได้โดยไม่ต้องมีจอ — แบบเดียวกับ requestNextStep
  • ทำเป็นสองก้อนได้: ก1 คิวรวม + เริ่มที่นี่ (ของใหญ่) · ก2 ย้ายฟีดลงท้าย + ลบ CSS ส่วนตัว

ถ้าอยากได้เร็วและเสี่ยงต่ำกว่า เลือก ข ก่อนก็ได้ — แล้วค่อยเติม "เริ่มที่นี่" ทีหลัง (ข ไม่ปิดทาง ก)
