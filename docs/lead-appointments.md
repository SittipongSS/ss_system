# นัดหมายของลีด + ห้อง Studio 01/02/03

สถานะ: รอตรวจ · มติเจ้าของ 2026-11-05 · mig 0424 รันบนฐานจริงแล้ว 2026-11-05 (`table_ok = 1` · `exclusion_ok = 1`)

## โจทย์

ลูกค้าหลายรายจองเวลานัดมาตั้งแต่ก่อนติดต่อ เช่น จองผ่านฟอร์มบนเว็บ MKT จึงรู้วัน เวลา และรูปแบบนัดตั้งแต่ตอนรับลีด
ที่ผ่านมา MKT แปะข้อความ "📅 การนัดหมาย — ✅ จองแล้ว · 13:30–15:00 · Meeting at Studio" ลงช่องรายละเอียดของลีด
บางใบแปะลงในชื่อลีดด้วย ผลคือ

- ระบบไม่รู้ว่าห้อง Studio ไหนถูกจองไปแล้ว นัดสองนัดลงห้องเดียวกันเวลาเดียวกันได้โดยไม่มีอะไรเตือน
- นัดพวกนี้ไม่ขึ้นปฏิทินนัด และ AE ต้องพิมพ์นัดซ้ำเองตอนกด "นัดประชุม"
- ในหน้ารายการลีด ไม่มีทางรู้ว่าใบไหนมีนัดแล้ว ถ้าไม่เปิดเข้าไปดูทีละใบ

ข้อมูลจริง 05/11: นัดประชุม 93 นัดล่าสุดที่ AE บันทึก เป็นแบบลูกค้าเข้ามาที่บริษัท 67 นัด
นัดที่ MKT แปะไว้ส่วนใหญ่ยาวรอบละ 1.5 ชม. (09:00–10:30 · 10:30–12:00 · 13:30–15:00 · 15:00–16:30 · 16:30–18:00)

## โครงข้อมูล (mig 0424)

ตารางใหม่ `lead_appointments` — หนึ่งแถวต่อหนึ่งนัด

- `source` คือที่มาของนัด: `intake` = MKT กรอกตอนรับหรือแก้ลีด · `meeting` = AE บันทึกนัดประชุม (`leadEventId` ชี้ไปที่แถวใน `lead_events`)
- `mode` ใช้ชุดเดียวกับ `MEETING_MODES` บวก `phone` · `room` มีค่าเฉพาะตอน `mode = onsite_at_office` (CHECK บังคับให้มาคู่กัน)
- `startAt`/`endAt` เป็นช่วงครึ่งเปิด [เริ่ม, จบ) — นัดที่จบ 15:00 กับนัดที่เริ่ม 15:00 ไม่ชนกัน
- ไม่ลบแถว แต่ "ปิด" ด้วย `endedAt` + `endedReason`: `replaced` = มีนัดใหม่แทน · `cancelled` = กดยกเลิก · `lead_closed` = ปิดลีด
- **EXCLUDE `lead_appointments_room_no_overlap`** — ห้องเดียวกัน ช่วงเวลาคาบกัน ของลีด **ต่างใบ** ที่ยังไม่ปิด ฐานจะปฏิเสธ (23P01) กันกรณีสองคนกดพร้อมกัน
  ลีดใบเดียวกันไม่ชนตัวเองโดยเจตนา เพราะ AE ต้องยืนยันนัดที่ MKT จองไว้ได้ (ห้องเดิม เวลาเดิม) — API แทรกนัดใหม่ก่อน แล้วค่อยปิดนัดเดิม

**ทำไมไม่ใช้ `lead_events` kind `meeting`:** ด่านกันห้องชนต้องอยู่บนตารางเดียว และ `lead_events` แก้หรือปิดแถวไม่ได้
(นัดที่ถูกเลื่อนจะกันห้องค้างตลอดไป) อีกเหตุคือ ถ้านัดของ MKT ลง kind meeting จะนับเข้า KPI ได้นัดใน 14 วันทันที ซึ่งขัดมติข้อ 5

## ทางเข้าและด่าน

| ที่ | ทำอะไร | API |
|---|---|---|
| ฟอร์มรับลีด/แก้ลีด (`LeadFormFields` → `LeadAppointmentFields`) | ช่อง "นัดหมายที่ลูกค้าจองไว้" · แผ่นห้องบอกว่า ว่าง/ไม่ว่าง จากนัดของวันนั้น | `POST /leads` · `PATCH /leads/[id]` (`appointment`) |
| กล่อง "นัดประชุม" ของ AE (TransitionDialog field ชนิด `custom`) | ช่องชุดเดียวกัน · เติมจากนัดที่รออยู่ (`initialValues`) | `POST /leads/[id]/transition` (`action: meeting` + `appointment`) |
| การ์ด "นัดหมาย" บนหน้าลีด | ปุ่มยกเลิกนัด (`canCancelLeadAppointment` = แก้ลีดได้ หรือทำงานลีดใบนี้ได้) | `PATCH /leads/[id]` ส่ง `{ appointment: null }` อย่างเดียว |
| แผ่นห้องว่าง | นัดที่ยังไม่ปิดของวันไทยหนึ่งวัน · ลีดนอกขอบเขตคนดูไม่โชว์ชื่อลูกค้า แต่ห้องยังขึ้นว่าไม่ว่าง | `GET /leads/appointments?date=YYYY-MM-DD` |

- ด่านเดียวของช่องนัดคือ `appointmentInputError` ใน `lib/sales/leadAppointments.js` — ฟอร์ม กล่องนัด และ API ใช้ตัวเดียวกัน
- เช็คห้องและจองห้อง **ก่อน** ขยับลีด · ห้องชน = 409 โดยที่สถานะ เวลานัด และประวัติไม่ขยับเลย
- ฟอร์มแก้ลีด **ล็อก** นัดที่ AE ยืนยันแล้ว ส่งค่าเดิมกลับมาได้ (ถือว่าไม่แตะ) ถ้าส่งค่าต่างมาได้ 409 พร้อมบอกทางเลื่อนนัดที่ถูกต้อง
- ยกเลิกนัด **ไม่แตะ** `sales_leads.meetingAt` และสถานะลีด เพราะ KPI อ่านค่านี้ว่า "เคยได้นัด" — การยกเลิกคือคืนห้อง ไม่ใช่ลบความจริงว่าเคยนัดได้
- เวลาที่ส่งมาจากจอเป็นวันและเวลาไทยเสมอ แปลงเป็นจุดเวลาด้วย `+07:00` ที่ `thaiDateTimeToIso` ที่เดียว

## ข้อจำกัดที่รู้อยู่

- **ไม่ backfill** — นัดประชุมที่บันทึกก่อน 05/11 และข้อความนัดที่ MKT แปะไว้ ไม่มีข้อมูลห้อง ระบบจึงไม่นับในการเช็คห้องชน
  นัด Studio ที่จองล่วงหน้าไว้แล้ว ต้องให้ AE กด "นัดเพิ่ม / เลื่อนนัด" แล้วเลือกห้อง
- "กำหนดการของฉัน" (`/api/sales-planning/my-schedule`) ยังอ่านแค่นัดประชุม ยังไม่เห็นนัดที่ MKT จองไว้ที่ AE ยังไม่ยืนยัน
