# ลบลูกค้า — ใครอ้างอยู่บ้างถึงลบไม่ได้

> สถานะ: **เสร็จสมบูรณ์** · ตรวจกับโค้ดเมื่อ 2026-08-16

## กฎ

ลบลูกค้าไม่ได้ถ้ายังมีแถวใน**ตารางใดก็ตาม**ที่ถือ `customerId` — ประกาศไว้ที่เดียวใน
[`CUSTOMER_REFERENCE_TABLES`](../webapp/src/lib/master/customerReferences.js) (ตอนนี้ 25 ตาราง)

`npm run check:refs` เทียบทะเบียนกับฐานจริง — มีตารางใหม่ที่ถือ `customerId` แล้วไม่อยู่ในทะเบียน = ตก

## ทำไม

🐞 **พบตอนตรวจระบบ 2026-08-16:** ด่านก่อนลบตรวจแค่ 4 ตาราง (`projects` · `orders` · `excise_registrations` · `products`) ทั้งที่บนฐานจริงมี **25 ตาราง**ถือ `customerId`

FK ของหลายตัวเป็น `ON DELETE SET NULL` ⇒ ฐานข้อมูล**ไม่ได้กัน**ให้ มันแค่ลบสายเชื่อมทิ้งเงียบ ๆ · ชื่อลูกค้าบนตัวเอกสารรอด (ใบเก็บ `customerName` เป็น snapshot) แต่**สายเชื่อมหายถาวร** กู้ไม่ได้เพราะค่าเดิมถูกเขียนทับด้วย null

**วัดกับข้อมูลจริง:** ลูกค้า 147 ราย · **11 รายที่ด่านเดิมปล่อยให้ลบทั้งที่ยังมีของอ้างอยู่**

| ลูกค้า | ที่ยังอ้างอยู่ |
|---|---|
| AR-352 · AR-121 · AR-1003 · AR-428 · AR-778 · AR-874 · AR-631 · AR-807 · AR-573 | ดีลรายละ 1 ใบ |
| AR-119 | 3 กลิ่น + 2 สูตรในทะเบียน |
| AR-767 | 3 กลิ่นในทะเบียน |

ทั้งหมดคือลูกค้าที่มีดีล/กลิ่น/สูตร แต่ยังไม่มีโครงการ ไม่มีสินค้า ไม่มีออเดอร์ — **สถานะปกติของลูกค้าต้นทางท่อ** ไม่ใช่ข้อมูลผิดปกติ

## ทำไมเป็นทะเบียนกลาง ไม่ใช่ลิสต์ในตัว route

ลิสต์ที่เขียนมือตกหล่นทุกครั้งที่เพิ่มตารางใหม่ — **เกิดมาแล้วจริง**: คอมเมนต์ในเส้นลบเขียนเองว่า `products` เพิ่งถูกเพิ่มเข้าด่านเมื่อ 2026-08-13 หลังพบว่าสินค้ากลายเป็นกำพร้าเงียบ ๆ

⇒ ให้ฐานเป็นคนบอกว่าครบไหม แทนที่จะหวังว่าคนจะจำได้

## กับดัก

⚠️ **อ่านตารางไหนไม่ได้ = ยังไม่รู้ว่ามีอะไรอ้างอยู่ → ต้องคืน error ไม่ใช่ปล่อยผ่าน** — บทเรียนเดียวกับการนับดีลที่เหลือใน `projectsRepo` (นับพลาดแล้วเงียบ = ชวนผู้ใช้ลบของที่ยังมีคนใช้)

⚠️ `check:refs` ต้องมี env ถึงจะทำงาน ไม่มีแล้ว**ข้ามเงียบ**เหมือน `check:columns` — ถ้า CI ไม่ได้ตั้ง env ด่านนี้เท่ากับไม่มี

⚠️ ตารางลูก (`sahamit_po_lines` · `sahamit_forecast_lines` · `sales_deal_forecast_lines`) อยู่ในทะเบียนด้วยโดยตั้งใจ — ปกติแม่ของมันก็บล็อกอยู่แล้ว แต่ถ้าเกิดแถวกำพร้าขึ้นจริง ด่านนี้ยังจับได้
