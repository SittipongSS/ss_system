# ค่าว่างพูดคำเดียวกันทั้งระบบ: ขีด `—`

สถานะ: `เสร็จสมบูรณ์` (มติผู้ใช้ 2026-08-17 — กลับคำจากมติ 2026-08-14 ที่เคยใช้ `N/A`)

## กฎ

**ทุกที่ที่ *แสดงผล* ค่าที่ไม่มี ให้ขึ้นขีดยาว `—` (em dash U+2014)**

```js
import { naText, NA, isBlank } from "@/lib/format";

naText(row.taxId)        // มีของ → คืนของเดิม · ว่าง → "—"
{cond ? value : NA}      // ternary
<span>{NA}</span>        // ขีดที่เคยเขียนเป็นข้อความใน JSX
```

กฎ "ค่าว่างมีหน้าตาเดียว" ยังอยู่เหมือนเดิม **เปลี่ยนแค่ตัวอักษรที่ใช้** — ยังต้องมาจาก
`NA` / `naText()` ที่เดียว ห้ามเขียน `-` `–` `.` ดิบกลับเข้ามา (`audit:ui` ยังฟ้องอยู่)

## ทำไมเลิกใช้ N/A

`N/A` เป็นตัวอักษรที่ดังกว่าข้อมูลจริงในแถว — หน้าที่ช่องว่างเยอะ (ตาราง · หน้ารายละเอียด)
สายตาจะไปสะดุดกับคำว่า N/A ซ้ำ ๆ ก่อนเจอค่าที่มีจริง ⇒ อ่านช้าลงและดูเพี้ยนทั้งหน้า
ขีดจาง ๆ ทำหน้าที่เดียวกัน (บอกว่า "ช่องนี้มีอยู่ แต่ยังไม่มีค่า") โดยไม่แย่งความสนใจ

## 📄 ข้อยกเว้น: เอกสาร PDR ยังพิมพ์ N/A

มติ ม-53 (2026-08-07) **ยังใช้ต่อ ไม่ถูกกลับคำ** — ทั้งกระดาษและหน้ารายละเอียดที่ต้องตรง
กับกระดาษ ยังพิมพ์ `N/A` ทุกช่องว่าง เพราะ RD อ่านเอกสารแล้วต้องแยกออกว่า
*ระบบถามแล้วไม่มีคำตอบ* ไม่ใช่ *คนพิมพ์ลืมช่องนี้* — บนกระดาษไม่มีบริบทให้เดา

ไฟล์ที่อยู่ใต้ข้อยกเว้นนี้ (ห้ามเปลี่ยนเป็นขีด):

- `lib/requests/pdrDocument.js` — ตัวประกอบเอกสาร PDR
- `components/requests/PdrSummary.js` — หน้ารายละเอียดที่ต้องตรงกับกระดาษทีละช่อง
- `components/requests/requestForm.module.css` (`.naValue`)

## ⚠️ ใช้กับ "ที่แสดงผล" เท่านั้น

| ที่ | ทำอะไร |
|---|---|
| ตาราง · หน้ารายละเอียด · การ์ด · ป้าย | **`—`** |
| `<input readOnly>` / `disabled` | **`—`** (มันคือการแสดงผล) |
| **`<input>` ที่พิมพ์ได้** | **ห้ามใส่ `—` ลง `value`** — ปล่อยว่าง บอกด้วย `placeholder` |

🪤 ใส่ขีดลง `value` ของช่องที่แก้ได้ = กด Save แล้วขีดลง DB เป็นข้อความจริง
⇒ แยกไม่ออกว่า "ไม่มีข้อมูล" หรือ "คนพิมพ์ขีดมา" · ช่องตัวเลขก็พังเพราะขีดไม่ใช่ตัวเลข
· ค้นหา/กรอง/export จะเห็นขีดเป็นข้อมูลจริง

## 🔴 ข้อยกเว้นที่ต้องจำ

**`0` และ `false` ไม่ใช่ค่าว่าง** — ยอด 0 บาท จำนวน 0 ชิ้น "ไม่อนุมัติ" คือ*คำตอบ*
ไม่ใช่การไม่มีคำตอบ

```js
naText(0)      // → 0    ✅
0 || NA        // → "—"  ❌ `||` กลืน 0 ทิ้ง
```

นี่คือเหตุผลที่ต้องมี `naText()` แทนการเขียน `value || NA` — `format.test.mjs` ตรึงไว้แล้ว

**`isBlank()` ยังนับคำว่า `N/A` เป็นค่าว่าง** — ช่วงที่กฎ 14/08 มีผล มีข้อมูลที่ถูกพิมพ์
หรือนำเข้ามาเป็นคำว่า N/A จริง ๆ ถ้าเลิกนับ มันจะโผล่เป็นค่าจริงในตารางแทนที่จะเป็นขีด

**คำที่มีความหมายเฉพาะ เก็บไว้** ห้ามยุบเป็นขีด:

- `ไม่มีกำหนด` — ไม่ใช่ลืมกรอก แต่*ไม่มี*จริง
- `ระบบ` — createdBy ที่ระบบสร้างเอง ไม่ใช่ไม่รู้ว่าใคร
- `ไม่ระบุลูกค้า` · `ไม่ต้องเสียภาษี` — ประโยคที่บอกสถานะจริง
- `emptyText` ของ picker ที่อธิบายว่ากรองอะไรออก (ดู [form-design-rules.md](form-design-rules.md))

## ⚠️ `src/lib/` ไม่อยู่ในกฎนี้

`src/lib` เป็น **ฟังก์ชันข้อมูล** กับ **ตัวประกอบเอกสาร** — ใส่ค่าว่างสำเร็จรูปที่นั่นจะกลายเป็น
*ข้อมูล* ไม่ใช่การแสดงผล ตัวอย่างที่ห้ามแตะ:

- `requests/scope.js` คืน **id** — `requestedById: "—"` คือ id ปลอม
- `master/customerAr.js` คืนชื่อลูกค้าที่ถูกเอาไปเทียบ/จัดกลุ่มต่อ
- `sales/quotationMasterTemplate.js` — แตะแล้ว**กระทบลายเซ็นอนุมัติของใบเสนอราคา**
- `**Print.js` · `pdrDocument.js` — เอกสารพิมพ์มีกติกาของตัวเอง (PDR พิมพ์ N/A อยู่แล้ว)

ที่นั่นตัดสินทีละจุดด้วยมือ · `audit:ui` จึงตรวจเฉพาะ `src/app` กับ `src/components`

## ด่านกันถอยหลัง

`audit:ui` ฟ้องเมื่อเจอรูปเหล่านี้ในชั้นแสดงผล (ต้องเป็น **0** เสมอ):

```js
x || "-"            // → naText(x)
cond ? y : "-"      // → cond ? y : NA
<span>-</span>      // → <span>{NA}</span>
```

⚠️ ขีดที่เขียนดิบยังผิดอยู่ **แม้ตัวอักษรจะหน้าตาเหมือนกับที่ `NA` คืนมา** — ต้องมาจาก
ที่เดียวเสมอ ไม่งั้นวันที่เปลี่ยนคำอีกรอบจะไล่ตามไม่ครบ (รอบนี้ 350 จุดเปลี่ยนที่บรรทัดเดียว)

`ReadableText` ตั้งค่าปริยาย `empty = NA` ไว้แล้ว — ไม่ต้องส่ง `empty` ซ้ำ
ส่ง `null` ถ้าตั้งใจให้หายไปเลยแทนที่จะขึ้นขีด
