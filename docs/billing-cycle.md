# กำหนดวางบิล — รอบวางบิลของลูกค้า → วันวางบิล / กำหนดชำระรายงวด

> สถานะ: **รอตรวจ** · ตรวจกับโค้ดเมื่อ 2026-09-26 · mig 0389 รันบน prod แล้ว · รอบสอง (6 ข้อตามหลัง + จัดวันใหม่ตามรอบ) ประกอบแล้ว · UAT หน้าจอแบบอ่านอย่างเดียวผ่าน · รอใช้จริง (ตั้งรอบ AR-267 แล้วเลือกรอบงวด 1 ของ SO-26080050-0)

ม็อกที่เจ้าของดูผ่าน: `~/ss-team/mockups/billing-cycle/` (5 จอ · brief.md มีมติ + ข้อมูลตัวอย่าง)

## ทำไม

ลูกค้าเครดิตมีรอบวางบิล ("วางบิลทุกวันที่ 5 · เงินเข้าทุกวันที่ 25") แต่ระบบไม่มีที่เก็บ ⇒ SA พิมพ์ไว้ในช่อง
"เงื่อนไขเครดิต" แล้วกรอก **วันวางบิลลงช่องกำหนดชำระ** (SO-26080050-0 งวด 1 = 5 ก.ย.) ⇒ ใบขึ้นแดง "เลยกำหนด"
ทั้งที่เงินยังไม่ถึงกำหนด และด่านช่างเข้าไซต์ (visitGate) อ่านช่องเดียวกัน

ข้อมูลจริง 25/09: งวดที่จ่ายแล้ว 125/128 จ่ายภายในวันที่ SO (ธุรกิจเกือบทั้งหมดจ่ายก่อน/พร้อมสั่ง) · ลูกค้าเครดิตจริง 13 ราย ·
มีรอบวางบิลชัด 3 ราย · ข้อความเครดิตเดิมแปลงเป็นรอบอัตโนมัติไม่ได้ ⇒ คีย์รอบทีละราย

## มติเจ้าของ (25–26/09/2026 — อย่ารื้อ)

1. เก็บ **สองชั้น**: รอบวางบิลที่ทะเบียนลูกค้า (`customers."billingRule"`) → วันวางบิล + กำหนดชำระรายงวด แก้รายงวดได้
2. ใช้ครบ 4 ทาง: ทะเบียนการชำระ FN · แผงงวดบนใบ SO · ระบบคิดกำหนดชำระให้ · กระดิ่งก่อนถึงวันวางบิล
3. "คิดให้" = **SA แตะเลือกรอบ** (3 รอบถัดไป · วันอื่น… · รอเหตุการณ์) ระบบคิดต่อ — **ไม่เดาวันให้งวดที่ผูกเหตุการณ์**
4. รอบวางบิลบนทะเบียนลูกค้า **SA (ทีมที่ดูแล) + FN แก้ได้ · ไม่ต้องอนุมัติใหม่** (เส้นแยก `/billing-rule`) · ลง audit
5. กระดิ่ง → **เจ้าของดีล (+ ผู้ออกใบ) และทุกคนในฝ่าย FN** (ข้ามกติกา mig 0185 "ห้ามแจ้งทั้งฝ่าย" โดยเจตนา — "แจ้งทั้งฝ่ายไปก่อน")
6. วันวางบิลตรงเสาร์/อาทิตย์ **ไม่เลื่อน เตือนอย่างเดียว**
7. หน้าสร้าง SO **ไม่บังคับเลือกรอบ** (บางที่ไม่มีรอบวาง)
8. **FN แก้วันรายงวดได้**
9. ปุ่ม **"เติมตามรอบ เดือนละงวด"** สำหรับใบหลายงวด: ทำ
10. ใบเก่า **ไม่เติมวันย้อนหลังอัตโนมัติ** · SO-26080050-0 ให้เจ้าของดีลเลือกรอบเองหลังขึ้นระบบ
11. (26/09 รอบสอง) **วันที่ระบบแนะนำต้องแก้เองได้เสมอ** ("ลูกค้าเปลี่ยนฉุกเฉิน หรือเปลี่ยนรอบเลย") — "วันอื่น…" + "แก้กำหนดชำระ"
    อยู่ในโมดัลรายงวดตลอด · ลูกค้าเปลี่ยนรอบถาวร = ปุ่ม **"จัดวันใหม่ตามรอบปัจจุบัน…"** จัดทั้งวันวางบิลและกำหนดชำระใหม่
    ให้งวดที่ยังเปิด (ไม่แตะงวดที่ขอใบแล้ว/รอเหตุการณ์/แจ้งชำระแล้ว/ยกมา) มีตาราง เดิม → ใหม่ ก่อนยืนยัน
12. (26/09 รอบสอง) หัวใบ SO "กำหนดชำระ" + บรรทัด "กำหนด" / การเรียงในหน้ารายการ = กำหนดชำระของงวดถัดไป (ไม่ใช่ `paymentDueDate`)
    · กระดาษที่พิมพ์ไม่แตะ (ตรึงลายนิ้วมือเอกสาร)

## กติกาที่ต้องรู้ก่อนแตะ

- **สองช่องแยกกัน ห้ามรวม** — `billingDate` = วันวางบิล · `dueDate` = กำหนดชำระ · ป้ายแดง "เลยกำหนด" + visitGate
  อ่าน `dueDate` ช่องเดียวเหมือนเดิม · วันวางบิลที่ผ่านแล้ว = "เลยรอบวางบิล" โทนเตือน **ไม่แดง**
- ห้ามตั้งชื่อ `billingCycle` — จองไว้ให้ความถี่งวดของสัญญาบริการ
- ตัวคิดวันทั้งหมดอยู่ที่ `webapp/src/lib/sales/billingRule.js` ที่เดียว (รอบ · กำหนดชำระ · เติมหลายงวด · สถานะ · ข้อความ)
- **"ขอใบวางบิลแล้ว"** ตัดสินที่ `billingRequestLive` ตัวเดียว = คำร้องที่ผูกกับงวด **ส่งถึงบัญชีแล้วและยังไม่ถูกยกเลิก** ·
  ร่างที่ยังไม่ส่ง = ยังไม่ขอ (ปุ่ม "ขอใบวางบิลงวดนี้" ผูกงวดตั้งแต่บันทึกร่าง) · ลบคำร้อง = ถอดลิงก์บนงวด (`cleanupRequestOrphans`)
- งวดยกมา (`kind='opening'`) ไม่มีวันวางบิล/รอเหตุการณ์ (CHECK ของ 0389)
- RPC ปรับแผน (0377) / ใบย้อนหลัง ไม่ได้แก้ — UPDATE ไม่แตะสองคอลัมน์นี้ (ค่าเดิมอยู่กับแถว) · แถวที่ INSERT ใหม่เริ่มว่าง
- ตัวทับงวดตอนอนุมัติ (`freezeInstallments`) พาสองคอลัมน์ไปด้วยแล้ว
- `sales_orders.paymentDueDate` เหลือใช้แค่กระดาษพิมพ์ · ลายนิ้วมืออนุมัติ · กำหนดส่งงานผลิต — จอทั้งหมดอ่านจากงวด (`installmentsNextDue`)
- แถว "รอบวางบิล" ในเธรดลูกค้าเป็นชนิด quiet และไม่นับคนเขียนเป็นผู้ติดตามเธรด (`NON_PARTICIPANT_KINDS`)

## ยังไม่ทำ

- ใบย้อนหลังยังไม่เก็บวันวางบิล (RPC ของใบย้อนหลังไม่มีสองคอลัมน์นี้) — ชิปในขั้น ③ จึงใช้ได้เฉพาะรอบที่เงินเข้า "ทุกวันที่ n" เดือนเดียวกัน
- RPC ปรับแผน (0377) ไม่มีช่องวันวางบิลในตัวแก้แผน — แก้วันวางบิลหลังปรับแผนทำที่แผงงวด
