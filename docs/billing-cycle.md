## ทำไม

ลูกค้าเครดิตมีรอบวางบิล ("วางบิลทุกวันที่ 5 · เงินเข้าทุกวันที่ 25") แต่ระบบไม่มีที่เก็บ ⇒ SA พิมพ์ไว้ในช่อง
"เงื่อนไขเครดิต" แล้วกรอก **วันวางบิลลงช่องกำหนดชำระ** (SO-26080050-0 งวด 1 = 5 ก.ย.) ⇒ ใบขึ้นแดง "เลยกำหนด"
ทั้งที่เงินยังไม่ถึงกำหนด และด่านช่างเข้าไซต์ (visitGate) อ่านช่องเดียวกัน

ข้อมูลจริง 25/09: งวดที่จ่ายแล้ว 125/128 จ่ายภายในวันที่ SO (ธุรกิจเกือบทั้งหมดจ่ายก่อน/พร้อมสั่ง) · ลูกค้าเครดิตจริง 13 ราย ·
มีรอบวางบิลชัด 3 ราย · ข้อความเครดิตเดิมแปลงเป็นรอบอัตโนมัติไม่ได้ ⇒ คีย์รอบทีละราย

## มติเจ้าของ (25–26/09/2026 — อย่ารื้อ)

1. เก็บ **สองชั้น**: รอบวางบิลที่ทะเบียนลูกค้า (`customers."billingRule"`) → วันวางบิล + กำหนดชำระรายงวด แก้รายงวดได้
2. ใช้ครบ 4 ทาง: ทะเบียนการชำระ FN · แผงงวดบนใบ SO · ระบบคิดกำหนดชำระให้ · กระดิ่งก่อนถึงวันวางบิล
3. "คิดให้" = **SA แตะเลือกรอบ** (3 รอบถัดไป · วันอื่น… · รอเหตุการณ์) ระบบคิดต่อ — **ไม่เดาวันให้งวดที่ผูกเหตุการณ์**
4. รอบวางบิลบนทะเบียนลูกค้า **SA (ทีมที่ดูแล) + FN แก้ได้ · ไม่ต้องอนุมัติใหม่** (เส้นแยก `/billing-rule`) · ลง audit
5. กระดิ่ง → **เจ้าของดีล (+ ผู้ออกใบ) และทุกคนในฝ่าย FN** (ข้ามกติกา mig 0185 "ห้ามแจ้งทั้งฝ่าย" โดยเจตนา — "แจ้งทั้งฝ่ายไปก่อน")
6. วันวางบิลตรงเสาร์/อาทิตย์ **ไม่เลื่อน เตือนอย่างเดียว**
7. หน้าสร้าง SO **ไม่บังคับเลือกรอบ** (บางที่ไม่มีรอบวาง)
8. **FN แก้วันรายงวดได้**
9. ปุ่ม **"เติมตามรอบ เดือนละงวด"** สำหรับใบหลายงวด: ทำ
10. ใบเก่า **ไม่เติมวันย้อนหลังอัตโนมัติ** · SO-26080050-0 ให้เจ้าของดีลเลือกรอบเองหลังขึ้นระบบ
11. (26/09 รอบสอง) **วันที่ระบบแนะนำต้องแก้เองได้เสมอ** ("ลูกค้าเปลี่ยนฉุกเฉิน หรือเปลี่ยนรอบเลย") — "วันอื่น…" + "แก้กำหนดชำระ"
    อยู่ในโมดัลรายงวดตลอด · ลูกค้าเปลี่ยนรอบถาวร = ปุ่ม **"จัดวันใหม่ตามรอบปัจจุบัน…"** จัดทั้งวันวางบิลและกำหนดชำระใหม่
    ให้งวดที่ยังเปิด (ไม่แตะงวดที่ขอใบแล้ว/รอเหตุการณ์/แจ้งชำระแล้ว/ยกมา) มีตาราง เดิม → ใหม่ ก่อนยืนยัน

## กติกาที่ต้องรู้ก่อนแตะ

- **สองช่องแยกกัน ห้ามรวม** — `billingDate` = วันวางบิล · `dueDate` = กำหนดชำระ · ป้ายแดง "เลยกำหนด" + visitGate
  อ่าน `dueDate` ช่องเดียวเหมือนเดิม · วันวางบิลที่ผ่านแล้ว = "เลยรอบวางบิล" โทนเตือน **ไม่แดง**
- ห้ามตั้งชื่อ `billingCycle` — จองไว้ให้ความถี่งวดของสัญญาบริการ
- **รูปของรอบรุ่นสอง** (`normalizeBillingRule` · CHECK ของ 0390): `null` = ยังไม่ระบุ · `{ credit: false }` = ไม่มีเครดิต ·
  `{ billing: { mode: 'anyday' } | { mode: 'monthly', days: [..] }, payment: { mode: 'credit', days } | { mode: 'monthly', rounds: [{ day, monthOffset }] } }`
  (rounds คู่กับ days ทีละรอบ) · รูปรุ่นแรก (`billing.day` · `payment.day`) ยังอ่านได้ — **ห้ามอ่านช่องข้างในตรง ๆ** ใช้ตัวช่วย
  `billingRuleNoCredit` · `billingRuleMonthly` · `billingRoundCount` · `billingRoundLabels`
- **ไม่มีเครดิต = วางบิลได้ทุกวัน + ชำระวันวางบิล** (มติ 17) — ตัดสินที่ `effectiveBillingRule` **ที่เดียว** แล้วทุกตัวถาม
  (`pickerRuleOf` · `dateRuleKind` · `creditDaysOf` · `fillKindOf` · `dueDateForBilling` · `planCreditCadence` · ข้อความ) ⇒ ทางคิดวันของไม่มีเครดิต
  คือทางของเครดิต N วัน (N = 0) ไม่มีสาขาแยก · ธง `noCredit` ใช้เลือกคำเท่านั้น · รูปที่อ่านแล้วส่งกลับเข้ามาได้ (ได้รูปเดิม) ·
  **ห้ามบันทึกรูปนี้กลับทะเบียน** (ที่เก็บยังเป็น `{ credit:false }`) · คำกลาง `NO_CREDIT_TEXT` / `PAY_ON_BILLING_TEXT` ·
  จำนวนวันเครดิตเป็นคำผ่าน `creditDaysText` เท่านั้น (0 = "ชำระวันวางบิล" — ประโยครอบ · การ์ด/โมดัลทะเบียนลูกค้า)
- คอลัมน์ "วันวางบิล" บนแผงงวด **ขึ้นทุกใบที่ยังเดิน** (`billingColumn = billingOn`) — ไม่ขึ้นกับรอบของลูกค้าหรือว่ามีงวดไหนมีวันแล้ว
- ⭐ **ข้อความชวน "ยังไม่กำหนด · N งวดไม่มีวันวางบิล" ของทะเบียน FN** (`billingRuleActive` = `billingRuleNeedsBillingDate`) นับเฉพาะ
  รอบรายเดือน/เครดิต N วัน — **ไม่มีเครดิตไม่นับ** (ทางเลือกที่เงียบที่สุดที่ยังพูดจริง · 28/09): กำหนดชำระของลูกค้าไม่มีเครดิต = วันวางบิล
  อยู่แล้ว ใบเก่าที่มีกำหนดชำระจึงไม่ได้ขาดอะไร · prod 28/09 ถ้านับ = ขึ้นชวน 46 ใบ (นับเฉพาะงวดที่ว่างทั้งวันวางบิล/กำหนดชำระ/เหตุการณ์ก็ยัง 24 ใบ)
  · ตัวกรอง `?billing=soon|7d|month|late` อ่านธงของแถวที่คิดจากวันวางบิลเท่านั้น ⇒ ใช้ได้กับทุกใบที่มีวันวางบิล (ไม่มีเครดิต · ยังไม่ตั้ง · ทุกสาย)
- กระดิ่ง (`billingDueNotify` + `daily-digest`) คัดจาก `billingDate` ของงวดเท่านั้น — ไม่ดูกติกาหรือสายของใบ ⇒ ลูกค้าไม่มีเครดิต/ยังไม่ตั้ง
  ที่งวดมีวันวางบิลได้กระดิ่งเหมือนทุกราย
- ทุกเส้นเขียนรับวันวางบิลโดยไม่ดูกติกา/สาย และตรวจรูปด้วย `normalizeInstallmentBilling` ตัวเดียว: หน้าสร้าง SO (`parseCreateFormInstallments`) ·
  `schedule` · `schedule-many` (**เก็บกำหนดชำระตามที่จอส่ง ไม่คิดใหม่จากกติกา**) · `fill-billing`/`redate-billing` เป็นตัวคิดของรอบรายเดือนโดยธรรมชาติ
  (ไม่มีเครดิต/ทุกวัน = ตีกลับพร้อมเหตุ · จอไม่เรียกแล้วตั้งแต่รอบสี่) · ใบย้อนหลัง: RPC ยังไม่มีสองคอลัมน์ (ดู "ยังไม่ทำ")
- ตัวคิดวันทั้งหมดอยู่ที่ `webapp/src/lib/sales/billingRule.js` ที่เดียว (รอบ · กำหนดชำระ · เติมหลายงวด · สถานะ · ข้อความ)
- **"ขอใบวางบิลแล้ว"** ตัดสินที่ `billingRequestLive` ตัวเดียว = คำร้องที่ผูกกับงวด **ส่งถึงบัญชีแล้วและยังไม่ถูกยกเลิก** ·
  ร่างที่ยังไม่ส่ง = ยังไม่ขอ (ปุ่ม "ขอใบวางบิลงวดนี้" ผูกงวดตั้งแต่บันทึกร่าง) · ลบคำร้อง = ถอดลิงก์บนงวด (`cleanupRequestOrphans`)
- งวดยกมา (`kind='opening'`) ไม่มีวันวางบิล/รอเหตุการณ์ (CHECK ของ 0389)
- RPC ปรับแผน (0377) / ใบย้อนหลัง ไม่ได้แก้ — UPDATE ไม่แตะสองคอลัมน์นี้ (ค่าเดิมอยู่กับแถว) · แถวที่ INSERT ใหม่เริ่มว่าง
- ตัวทับงวดตอนอนุมัติ (`freezeInstallments`) พาสองคอลัมน์ไปด้วยแล้ว
- `sales_orders.paymentDueDate` เหลือใช้แค่กระดาษพิมพ์ · ลายนิ้วมืออนุมัติ · กำหนดส่งงานผลิต — จอทั้งหมดอ่านจากงวด (`installmentsNextDue`)
- แถว "รอบวางบิล" ในเธรดลูกค้าเป็นชนิด quiet และไม่นับคนเขียนเป็นผู้ติดตามเธรด (`NON_PARTICIPANT_KINDS`)

- **แตะวัน = ร่าง** (ไม่ลงฐาน) → แถบบันทึกตรึงล่าง "เปลี่ยน N งวด · ดูเดิม → ใหม่ · แทนกำหนดชำระเดิม M งวด · เติมวันงวดที่ว่าง… · ยกเลิก (เอาคืน) ·
  บันทึก N งวด" → **คำขอเดียว** `PATCH …/installments { action:'schedule-many', rows:[{ id, billingDate, billingEvent, dueDate, updatedAt }] }`
  (≤ 60 งวด · ตรวจทุกงวดก่อนเขียน · 409 พร้อมรายชื่องวดที่เปลี่ยนใต้มือ แล้วหน้าดึงใบสดโดยร่างที่ยังใช้ได้อยู่ต่อ · เขียนทีละงวดแบบมีเงื่อนไข
  updatedAt หยุดที่งวดแรกที่พัง · audit ก้อนเดียว before/after)
- ตัวแก้รายงวดตามแบบของกติกา: รอบรายเดือน [ตามรอบ | วันอื่น | รอเหตุการณ์] · ทุกวัน + เครดิต (**รวมไม่มีเครดิต** · มติ 17)
  [ต่อจากงวดก่อน | วันอื่น | รอเหตุการณ์] · ยังไม่ตั้ง [วันวางบิล | กำหนดชำระ | รอเหตุการณ์] (**วันวางบิล → กำหนดชำระ เสมอ** — เจ้าของทัก 28/09 ·
  เปิดที่ช่องที่แตะ · แตะอีกช่องของงวดที่เปิดอยู่ = สลับช่อง แตะช่องเดิม = ปิด) · กำหนดชำระเห็นและแก้ได้เสมอ + ป้ายที่มา ·
  มีวันวางบิลแต่ไม่มีกำหนดชำระ (กติกาคิดได้) = เซลล์ "ยังไม่มีกำหนดชำระ" + ปุ่มแตะเดียว "ใช้วันตามรอบ"/"ใช้วันวางบิล" (`dueSourceOf` 'missing') ·
  งวดที่ล็อก (แจ้ง/รับเงิน/คืนเงิน/ยกมา/ขอใบวางบิลแล้ว/โมฆะ) อ่านอย่างเดียวพร้อมเหตุ — ประโยคเดียวกับ 409 (`installmentDateLock`)
- **กติกาของลูกค้าเปลี่ยนระหว่างอยู่ในโหมด** (ตั้งในแท็บทะเบียนแล้วกลับมา · ล้างแล้วหน้าโหลดใหม่ — `dateRuleShape` เปลี่ยน) = วิธีที่จำไว้รายงวด
  และแผงเติมตั้งต้นใหม่ · **ร่างอยู่ครบ** (ผิดกติกาใหม่ = คำเตือนเดิม) · ตัวแก้ผูก key `${row.id}:${mode.kind}` ทั้งสามที่วาง (review 28/09)
- แผง **"เติมวันงวดที่ว่าง…"** เขียนร่างอย่างเดียว: รอบรายเดือน → `planMonthlyFill`/`planRedate` (หลายรอบต้องเลือกก่อน) ·
  เครดิต N / ไม่มีเครดิต → ข้อเสนอ "ต่อจากงวด X" (`creditFillSuggestion` — ยึดวันที่ของกำหนดชำระงวดก่อน · วันสุดท้ายของเดือนสั้น
  เป็น "สิ้นเดือน" เว้นแต่งวดก่อนตกวันที่เดียวกันในเดือนที่ยาวกว่า เช่น 30 ต.ค. · 30 พ.ย. = วันที่ 30) + วันที่เอง แล้ว **"ตามเดือนในชื่องวด"**
  (`planCreditCadence` `startMonth: null` · AR-622 · `installmentLabelMonth`: ชื่อเต็ม → ย่อมีจุด → ย่อไม่มีจุดที่ยืนเดี่ยว — "มค" ใน "รวมค่า" ไม่นับ)
  หรือเดือนเริ่ม · ยังไม่ตั้ง → `planNoCreditDates` (กำหนดชำระอย่างเดียว วันวางบิลที่เลือกเองคงเดิม) · สวิตช์ "จัดใหม่งวดที่มีวันแล้วด้วย"
  = งานของ "จัดวันใหม่ตามรอบปัจจุบัน…" เดิม
- จอ: ≥1000px ป๊อปโอเวอร์ข้างแถว (ไม่บังหัวใบ/ปุ่มการ์ด) · 641–999px กางใต้แถว · ≤640px แผ่นเต็มจอที่ท้ายตรึงมีปุ่มบันทึกปุ่มเดียว ·
  ร่างวันงวดกับร่างช่วงครอบบริการเปิดพร้อมกันไม่ได้ · ออกจากหน้า/สลับแท็บที่มีร่างค้าง = ถามก่อน
- **ถอดแล้ว**: โมดัลรายงวดทั้งสองแบบ ("กำหนดวันงวด" / "ตั้ง-แก้กำหนดชำระ") · เมนูแถวสามรายการเดิม (เหลือ "ตั้งวันงวด") · ลิงก์ "เลือกรอบ" ในเซลล์ ·
  ปุ่ม+โมดัล "เติมตามรอบ เดือนละงวด…" และ "จัดวันใหม่ตามรอบปัจจุบัน…" บนการ์ด · action `fill-billing`/`redate-billing` ของ API **ยังอยู่**
  (แท็บเก่าก่อน deploy) แต่จอไม่เรียกแล้ว · `BillingRoundPicker` **ยังใช้ที่หน้าสร้าง SO** (แผงงวดไม่ใช้แล้ว)

## ยังไม่ทำ

- ใบย้อนหลังยังไม่เก็บวันวางบิล (RPC ของใบย้อนหลังไม่มีสองคอลัมน์นี้ · ไม่ขึ้นกับกติกา — ทุกลูกค้าเหมือนกัน) — ชิปในขั้น ③ จึงใช้ได้เฉพาะรอบที่
