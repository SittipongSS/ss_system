พัฒนาสูตร — ทั้งระบบของ SA และ RD

ฝ่ายขายทำงานที่ บริหารงานขาย · ฝ่ายวิจัยและพัฒนาทำงานที่ วิจัยและพัฒนา · ฐานข้อมูล เป็นศูนย์รวมข้อมูลของทุกระบบที่ทุกฝ่ายเข้าถึงได้แต่จำกัดสิทธิ์ — ใบนี้วาดว่าแต่ละฝ่ายเปิดระบบของตัวเองมาเจออะไร กดต่อไปไหน และ flow พัฒนาสูตรวิ่งผ่านตรงไหน

SA ระบบบริหารงานขาย RD ระบบวิจัยและพัฒนา DB ฐานข้อมูล (ของกลาง) เสนอใหม่ ยังไม่มีในโค้ดวันนี้
อ่านคู่กับ scent-dev-system-ui-mockup.html — สองหัวข้อนี้เดินสายเดียวกัน (7 ก้าวของ rowStage.js) และใช้จอเดียวกันทั้งคิว ใบคำร้อง และแถบก้าวถัดไป · §12 ท้ายใบเทียบให้ว่าต่างกันตรงไหนบ้าง
ต่างจาก rd-formula-dev-ui-mockup.html ซึ่งวาด "ก้าวของ flow ทีละก้าว" ตอนวางแผน P4 — ใบนี้วาด ทั้งระบบของแต่ละฝ่าย ตามของที่ส่งไปแล้วจริง

00แผนที่ — ใครทำอะไร ที่ระบบไหน

สายเดียว 7 ก้าว ข้ามสองระบบสามครั้ง · ทุกครั้งที่ข้าม ใบยังเป็นใบเดิม — เปลี่ยนแค่ว่าใครเป็นคนเห็นปุ่ม

SA บริหารงานขาย

  1. ดีล NPD ที่ผูกโครงการแล้ว — ไม่ต้องมีใบสั่งขาย
  2. เปิดคำร้อง พัฒนาสูตร · กรอกบรรทัด หมวดสินค้า × กลิ่น เอง
  3. กดส่ง → ออกเลขที่ FD-… → เข้าคิวฝ่าย RD
  4. รอ RD (ระหว่างนี้ถามตอบในเธรดได้)
  5. รับของ ทีละแถว (ใส่วันที่รับ)
  6. ส่งให้ลูกค้า (ใส่วันที่ส่ง)
  7. บันทึกคำตอบลูกค้า — คอนเฟิร์ม / ขอให้แก้ / ไม่เอา
  8. ปิดเรื่อง เมื่อทุกแถวจบ

RD วิจัยและพัฒนา

  1. คิวฝ่าย /rd/requests แท็บ รอฝ่ายตอบ
  2. รับเรื่อง + รับปากวันส่ง — หัวข้อนี้ บังคับวัน (ม-55)
  3. ข้อมูลไม่พอ → ตีกลับให้แก้ไข (ใบยังอยู่ เลขที่เดิม)
  4. ทำสูตรจริงในห้องแล็บ
  5. ส่งของรายแถว — กรอกชื่อสูตร · รหัสสูตร · วันที่ของสูตร
  6. ลูกค้าคอนเฟิร์มแถวไหน → ใส่ราคาเนื้อสารต่อกิโล แถวนั้น
  7. วันเลื่อนได้ → เลื่อนวันกำหนดส่ง พร้อมเหตุผล

DB ฐานข้อมูล

  1. ทะเบียนกลิ่น — ต้นทางของบรรทัด (อ่านอย่างเดียวในสายนี้)
  2. ทะเบียนสินค้า/หมวด — ตัวเลือกหมวดสองชั้น
  3. ทะเบียนสูตร — สูตรเกิดตอน RD กดส่งของ (ขึ้นเป็น ใช้งานได้ ทันที)
  4. ทะเบียนวัสดุ — ราคาเนื้อสาร RM_FB ลงเป็น rev ใหม่ ประทับ formulaId
จุดตัดสินที่ทำให้หัวข้อนี้ไม่เหมือนพัฒนากลิ่น (ม-40) — พัฒนาสูตรคือ ขอตัวอย่างจากกลิ่นที่มีอยู่แล้ว ⇒ ไม่ต้องมีใบสั่งขาย · ไม่มีฟอร์ม PDR · ไม่ผ่านประตูหัวหน้าฝ่ายขาย · เคสที่พบบ่อยที่สุดคือลูกค้ายังไม่ซื้อ อยากลองของก่อน — บังคับ SO ที่อนุมัติแล้วจะทำให้เปิดใบไม่ได้เลยในเคสนั้น

10ราคา — เนื้อสาร RM_FB ต่อกิโล

ขั้นสุดท้ายของสาย อยู่ในใบเดิม ไม่ใช่คำร้องใบใหม่

RD ทางเดินของราคาหลังลูกค้าคอนเฟิร์ม

  1. แถวเดินไปขั้น รอใส่ราคา อัตโนมัติ (ไม่มีใครต้องไปเปิดใบใหม่)
  2. RD กด ใส่ราคา ที่แถบก้าวถัดไป → กรอกราคาต่อกิโล
  3. ระบบสร้าง/หาวัสดุชนิด RM_FB แล้วต่อ rev ใหม่ ในทะเบียนวัสดุ
  4. ประทับ material_prices.formulaId = สูตรที่เพิ่งส่ง
  5. แถวเดินไปขั้น เสร็จ → ครบทุกแถวแล้ว SA กด ปิดเรื่อง ได้
🐞 บั๊กที่เคยทำให้ใบปิดไม่ลงถาวร — ขั้นราคาเดิมบังคับ producedScentId อย่างเดียวแล้วสร้างวัสดุ RM_F จากชื่อกลิ่น · แถวของพัฒนาสูตรผูก producedFormulaId (ไม่มีกลิ่นที่ผลิตขึ้นใหม่ — กลิ่นมีอยู่ก่อนแล้วบนแถว) ⇒ กดใส่ราคาได้ 400 ตลอดกาล · ลูกค้าคอนเฟิร์มแล้วแถวค้างที่ "รอใส่ราคา" ปิดใบไม่ได้
แก้แล้วและมี ratchet เทสต์คุมไว้: พัฒนากลิ่น → หัวน้ำหอม RM_F · พัฒนาสูตร → เนื้อสาร RM_FB — ต่อกิโลทั้งคู่
ไม่ใช่ราคาต่อชิ้นของผลิตภัณฑ์ — ราคาสินค้าสำเร็จรูปต้องรวมบรรจุภัณฑ์และ ค่าผลิต ซึ่งเป็นงานของ ใบขอราคาผลิต ไม่ใช่ของ RD

13ช่องว่างที่แบบนี้เสนอให้ปิด

ห้าข้อ เรียงจากที่คนเจอบ่อยสุด — ทุกข้อยืนยันกับโค้ดวันที่ 2026-08-08 แล้ว

#ช่องว่างอาการที่ผู้ใช้เจอเสนอ
1 หน้าดีลไม่มีทางลัดเปิดคำร้องพัฒนาสูตร ลิงก์ที่มีพาไปคิว แล้วต้องกด "เปิดคำร้อง" อีกที เลือกฝ่าย เลือกหัวข้อ เลือกดีลซ้ำ การ์ด "ขอตัวอย่างของดีลนี้" คู่ขนานกับการ์ด "บรีฟกลิ่นของใบนี้" บนหน้าใบสั่งขาย
2 ทะเบียนสูตรไม่มีคอลัมน์ "ที่มา" แยกไม่ออกว่าสูตรตัวไหนมาจากคำร้อง ตัวไหนพิมพ์เข้ามาเอง — ทะเบียนกลิ่นแยกได้แล้ว ยกกติกาเดียวกับ ม-74 มาใช้ (ตัดสินจากคำร้องที่ผลิตมัน ไม่ใช่จาก dealId)
3 ส่งของได้ทีละแถวเท่านั้น ใบที่ขอ 5 รายการและทำเสร็จพร้อมกัน RD ต้องเปิดโมดัลห้ารอบ กรอกวันเดิมห้าครั้ง โมดัลรวบหลายแถวแบบพัฒนากลิ่น — วันที่ส่งกรอกครั้งเดียว ชื่อ/รหัสสูตรกรอกรายแถว
4 สูตรที่ได้ไม่มีลิงก์ไปทะเบียน ตารางสรุปบอกแค่ "เข้าทะเบียนสูตรแล้ว" และเติมรหัสต่อท้ายชื่อแถว — ต้องไปค้นเอง ทำรหัสสูตรเป็นลิงก์ไป /database/formulas ที่กรองไว้แล้ว
