# ที่มาของยอด FC ของดีล — กรอกเอง หรือเดินตามใบเสนอราคา

สถานะ: **รอตรวจ** (โค้ดครบ · **mig 0337 รันบนฐานจริงแล้ว 2026-09-02** · ยังไม่ UAT)

## มติ (ผู้ใช้ 2026-09-02)

> *"ตอนนี้ deal พอ AE ใส่มูลค่า แล้ว อยากให้พอสร้างใบเสนอราคาแล้ว ปรับยอด FC เป็นตาม
> ใบเสนอราคาแทน แต่ทีนี้ 1 ดีลสร้างได้หลายใบ ทำไงดี"*

คำตอบที่เคาะในรอบเดียวกัน:

| คำถาม | มติ |
|---|---|
| FC ขยับตอนไหน | **ตอนใบอนุมัติแล้ว** (`approvalStatus='approved'`) — ไม่ใช่ตอนสร้าง |
| หลายใบคนละเลขที่ | **ไม่เดา ไม่รวม ไม่เลือกใบใหม่สุด** — ค้างที่เดิมจนกว่า AE จะเลือก |
| ดีลเก่าที่มีใบอนุมัติแล้ว | **ไม่ backfill** — ขึ้นคิว `/sa/forecast-review` ให้ AE กดรับทีละดีล |

## โครงข้อมูล (mig 0337)

`sales_deals` ได้ 5 คอลัมน์:

- `forecastManualValue` — ยอดที่ AE กรอก (ผลบวกแถวรายหมวด) **เก็บถาวร ใบไม่ทับ**
  ⭐ คอลัมน์นี้คือหัวใจ: ถ้าไม่มี ระบบจะถอยกลับไม่ได้เมื่อใบถูกลบ และตอบคำถาม
  "AE เดาแม่นแค่ไหน" ไม่ได้อีกเลย
- `forecastSource` — `'manual' | 'quotation'`
- `forecastQuotationId` — FK ไป `quotations` · `ON DELETE SET NULL`
- `forecastPinnedAt` / `forecastPinnedBy` — คนเลือกที่มาเอง = ปัก ระบบไม่เลื่อนทับ

`projectValue` **ยังเป็นยอด FC ที่ทั้งระบบอ่านเหมือนเดิม** (dashboard · perf · projectRollup)
— ห้ามย้าย ตัว resolver เขียนทับให้ตามที่มาที่ตัดสินได้

ด่านที่ฐาน:
- `CHECK (("forecastSource" = 'quotation') = ("forecastQuotationId" IS NOT NULL))` —
  สถานะ `('quotation', NULL)` เขียนลงฐานไม่ได้เลย
- trigger `BEFORE DELETE ON quotations` → ถอยดีลที่ชี้ใบนั้นกลับเป็น manual
  ในทรานแซกชันเดียวกับการลบ (บาดแผลเดิม: mig 0168)

**backfill มีคำสั่งเดียว** — `forecastManualValue = COALESCE(projectValue, 0)` ซึ่ง
**ไม่มีตัวเลขไหนบนจอเปลี่ยน** เพราะ `forecastSource` ยังเป็น `'manual'` ตาม DEFAULT

✅ ตรวจหลังรันจริง 2026-09-02: 397 ดีลเป็น `manual` ทั้งหมด · `forecastManualValue`
ตรงกับ `projectValue` ทุกแถว (ต่าง 0 แถว) · ไม่มีแถวที่ตัวชี้ไม่ตรงที่มา · CHECK ทั้งสอง
ตัวปฏิเสธการเขียนผิดจริง · trigger ทดสอบด้วย fixture แล้วถอย FC 1,000,000 → 500,000 ถูกต้อง
และไม่แตะ `metadata`/`stage`/`wonValue`

## สูตรอยู่ที่เดียว

`src/lib/sales/forecastSource.js` — หน้าจอใช้บอกผู้ใช้ · route ใช้ตอนเขียนจริง

ใบที่มีสิทธิ์เป็นแหล่ง FC = `status ∈ (sent, accepted)` **และ**
`approvalStatus ∈ (approved, not_required)` — บัญชีขาว ไม่ใช่บัญชีดำ

- ร่างไม่มีสิทธิ์เด็ดขาด (`save_quotation_content` เขียนยอดใหม่ทุกครั้งที่กด save)
- `revised` ไม่นับ — ถูกแทนที่แล้ว (ของจริง 69 ใบ · นับด้วย = นับซ้ำทุกใบที่เคยแก้)

เหตุผลที่ resolver คืนได้: `won_frozen` · `no_eligible` · `single` · `revision` ·
`awaiting_revision` · `pinned` · `ambiguous` · `pointer_gone`

⭐ **`awaiting_revision`** — วินาทีที่กดสร้าง Rev. แถวเดิมพลิกเป็น `revised` ทันทีส่วน
ฉบับใหม่ยังเป็นร่าง ⇒ ชั่วขณะนั้นไม่มีใบมีสิทธิ์เลย · ถ้าปล่อยตกกลับ FC ทั้งบริษัทจะ
แกว่งทุกครั้งที่มีคนกดแก้ใบแล้วเด้งกลับตอนอนุมัติ ⇒ **ค้างยอดเดิมไว้**

## ใครเรียก resolver ได้บ้าง (สำคัญ)

`applyForecastSource` เขียนฐาน **เฉพาะเหตุการณ์ที่มีคนกดจริง** ไม่มีการไล่ปรับตอนอ่าน:

| เหตุ | ขึ้นบันได manual → quotation ได้ไหม |
|---|---|
| `quotation_approved` (อนุมัติใบ) | ✅ ได้ — เหตุเดียว |
| `quotation_deleted` (ลบใบ) | ❌ ดูแลตัวชี้ที่มีอยู่เท่านั้น |
| AE เลือกเองที่หน้าดีล/คิว | ✅ ผ่าน `chooseForecastSource` + ปักให้ |

นี่คือสิ่งที่ทำให้ "ไม่ backfill" เป็นจริง — ดีลเก่าไม่มีเหตุการณ์มาปลุก resolver

## คิว `/sa/forecast-review` — สามกอง ไม่ใช่สอง

| กอง | ความหมาย | กดแล้ว |

ป้ายจะขึ้น 50 แล้วคนอ่านนึกว่ามีตัวเลขต้องแก้ 50 ที่ ทั้งที่จริงมี 23

## กับดัก

1. 🔴 **mig 0337 ต้องรันก่อน deploy เสมอ** — `POST/PATCH /deals` เขียน `forecastManualValue`
   ทุกครั้ง ถ้าคอลัมน์ยังไม่มี PostgREST ปฏิเสธทั้งคำสั่ง ⇒ **สร้าง/แก้ดีลไม่ได้ทั้งระบบ**
2. **trigger ห้ามแตะ `metadata` / `stage` / `wonValue`** — `sales_deals_enforce_so_actual_trg`
   (0110) เป็น BEFORE UPDATE OF สามคอลัมน์นั้น มีตัวทำงานแบบไม่มีเงื่อนไข ⇒ แตะเมื่อไร
   ดีลย้ายระบบ (`actualSource='legacy'`) ถูกตีตราใหม่เป็น `'sale_order'` แล้ว `wonValue`
   ถูกล้างเป็น 0 ถาวร · เทสต์ `forecastSource.test.mjs` อ่านไฟล์ .sql ล็อกไว้แล้ว
3. **ยอดบนจอ ≠ ยอดบนกระดาษ** — FC ใช้ยอด **ก่อน VAT** ให้เข้าคู่กับ `wonValue`/Actual
   ⇒ เอกสารพิมพ์ 1,070,000 แต่ FC ขึ้น 1,000,000 · ทุกจุดที่โชว์ต้องติดป้าย "ก่อน VAT"
4. **ใบที่ `vatRate = 0` คือ "ราคารวม VAT แล้ว"** (`createQuotationDraft.js`) ⇒
   `quotationWonAmount` คืนยอดเต็ม · ปัญหานี้มีอยู่แล้วในเส้น Won/Actual วันนี้
   ไม่ใช่ของใหม่ที่นี่ แต่มองเห็นง่ายขึ้นเพราะ FC ขยับเร็วกว่าเดิม
5. **PATCH ดีลของดีลที่เดินตามใบอยู่ ไม่เขียน `projectValue`** — แก้แถวมูลค่ารายหมวด
   คือแก้ "ยอดที่เคยเดาไว้" (เก็บเทียบความแม่น) ไม่ใช่แก้ FC
